title: A ring buffer that loses track of where the oldest element is
match: the slot arithmetic wraps and keeps wrapping
platforms: linux, windows

## Symptom

A moving average over the last N readings is right until the buffer fills for
the first time, and then drifts. Or a pose trail draws the right points in the
wrong order, with one jump in it that moves round the screen as the robot
drives.

Everything is in the buffer. Nothing is missing. The order is wrong, or one
element is read twice and another not at all.

## Cause

In a ring buffer, the position of an element and its slot in the array are not
the same number, because the oldest element moves.

```cpp
std::size_t slot(std::size_t index) const { return (first_ + index) % Capacity; }
```

That one line is the whole idea, and there are three ways to get it wrong.

**Counting from the array instead of from the oldest.** Returning
`storage_[index]` reads in the order the slots happen to lie, which is the
right set of elements in the wrong order once the buffer has wrapped.

**Forgetting to advance the oldest on overwrite.** When the buffer is full the
slot holding the oldest element is the one to reuse, and the position after it
becomes the new oldest. A `push` that writes without moving `first_` keeps
reporting an element that has been overwritten.

**Advancing it when there was room.** A `push` that moves `first_` on every
call starts discarding before the buffer is full, so a ring of twenty holds
nineteen.

None of these show up on a buffer that has not filled yet, which is why they
reach a release. Every test written with fewer pushes than the capacity passes.

## Fix

**Test past the capacity, several times round.** A ring of three with a hundred
pushes catches a wrap that works once and drifts. Measured: after 100 pushes it
must hold 97, 98, 99 in that order.

**Test a ring of one.** `Ring<T, 1>` is where the off by one errors live,
because every push is an overwrite and the oldest and newest are the same
element.

**Assert the slot stays in range.** `slot(i) < capacity()` for every valid `i`
is one line in a test and it catches arithmetic that walks off the end.

**Keep the two cases in `push` explicit.** There is room, or there is not. A
single clever expression that handles both is where the third bug above comes
from.

**Decide what position zero means, write it down, and keep it.**
`rc::core::Ring` counts from the oldest, because that makes a window read in
chronological order. Counting from the newest is also defensible. Changing your
mind halfway through the class is not.
