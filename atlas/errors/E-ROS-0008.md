title: A required node fails and the rest are left running
match: when a required node cannot configure, nothing is activated and what was configured is given back, newest first
match: when a required node cannot activate, the nodes already running are stopped and everything is given back, newest first
platforms: linux, windows
teaches: 17-19-up-in-order-down-in-reverse

## Symptom

A robot is half up: a controller running with no planner, a device left open by a bring up that was abandoned, and nothing reports it.

## Cause

A required node failing stops the bring up and everything already brought up is taken back, newest first, so that a node is never taken down while something that needs it still runs. A planner that would not configure gave driver:configure filter:configure planner:configure filter:cleanup driver:cleanup. A controller that would not activate rolled back the running planner, filter and driver, each deactivated and cleaned up.

## Fix

Roll back in reverse and report which node stopped it.

```cpp
report.failed = name;
roll_back(report);
```
