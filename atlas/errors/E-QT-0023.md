id: E-QT-0023
title: A property setter that makes QML re-evaluate everything
match: a setter that emits when nothing changed makes QML re-run every binding
platforms: linux, windows
teaches: 11-02-the-value-that-never-changed
---

## Symptom

The panel is correct and slow. Frame rate drops when the robot is connected and
recovers when it is not. A profiler shows time inside the QML engine rather than
in any code you wrote.

The telemetry arriving is mostly unchanged: a speed that sits at zero while the
robot waits, a battery level that moves once a minute.

## Cause

The setter emits its NOTIFY signal every time it is called, whether or not the
value differs. Every emission invalidates every binding that reads the property,
and QML re-runs all of them.

Measured by writing the same value a thousand times, with a binding that counts
its own evaluations:

| setter | binding evaluations |
|---|---|
| no guard | 1002 |
| guarded on equality | 2 |

Both panels display the correct number. One of them did five hundred times the
work to do it, and that is before any of the bindings downstream of it, the
layouts that depend on their sizes, or the repaints.

A telemetry field written at 100 Hz with an unchanged value is the ordinary case
in robotics, not a rare one. A stationary robot is the worst case for this bug,
which is why it tends to be found late.

## Fix

**Compare before assigning.**

```cpp
void setSpeed(double value) {
  if (value == speed_) return;
  speed_ = value;
  emit speedChanged();
}
```

Exact comparison is right here. The question is not whether the values are close
but whether anything downstream needs to know, and a float that differs in the
last bit did change.

**Watch out for the same bug in a batch update.** A method that sets six fields
and emits six signals emits all six when one changed. Guard each, or emit one
signal for the group and let the bindings depend on that.

**Measure it rather than assuming.** A binding that calls a counting function is
four lines and turns this from a suspicion into a number:

```qml
property real shown: tally.tap(source.speed)
```

**Do not solve it by emitting less often on a timer.** Coalescing updates is a
real technique and it belongs above this, not instead of it. A setter that lies
about having changed is wrong at any rate.
