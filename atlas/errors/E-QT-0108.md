title: A log message with an effect, in a category that is switched off
match: a disabled category does not print, and does not evaluate what it was going to print

platforms: linux, windows

## Symptom

The robot behaves differently with debugging on and off: a counter advances only in the debug build of the station, or a queue is drained by the line that logs it.

## Cause

A disabled message is not built, and the expressions in it are not evaluated. A log line that carries a call that changes something changes it only when the category is on. Measured with `station.link.debug=false`: **1** message kept and the arguments worked out **1** time, for the category that was on.

## Fix

Keep the arguments of a log message free of effects, and do the work outside:

```cpp
const int n = pending.size();
qCDebug(lcLink) << "queued" << n;
```
