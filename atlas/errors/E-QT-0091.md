id: E-QT-0091
title: A view whose delegate count nobody watches
match: jumping a long way down a ListView makes a few delegates and lets the old ones go
match: the number of delegates of a ListView does not depend on the number of rows
platforms: linux, windows
teaches: 11-11-ten-thousand-delegates
---

## Symptom

Memory grows as a user scrolls a list, or the interface slows with the age of the session, and no single change of the QML explains it.

## Cause

A view makes and gives up delegates as it moves, but a delegate that holds something alive, or a model that makes the view keep rows (a large cache), changes the count. The only way to know is to count. Measured: after a jump of 5000 rows, **11** delegates were made and **12** were alive, the peak **32**; the alive count was **21** for 100, 10000 and 1000000 rows.

## Fix

Have the delegate report itself and put a budget in a test:

```qml
Component.onCompleted: delegates.created()
Component.onDestruction: delegates.gone()
```
