id: E-IO-0008
title: A read of zero mistaken for a failure
match: a read of zero is not an error and not a disconnection
match: expected .*port_errors.*to equal 0
platforms: linux, windows
teaches: 08-04-the-link-that-goes-quiet
---

## Symptom

A link reports itself disconnected on a bus that is working. Often within
milliseconds of starting, and more reliably the faster the loop runs, which is
the clue: polling harder makes it worse.

The device is fine. Plugging in a terminal shows data arriving normally.

## Cause

Zero and negative were treated as the same thing:

```cpp
const int count = port.read(buffer, sizeof(buffer));
if (count <= 0) return Error::Disconnected;      // the bug
```

A non blocking read returns zero when nothing has arrived yet. On a device
sending at 100 Hz polled at 1 kHz, nine reads in ten return zero, and every one
of them is the link working exactly as it should.

Three returns, three meanings:

| return | meaning |
|---|---|
| positive | that many bytes arrived |
| zero | nothing has arrived yet, and it is not news |
| negative | the port itself failed |

There is a mirror image of this bug that is worse and quieter. Treating negative
as if it were zero gives a link that never reports a failure at all, and it
looks healthy right up to the point where somebody notices the robot has not
moved.

## Fix

Separate all three:

```cpp
const int count = port.read(into);
if (count == 0) return false;             // nothing yet, keep going
if (count < 0) { ++port_errors_; return false; }
```

Then decide whether the link is dead from **elapsed time without a valid
message**, not from any single call's return. A read tells you what happened in
one instant; whether anybody is at the other end is a question about a stretch
of time, and only a clock can answer it. See `E-IO-0010` for the way that clock
gets fed wrongly.

Two details worth having at the same time.

**Count the port errors** rather than only returning them. A link that has seen
three read failures and is now fine is a different situation from one that has
seen none, and neither is visible from a boolean.

**Bound the reads per poll.** A port with an endless supply of bytes will
otherwise hold a control loop past its deadline. Read a fixed number of times,
return, and continue on the next poll.
