## Symptom

A numerical derivative that is accurate in the tests is wrong in use, and only
for large values. A Jacobian of a joint angle in radians is fine and the same
code on a position in millimetres from a survey origin is nonsense. Sometimes
the answer is exactly zero.

## Cause

The step is a constant, and a step is only small relative to something.

Doubles are spaced proportionally, not evenly. Near 1.0 the gap between
neighbours is 2.2e-16; near 1e12 it is 1.2e-4. A step of 1e-6 is a hundred
million times the gap in the first place and a hundredth of it in the second,
where adding it does nothing whatever.

`x*x` differentiated with a fixed step of 1e-6:

| x | gap between doubles at x | x + h == x | relative error |
|---|---|---|---|
| 1e0 | 2.22e-16 | no | 1.000e-12 |
| 1e3 | 1.14e-13 | no | 1.071e-08 |
| 1e9 | 1.19e-07 | no | 4.000e-02 |
| 1e10 | 1.91e-06 | no | 6.384e-01 |
| 1e12 | 1.22e-04 | **yes** | **1.000e+00** |

A relative error of 1.0 is the answer being zero. The derivative of `x*x` at a
trillion is two trillion, and this returns nothing at all, without a warning,
because `f(x + h)` and `f(x - h)` were handed the same number.

## Fix

Scale the step to the value, with a floor so it does not vanish near zero:

```cpp
inline double suggested_step(double x) {
  const double scale = std::fabs(x) > 1.0 ? std::fabs(x) : 1.0;
  return std::cbrt(std::numeric_limits<double>::epsilon()) * scale;
}
```

The floor matters as much as the scaling. A step of `eps^(1/3) * |x|` alone goes
to zero with x, and at `x = 0` there is no step at all.

With that, the same sweep is accurate to about 1e-12 relative at every value
from 1 to 1e12.

Then assert the property rather than trusting it:

```cpp
const double h = suggested_step(x);
RC_CHECK(x + h != x);
RC_CHECK(x - h != x);
```

Two lines, and they catch this class of bug at the point it happens instead of
in a Jacobian six functions later.

The same reasoning applies to every tolerance compared against a magnitude, not
only to derivative steps. A convergence test of `fabs(a - b) < 1e-9` is a
different test at 1 than at 1e12, and at 1e12 it can never pass.
