id: E-IO-0014
title: A field that parsed and was not a number
match: std::stod answers a different question from the one you asked
platforms: linux, windows
teaches: 01-12-readings-from-somewhere-else
---

## Symptom

A log loads without complaint and the numbers are wrong. Not absent, not
garbage: plausible, in range, and wrong by a factor of ten or by a decimal
place. An average is consistently low. A calibration computed from the file
does not match the one computed by hand from the same file.

Nothing threw. Nothing was logged. Every row was accepted.

## Cause

`std::stod` answers whether a field **starts with** a number, not whether it
**is** one.

Measured on seven fields, `stod` accepted all seven:

| field | stod gives | characters it used |
|---|---|---|
| `1.5` | 1.5 | 3 of 3 |
| `1,5` | **1** | 1 of 3 |
| `1.5abc` | 1.5 | 3 of 6 |
| `1.5.7` | 1.5 | 3 of 5 |
| `nan` | nan | 3 of 3 |
| `inf` | inf | 3 of 3 |
| `1e3` | 1000 | 3 of 3 |

The second row is the one that costs money. A log written on a machine where
the decimal separator is a comma reads as whole numbers. `1,5` becomes 1 and
`2,75` becomes 2, consistently, across the whole file, and the result is
believable.

`nan` and `inf` are spellings `strtod` accepts, so one dropped out sensor
reading poisons every average computed from the file, which lesson 01-08 is
about.

`stod` throws only when the field does not begin with a number at all, so
`abc` and an empty field are caught and none of the rows above are.

## Fix

**Require the whole field.** `std::strtod` takes a pointer it sets to just past
whatever it consumed, and comparing that against the end of the text is the
entire check:

```cpp
if (end != begin + text.size()) return {};   // it began with a number
```

That one line separates `1.5` from `1,5`. `rc::core::parse_number` is this plus
three more conditions.

**Trim first.** A file written on Windows leaves a carriage return on every
line, so the last field of every row is `2.25\r` and has something left over.
`rc::core::trim` takes it off along with any spaces.

**Check `errno` for `ERANGE`.** `strtod` reports a value too large or too small
for a double that way, and almost nobody looks.

**Reject `nan` and `inf` at the boundary.** A sensor cannot read either.
Refusing them where the data comes in is much cheaper than finding one later
in an average.

**Prefer `strtod` to `stod` for parsing input.** It does not throw, and the end
pointer is the information you actually need. Exceptions for a malformed line
in a file of ten thousand lines are the wrong shape anyway: a bad line is
expected, not exceptional, which is lesson 03-02.
