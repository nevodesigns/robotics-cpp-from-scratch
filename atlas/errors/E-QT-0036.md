title: A handler that runs the event loop inside itself
match: a handler that lets the loop run is entered again by the readings that arrive while it works, from inside itself
match: expected naive.max_depth
platforms: linux, windows

## Symptom

A handler works for most readings, and under load its logs interleave: "begin 1", "begin 2", "end 2", "end 1". A value it computed at the start is wrong at the end, and it only happens when readings arrive quickly.

## Cause

`QCoreApplication::processEvents()` runs the event loop for a moment, and the event loop delivers the next reading to the same handler, from inside the call to `processEvents`, before the first reading's handling has finished. The handler is entered again while it is running.

Measured: reading 1, with 2 and 3 arriving while it works. The log was **begin 1, begin 2, end 2, begin 3, end 3, end 1**, a nesting depth of **2**. (It is not 3: Qt does not deliver an event again from a nested call while its own batch is still being delivered, so 3 waits for 2 to finish.)

## Fix

Do not call `processEvents` from a handler. If the program has to stay responsive, hand the work to another thread (lesson 09-03) or split it into steps that return to the loop between them.
