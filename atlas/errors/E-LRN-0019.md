## Symptom

Once in a while the learned policy commands something wild, or NaN, for one step, and the log shows a sensor glitch at the same moment.

## Cause

A sensor gave a value that is not a number, and it went straight into the network. NaN spreads through every sum it meets, so the output was NaN, which the actuator code may turn into its largest command or zero. A damaged weight does the same from the inside.

Nothing about a network's arithmetic notices; only code round it can.

## Fix

Check inputs and outputs for finiteness before and after the network, hand over to the fall-back when either fails, and record the reason.

```cpp
const rc::learn::GuardedAction a = rc::learn::guarded_act(task, guard, policy, offset, heading);
if (a.reason == rc::learn::kBadInput) count_sensor_fault();
```

The same check belongs in front of any controller, learned or not; for a network it is the only way to know.
