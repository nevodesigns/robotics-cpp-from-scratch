title: A solver that does not say it failed
match: a pose that cannot be reached stops at the iteration limit with the tool as near as it can get, and is not a crash or a number that is not a number
match: expected r.converged
platforms: linux, windows
teaches: 13-15-taking-steps-toward-the-pose

## Symptom

The arm is sent to a pose that cannot be reached and ends somewhere nobody asked for, and the program reports success.

## Cause

A loop that steps until it stops has to say why it stopped. A solver that returns the angles alone gives no way to tell a pose reached from the best that could be done. Measured: an unreachable pose gave converged false at the **300** iteration limit with the tool **1.7661** m and **0.604296** rad away; the angles were finite.

## Fix

Return whether it converged, and how far off it was:

```cpp
r.converged = true; return r;     // within the tolerances
// ... otherwise r.position_error and r.heading_error say how near it got
```
