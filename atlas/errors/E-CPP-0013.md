title: A number parsed from text that was not entirely a number
match: expected .*NotANumber
platforms: linux, windows
teaches: 03-02-errors-that-are-not-exceptional

## Symptom

A value such as 1.5kg, 100rpm or 3.2.1 is accepted as a number, and the trailing
text disappears without a word. The robot runs with a setting the operator did
not write.

## Cause

Reading from a stream stops at the first character that cannot be part of a
number and reports success for what it did read. Checking only the failure state
therefore accepts any text that begins with a number.

std::stod behaves the same way, and additionally throws on text that is not a
number at all, which is usually the opposite of what a parser wants.

## Fix

Check that the whole text was consumed, not merely that something was read:

```cpp
std::istringstream in(text);
double value = 0.0;
in >> value;
if (in.fail() || !in.eof()) return rc::unexpected(ConfigError::NotANumber);
```

std::from_chars, in C++17, reports where it stopped and does not throw or
allocate, which makes it the better tool once a project can rely on the
floating point overloads being present in its standard library.
