## Symptom

A small change produces a screen of errors. Nothing in it is familiar, the
last one mentions a file you have never opened, and the reasonable response is
to start again.

## Cause

The compiler reads your file once, from the top. When it meets something it
cannot make sense of, it makes an assumption about what you probably meant and
carries on, so that it can report more than one problem per build. That is
useful and it has a cost: when the assumption is wrong, everything after it is
reported against a misunderstanding rather than against your code.

So the count of errors is not the count of mistakes. Measured in lesson 00-03,
a file with four mistakes produces six errors on GCC and six on Clang, and
fixing the first one removes three of them.

The two shapes worth recognising:

**A missing declaration.** One name the compiler does not know produces an error
at every place it is used, and then more errors for every variable that was
going to be built from it.

**A missing punctuation mark.** Everything after it is being read as part of an
unfinished statement, so the errors describe a file that does not exist.

## Fix

Fix the first error. Then rebuild, before reading anything else.

Not the first three. Not the ones that look easiest, which is the natural
instinct and is usually wrong, because the easy looking ones near the bottom are
most likely to be consequences of the hard looking one at the top.

Three habits that make this fast.

**Look at what comes with the error, not just the error.** A `note:` line often
names the header to include or points at the declaration that says how many
arguments a function wanted. It is not labelled as an error, so it gets skipped.

**Errors inside a header you did not write are usually caused by your file.**
See `E-CPP-0003`. Scroll up to the "In file included from" line, which names the
line of yours that started it.

**Paste the first error into `rcpp explain`**, which searches the atlas for it
and returns the cause and the fix.

Once the list stops shrinking faster than you are fixing it, the remaining
errors are probably independent, and then reading several at once is worth the
time.
