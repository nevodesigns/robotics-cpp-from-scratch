## Symptom

A link has a checksum and still delivers wrong messages. The values are not
noise; they are plausible numbers in the wrong fields, or the right numbers a
message late. The checksum passes every time, which is why the checksum is the
last place anybody looks.

## Cause

The checksum is a sum, or an exclusive or, and both are commutative:

```cpp
std::uint8_t check = 0;
for (auto byte : payload) check += byte;      // the bug
```

The order of the bytes cannot affect the result. Measured over swapped byte
pairs, a sum and an exclusive or each catch **zero percent**, and that number is
not a statistic. It is what commutativity means, and no width of sum improves
it.

Reordering sounds exotic until you know where it comes from. A frame parser that
resynchronised onto a false start byte does not deliver corrupted bytes. It
delivers correct bytes at the wrong offsets, which is the one class of error
these schemes are blind to by construction.

The same arithmetic has a second hole, smaller and more ordinary. Two changes
that cancel are invisible to a sum: 128 and 128 add to 256, which is zero in
eight bits. Measured over every pair of flipped bits, a sum misses one in
sixteen and an exclusive or misses one in nine, the latter being every pair of
flips that share a bit position.

## Fix

Use a CRC. It is not commutative, which is the entire reason to pay for it:

```cpp
std::uint8_t crc = 0x00;
for (auto byte : payload) {
  crc ^= byte;
  for (int bit = 0; bit < 8; ++bit) {
    const bool set = (crc & 0x80u) != 0;
    crc = static_cast<std::uint8_t>(crc << 1);
    if (set) crc = static_cast<std::uint8_t>(crc ^ 0x07u);
  }
}
```

Eight shifts and a conditional xor per byte, or one table lookup if that is ever
measured to matter, which on anything running C++ it will not be.

Choosing the width is a separate decision from choosing the scheme, and above
its own width every scheme performs identically. Measured over three million
messages with runs of bytes replaced by noise, a sum, an exclusive or and CRC-8
each missed about one in 256, while CRC-16 missed one in 65536. Pick the width
from the residual risk you will accept, then pick a standard polynomial of that
width.
