id: E-IO-0004
title: A length field trusted without checking it fits
match: a frame claiming more than fits is refused
match: heap-buffer-overflow.*FrameParser
platforms: linux, windows
teaches: 08-02-framing-a-stream
---

## Symptom

A parser that has run for months crashes, or corrupts memory near its buffer,
after nothing changed. Under the address sanitizer:

```text
ERROR: AddressSanitizer: heap-buffer-overflow
  in FrameParser::push(unsigned char)
```

Often it follows a physical event rather than a code change: a motor started, a
connector was disturbed, a cable was run next to a power line.

## Cause

The length field was believed:

```cpp
const std::uint8_t length = byte;   // arrives from the wire
expected_ = length;                 // the bug: no check against storage
```

A one byte length can say 255. The buffer is whatever you decided it should be,
often 64 or 16. The difference is written past the end of it.

The important part is where the number came from. It is not a fact about your
message, it is a **claim made by something outside your program**: a device that
may be faulty, a cable picking up interference from a motor, or on a network, an
attacker. This exact shape, a length from the wire used to index a fixed buffer,
is one of the most common serious defects there is.

Interference is enough. Flipping the two high bits of a length of 5 gives 197,
and no attacker is required.

## Fix

Check it against the space that exists, before anything is done with it:

```cpp
if (length > storage_.size()) {
  ++oversized_;
  state_ = State::WaitStart;   // go back to hunting for a start byte
  return false;
}
expected_ = length;
```

Three details that matter.

**The check comes before the use**, not inside the loop that stores bytes.
Checking as you go still lets a wrong length put the parser out of step with the
stream even when it stops short of the buffer's end.

**Refuse the frame, do not truncate it.** Delivering the first sixteen bytes of
a frame that claimed two hundred hands the application a message that was never
sent, and it will look like a message.

**A payload of exactly the storage size fits.** Writing `>=` instead of `>`
silently loses every largest frame, which shows up much later as a protocol that
works except for one message type.

Count what was refused and expose the count. A parser quietly discarding frames
looks identical to a device that has stopped talking.
