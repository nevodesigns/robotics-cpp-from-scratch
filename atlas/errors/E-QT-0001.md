## Symptom

A class compiles fine until it uses Q_OBJECT or emits a signal, then the build
fails at the linking step with an undefined vtable or a missing signal body.

## Cause

Q_OBJECT declares the meta object machinery and the signal functions without
defining them. moc, the meta object compiler, writes those definitions into a
generated file. If moc did not run for this class, nothing defines them.

There are exactly three causes: the class has no Q_OBJECT, moc never saw the
header because it is not part of a target, or Q_OBJECT was added without
reconfiguring the build.

## Fix

Check them in that order. Ensure Q_OBJECT is the first thing in the class body
and the class inherits QObject. Ensure the header is listed among the target's
sources, which is why cmake/RcLesson.cmake globs headers as well as sources.
Then reconfigure: cmake -S . -B build/default
