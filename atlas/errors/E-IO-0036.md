id: E-IO-0036
title: A request that retries with a new id, or never stops, or loses its place
match: a silent device is asked again with the same id, and then given up on
match: a send that fails does not start a request, and does not use up an id
match: ids wrap and never come out as zero
platforms: linux, windows
teaches: 08-11-asking-and-being-answered
---

## Symptom

Three small failures that each undo something the rest of the design relies on.

A retry is executed as a new command because the device cannot tell it is a repeat.
A dead device is asked ten times a second for ever, and the caller never learns it
gave up. A request that never went out is reported as sent, and its answer, which
never comes, is waited for. An id of zero is treated as "no request" and a real
request is thrown away.

## Cause

**A retry gets a new id.** The id is how a device recognises a repeat. A resend
that takes a fresh one is, to the device, a different command, and the reply cache
and the stale count both stop working.

**No limit on attempts.** The longest a request can take is the timeout times the
attempts: 50 ms times 3 is 150 ms here. A caller with a deadline checks that number,
and a requester with no limit has no number to check. After the last attempt the
state must say so, `TimedOut`, so the caller can act.

**A failed send that starts the request.** The id is used and the state is Waiting,
and the request was never on the wire. The requester then waits out its timeouts for
an answer to nothing, and the next id has skipped a number.

**Zero as an id.** Zero is the value a requester has before it has asked anything.
When the counter wraps, 255 plus one is zero, and a request that carries it is
indistinguishable from "nothing outstanding".

## Fix

Take the id only for a request that was sent, keep it across retries, skip zero when
it wraps, and bound the attempts:

```cpp
std::uint8_t next = static_cast<std::uint8_t>(id_ + 1u);
if (next == 0) next = 1;
...
if (!link_.send(...)) { ++send_failures_; return false; }   // before id_ = next
id_ = next;
```
