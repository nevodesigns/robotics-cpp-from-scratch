## Symptom

Code that builds cleanly on Linux fails only on Windows, reporting that a
variable cannot be implicitly captured because no default capture mode has been
specified. The variable is usually a constexpr constant declared just above the
lambda.

## Cause

Using a constexpr variable for its value alone is not an odr-use, so the
standard does not require capturing it. GCC and Clang take that reading and
accept the code. MSVC is stricter and asks for the capture anyway.

This is exactly the class of difference a single toolchain never reveals. It was
found by the Windows lane of this repository's continuous integration on code
that had already passed on GCC 11, Clang 14 and GCC 13.

## Fix

Move the constant to file scope, which removes the capture question on every
compiler:

```cpp
namespace {
constexpr long kPublicationsEach = 20000;
}
```

Capturing it explicitly, or using a default capture of [&] or [=], also works.
File scope is preferable for a genuine constant because it says the value has
nothing to do with any particular call.

The general lesson is worth more than the fix: build on more than one compiler.
Each one accepts things the others reject, and finding out on somebody else's
machine is the expensive way.
