title: Unsigned wrapping and signed overflow confused for each other

## Symptom

Two pieces of arithmetic that look identical behave completely differently. One
produces a wrong number that can be reproduced and traced. The other produces
a program that cannot be reasoned about at all, where adding a print statement
changes the outcome.

Or the opposite confusion: somebody "fixes" an unsigned wrap by switching the
type to `int`, and makes it far worse.

## Cause

They are not the same category of mistake, and C++ treats them differently on
purpose.

**Unsigned wrapping is defined.** The result is specified exactly: modulo two
to the width of the type. `UINT_MAX + 1u` is 0, and `0u - 1u` is 4294967295, on
every machine and every compiler, every time. The answer is wrong for what you
meant and it is a fact you can assert in a test.

**Signed overflow is undefined.** The standard places no requirement on the
program. The compiler may assume it never happens and optimise accordingly, so
the behaviour is not merely unpredictable, it can be inconsistent with the
source.

The compiler enforces the distinction where it can see it. In a constant
expression, undefined behaviour makes the program ill formed:

| constant expression | gcc | clang |
|---|---|---|
| `constexpr int x = INT_MAX + 1;` | refused | refused |
| `constexpr int x = 1 << 32;` | refused | refused |
| `constexpr int x = 1 / 0;` | refused | refused |
| `constexpr unsigned u = UINT_MAX + 1u;` | accepted | accepted |
| `constexpr unsigned u = 1u << 31;` | accepted | accepted |

Same arithmetic, two different rules. Note that this only happens when the
compiler can see the values. The moment either operand arrives at runtime,
nothing is refused and nothing is said.

## Fix

**Know which one you have.** Unsigned is for bit patterns, sizes and anything
that genuinely wraps, such as a free running hardware counter. Signed is for
quantities that can be negative and must never silently roll over.

**Do not switch a type to silence a symptom.** Changing `unsigned` to `int` to
stop a wrap replaces a defined wrong answer with undefined behaviour, which is
strictly worse because it cannot be tested for.

**For unsigned, assert the wrap.** It is specified, so write it down:
`RC_CHECK(wrapped == 0u)`. A defined behaviour you have pinned in a test is not
a bug, it is a documented property.

**For signed, check before.** `rc::core::add_overflows` and friends, which is
the only point at which the question has an answer.

**Shift carefully.** A shift by the width of the type or more is undefined for
both signedness. `1u << 31` is the largest legal shift of a 32 bit unsigned,
and a loop that builds masks by shifting up to and including the width walks
straight off the end.
