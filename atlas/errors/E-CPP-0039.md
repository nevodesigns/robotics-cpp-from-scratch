id: E-CPP-0039
title: Advice about passing strings applied without knowing which strings
match: a short string keeps its characters inside itself
platforms: linux, windows
teaches: 01-11-what-the-call-costs
---

## Symptom

Every string parameter in a codebase is a `const std::string&`, including the
ones that take a two character unit label or a three character command code.
Call sites that have a `const char*` or a string literal now construct a
temporary `std::string` to call them, which allocates nothing but is a
constructor call and a destructor call at every use, to avoid a copy that would
also have allocated nothing.

Or the opposite: strings are passed by value everywhere because somebody
measured a short one and found it free.

## Cause

"Pass strings by const reference" is advice about long strings, and whether a
string is long is a property of your standard library rather than of the
language.

A short string keeps its characters inside the string object itself, so copying
it allocates nothing at all: it moves a handful of bytes within one object.
Measured, with `sizeof(std::string)` of 32:

| length | characters live | copying it allocates |
|---|---|---|
| 0 | inside the object | nothing |
| 1 | inside the object | nothing |
| 15 | inside the object | nothing |
| 16 | on the heap | a buffer |
| 64 | on the heap | a buffer |

The length at which that changes is a choice the implementation made. Measure
it rather than quoting a number, because the number is not portable and the
behaviour either side of it is.

A long string is a different matter. Measured on 256 characters, passing by
value arrives as a new buffer and by const reference arrives as the same one.

## Fix

**Know which kind of string the parameter is.** A unit label, a command code or
an enum name is short and the advice does not apply to it. A log line, a file
path or a serialised message is long and it does.

**For a parameter you only read, take `std::string_view`**, which is to strings
what a span is to buffers: it copies nothing, and it accepts a `std::string`, a
`const char*` and a literal without constructing anything. That removes the
question rather than answering it per parameter.

**For a parameter you will keep, take it by value and move it.** The caller then
chooses whether to hand over a string they are done with or a copy, and you do
not copy again on the way into your member.

**Measure before optimising a string parameter.** This whole class of change is
frequently a rewrite that moves no bytes at all, and the measurement is four
lines: compare the address of the characters against the address of the object.
