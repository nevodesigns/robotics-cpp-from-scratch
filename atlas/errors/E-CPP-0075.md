title: A stream that stays failed after one bad answer
match: asking again gets past bad answers, and without clearing the stream it never would
match: expected this to be true: asked.entry.ok
platforms: linux, windows

## Symptom

A program that asks for a number is given a word once, and from then on every question fails instantly. If it loops until it gets a good answer it spins at full speed
and never stops, even though the person is typing correct numbers.

## Cause

A failed read sets the stream's fail flag, and while that flag is set every further read does nothing and fails. The bad text is also still in the stream, so even
after the flag is cleared the same text would be read, and fail, again.

Measured: typed `abc` and then three sevens, ten reads with `>>` and no clean up, **0 succeeded**. Through `ask()`, the input `abc`, `-5`, `12abc`, `7` gave the value 7 after 4 attempts.

## Fix

Two lines, in this order, after any failed read:

```cpp
in.clear();                                                        // the flag
in.ignore(std::numeric_limits<std::streamsize>::max(), '\n');      // the bad line
```
