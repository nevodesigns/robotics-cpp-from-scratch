id: E-MEM-0006
title: Releasing a resource that was never acquired
match: (AddressSanitizer|ERROR).*attempting free on address which was not malloc
match: Bad file descriptor
platforms: linux, windows
teaches: 02-03-raii-and-destructors
---

## Symptom

A destructor closes a device, frees memory, or unlocks something that was never
obtained. On Linux a file operation reports a bad file descriptor. A sanitizer
reports a free on an address that was never allocated.

## Cause

The constructor failed, or the object was moved from, or close was already
called, and the destructor released anyway because it did not check whether it
still held anything.

## Fix

Give the empty state a value that cannot be mistaken for a real one, such as
kNoDevice or nullptr, and check it before releasing:

```cpp
void close() {
  if (id_ == kNoDevice) return;
  const int held = id_;
  id_ = kNoDevice;
  fake_close(held);
}
```

Marking the object empty before performing the release makes the operation safe
to call more than once, so an early close followed by the destructor cannot
release twice.
