title: A container that range-for and the algorithms will not accept
match: range-for asks for exactly three operations
platforms: linux, windows
teaches: 03-08-making-it-iterable

## Symptom

```
error: 'begin' was not declared in this scope
error: 'end' was not declared in this scope
```

for a container that plainly has elements in it, with a `size()` and an
`operator[]` that work perfectly well. Or the range-for compiles and
`std::count_if` does not, with an error about
`std::iterator_traits` having no member `difference_type`.

So every loop over your own type is written by hand with an index, and lesson
03-04's advice to prefer the algorithms quietly does not apply to anything you
wrote yourself.

## Cause

Two separate requirements, and they are much smaller than they look.

**range-for asks for three operations.** It expands to a loop that
dereferences, pre-increments and compares for inequality. That is the entire
requirement: `operator*`, `operator++`, `operator!=`, plus a `begin()` and an
`end()` to get them from. Measured, a struct with `size()`, `operator[]` and an
iterator providing exactly those three worked.

**The algorithms ask for the typedefs.** They look up
`std::iterator_traits<It>`, which needs five names declared on the iterator:

```cpp
using iterator_category = std::random_access_iterator_tag;
using value_type = double;
using difference_type = std::ptrdiff_t;
using pointer = const value_type*;
using reference = const value_type&;
```

Nobody guesses those. They are looked up, and a missing one produces an error
from inside `<algorithm>` rather than from your own file, which is lesson
03-07's measurement about template diagnostics.

And the container itself needs a `value_type`, because anything generic has to
be able to name the element type rather than be told it. That is the first
thing a container says about itself, and `rc::core::Ring` gained the line for
exactly this reason.

## Fix

**Use `rc::core::IndexIterator`.** Any container with `size()`, `operator[]`
and `value_type` gains range-for and the whole of `<algorithm>` from two lines:

```cpp
IndexIterator<Mine> begin() const { return IndexIterator<Mine>(this, 0); }
IndexIterator<Mine> end() const { return IndexIterator<Mine>(this, size()); }
```

**Declare `value_type` on the container first.** It is one line and everything
generic depends on it.

**`end()` is one past the last element, which is the size itself.** There is no
element there and there does not need to be: `end` is never dereferenced, only
compared against.

**Prefer member `begin()` and `end()`,** which range-for looks for first. Free
functions in the container's own namespace also work, through argument
dependent lookup, and are the answer for a container whose definition you
cannot change.

**Check the empty case.** A container with nothing in it must iterate zero
times, which is where a `begin` that is not equal to `end` when it should be
shows up immediately.
