title: A handle left open by an exception, or a close of one that never opened
match: a handle is closed when an exception leaves the scope, and a failed open is never closed
match: expected device_log
platforms: linux, windows
teaches: 02-16-a-handle-the-library-gave-you
---

## Symptom

A function that holds a device throws, and the exception is caught far away. The device stays open. Or the cleanup closes every handle in a list, including one that never opened, and the library
prints an error or crashes.

## Cause

Code written to close a handle at the end of a function does not run when an exception leaves it half way. A cleanup that does not check for null closes a handle that does not exist.

Measured: an exception thrown while holding a device gave opened **1**, closed **1**. A device that failed to open went out of scope with **0** bad closes, because a `unique_ptr` never calls its deleter on a null pointer, and the deleter checks too.

## Fix

```cpp
struct DeviceCloser {
  void operator()(Device* d) const {
    if (d != nullptr) device_close(d);
  }
};
```
