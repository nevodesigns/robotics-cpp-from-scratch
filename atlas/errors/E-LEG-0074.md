## Symptom

A failed job check is answered by changing a setting, the check is run again, and it fails again or fails somewhere else.

## Cause

The requirements fall into kinds: the speed is the operator's choice, the ground and the push are the job's, and the knees, the battery and the people are the robot's and the site's. When the first failure is a robot limit, no setting helps; the robot or the job has to change. The check's order runs from what is cheapest to change last, so its answer says which kind it is.

## Fix

Read the first failure's kind before acting: lower the speed for 1, change the route for 2 and 3, and change the robot or the load for 4 and 5.

```cpp
switch (v.first_fail) {
  case 1: job.speed = 0.9 * v.v_legs; break;      // a setting
  case 4: case 5: escalate("robot limit"); break; // not a setting
  default: break;
}
```

Saying which kind of limit failed is most of the value of the check.
