## Symptom

An interface widget is updated from the sensor's callback and the program crashes now and then, or draws garbage, or Qt prints that a widget was used from another thread.

## Cause

`connect` with no receiver object, which is what a lambda connection without a context is, is a direct connection. The slot runs in the thread that emitted. A sensor thread that emits `reading` has run the interface's code on the sensor's thread.

Measured: a direct slot connected to a signal emitted from another thread ran on **the sensor's thread** and not the interface's. The latest value's update, from a write on the same other thread, ran on **the interface's thread**.

## Fix

Connect with a receiver object that lives on the interface's thread, or give the object that is written from the sensor thread the interface's thread and let it post its own delivery:

```cpp
QMetaObject::invokeMethod(this, &LatestValue::deliver, Qt::QueuedConnection);   // runs where this object lives
```
