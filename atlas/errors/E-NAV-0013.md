title: A cast instead of a floor, and the double-width cell at the origin
match: a point in the world lands in one cell, on both sides of the origin
platforms: linux, windows
teaches: 16-05-what-the-robot-does-not-know

## Symptom

Obstacles land one cell out of place, but only on one side of the map. A wall
mapped while driving east appears in a slightly different place than the same
wall mapped while driving west. Features near the middle of the map are smeared
or doubled.

Everything is fine in a map whose origin is at a corner, and wrong in one whose
origin is at the centre.

## Cause

The world-to-cell conversion casts to `int` instead of taking a floor.

```cpp
const int cx = static_cast<int>((x - origin_x) / resolution);        // wrong
const int cx = static_cast<int>(std::floor((x - origin_x) / resolution));  // right
```

A cast truncates toward zero, which is a different operation from flooring for
every negative value. With 10 cm cells and the origin at the centre of the map:

| x | floored | truncated |
|---|---|---|
| -0.25 | -3 | -2 |
| -0.15 | -2 | -1 |
| -0.05 | -1 | 0 |
| 0.05 | 0 | 0 |
| 0.15 | 1 | 1 |
| 0.25 | 2 | 2 |

Every cell on the negative side is shifted by one, and `-0.05` and `+0.05` land
in the same cell, so **the cell at the origin is 20 cm wide while every other
one is 10**. The grid has a seam down the middle of the world.

It hides because the usual first test map puts the origin at a corner, where
every coordinate is positive and truncation and flooring agree exactly.

## Fix

Use `std::floor`, and test on both sides of the origin.

```cpp
CellIndex index;
index.x = static_cast<int>(std::floor((x - origin_x_) / resolution_));
index.y = static_cast<int>(std::floor((y - origin_y_) / resolution_));
index.inside = inside(index.x, index.y);
```

Return whether the point is inside the grid rather than clamping it. A clamped
index silently piles everything beyond the edge of the map into the border
cells, which produces a wall around the map that nobody put there.

The same truncation appears wherever a continuous quantity is bucketed: a
histogram of a signed error, a time index relative to a mid-run epoch, a bin
number from a value that can go negative. **Casting is not rounding and it is
not flooring**, and the case that finds it is always the negative one, which is
always the one the first test does not have.
