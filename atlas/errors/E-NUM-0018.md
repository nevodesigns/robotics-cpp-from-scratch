## Symptom

A type was introduced to stop a class of mistake, and the mistake still happens.
The unit type is there, the code compiles, and somewhere a plain number got in
without anybody saying which unit it was in.

Or the reverse: nobody can say whether the type still refuses what it was
written to refuse, because nothing anywhere tries.

## Cause

Two different holes, and the second is the interesting one.

**An implicit constructor.** Without `explicit`, a `double` becomes a `Metres`
silently whenever a function wants one. The type is then a documentation
comment with extra steps: it describes an intention and enforces nothing at the
boundary where the intention matters.

**Nothing checks the refusals.** A test can only assert what runs. Everything a
type system promises is a thing that does **not** compile, and there is no
`RC_CHECK` for that. So the guarantee is asserted in a comment, and a later
change quietly removes it: somebody adds an implicit conversion for convenience,
or defines `operator*` between two quantities because one call site wanted it,
and every test still passes.

## Fix

Write the refusals down as code, and have the build try to compile them.

```
checks/adding_metres_to_seconds.cpp
checks/a_bare_double_becoming_a_length.cpp
checks/multiplying_two_lengths.cpp
```

Each is a small program that must not compile. `rc_add_lesson` builds a target
for each one, excluded from the default build, and registers a test that runs
that build and is marked `WILL_FAIL`. A snippet that starts compiling is
therefore a **test failure**, reported like any other.

That turns three sentences of intent into three things the compiler checks on
every toolchain, every push.

Three details worth having right.

**Compile them against the finished implementation**, not the learner's or the
work in progress. A half-written type fails to compile for reasons that have
nothing to do with the guarantee, and the check would pass for the wrong reason.

**Keep each snippet to one refusal.** A file that fails for two reasons still
passes when one of them stops working.

**Say in the snippet what it is proving**, at the top, because a file whose
entire purpose is to fail looks like a mistake to the next reader.

The same mechanism covers every promise a type makes: a deleted copy
constructor, a template that rejects the wrong argument, a `static_assert` that
should fire. If it is a compiler error you rely on, compile it.
