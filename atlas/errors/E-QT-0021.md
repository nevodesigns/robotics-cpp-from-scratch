title: A QML panel showing a value the robot moved on from

## Symptom

The panel comes up with the right numbers and then never changes. Speed reads
whatever it was at startup, usually zero, while the robot is plainly moving.

Logging in the C++ getter shows it being called exactly once, at startup, and
never again. No error, no warning, nothing on stderr.

## Cause

A QML binding is not a poll. It reads the property once, builds a dependency on
whatever signal the property nominates, and then waits to be told. If nothing
tells it, it waits forever, and the value it read at startup is the value the
panel shows for as long as the panel exists.

There are three ways to end up in that state and they look identical from QML.

| how it is exposed | C++ now | QML sees | evaluations | warnings |
|---|---|---|---|---|
| NOTIFY, emitted | 7.50 | 7.50 | 2 | 0 |
| no NOTIFY | 7.50 | 1.00 | 1 | 0 |
| NOTIFY, not emitted | 7.50 | 1.00 | 1 | 0 |
| CONSTANT | 7.50 | 1.00 | 1 | 0 |

Zero warnings on every row, including the broken ones. By the three tiers of
lesson 11-01 this is the bottom one: it loads, it runs, and no channel reports
it.

The one binding evaluation on the broken rows is the tell. A working property
gets two, one when the panel is built and one when the value moves.

## Fix

**Declare NOTIFY, and emit it.** Both halves, because they fail the same way:

```cpp
Q_PROPERTY(double speed READ speed WRITE setSpeed NOTIFY speedChanged)

void setSpeed(double value) {
  if (value == speed_) return;
  speed_ = value;
  emit speedChanged();
}
```

**Check the declarations from a test.** `rc::qt::every_property_is_trackable`
reads the meta object and catches a property with no NOTIFY before anything
runs. Assert it for every type you hand to QML.

**And do not stop there.** That check reads the declaration, so it clears a
setter that declares NOTIFY and never emits it, and it clears a CONSTANT
property on an object that changes anyway. Of the three broken rows above it
catches one. The other two need a test that changes the value in C++ and reads
it back through QML, which is four lines and the only thing that proves the
whole path.

**Use CONSTANT only when it is true.** It is the right answer for a serial
number or a link length. It is a promise, and QML holds you to it.
