title: A write that went nowhere and said nothing
match: (stream never opened|No such file or directory|No space left on device)

## Symptom

The program runs to the end, prints that it saved, and there is no file. Or
there is a file and it is shorter than it should be. Nothing threw, nothing was
printed, and the exit status was 0.

```
$ ./record_run
saved run.csv
$ ls run.csv
ls: cannot access 'run.csv': No such file or directory
```

## Cause

A stream that fails to open does not complain. It sets a flag and then ignores
every write you give it.

Measured on a stream opened on a folder that does not exist:

| | |
|---|---|
| threw an exception | **no** |
| `is_open()` | false |
| `good()` after a write | false |

The flag was set and nobody read it.

A full disk is the same shape one step later. Measured by writing to
`/dev/full` on Linux: `good()` after the `<<` was **true**, and became false
only when the buffer was emptied. The error arrives when the data is flushed,
not when you wrote it, so a program that looks after the last write and not
after the flush never learns.

## Fix

Check the stream at both moments that matter.

```cpp
std::ofstream out(path, std::ios::binary);
if (!out) { /* could not open: say which file and why it might be */ }

out << text;
out.close();                 // empties the buffer, so this is when it fails
if (out.fail()) { /* the write did not complete */ }
```

Or use `rc::core::save_text`, which does both, names the file in the message,
and returns a value you have to look at.

```cpp
#include <rc/core/save.hpp>

const auto saved = rc::core::save_text("run.csv", text);
if (!saved.ok) std::cerr << saved.error << "\n";
```

Do not rely on `good()` before the close. It is true right up to the moment it
is not.
