## Symptom

A device that follows a byte layout in a data sheet receives frames from a Qt program and rejects every one, or reads an id of 513 where 258 was sent. Frames that pass between two Qt programs look fine, because both use the same defaults.

## Cause

A `QDataStream` has defaults that suit Qt talking to Qt, and not a data sheet. Its byte order is big endian. A `float` goes out as eight bytes, because the default precision is double. Two Qt programs agree and a device does not.

Measured: the 16 bit number 0x0102 was **01 02** by default and **02 01** little endian. The float 1.5 was **8 bytes**, `3f f8 00 00 00 00 00 00`, by default and **4 bytes**, `3f c0 00 00`, with single precision.

## Fix

Say every choice the format makes, on every stream:

```cpp
stream.setByteOrder(QDataStream::LittleEndian);
stream.setFloatingPointPrecision(QDataStream::DoublePrecision);
```
