## Symptom

The application looks right on the machine it was written on and wrong on a
better screen: everything is drawn small, in the top left corner, with the rest
of the widget empty. On a screen at three times the ratio it is a ninth of the
size.

Rendering to an image for a report or a test has the same fault, and the image
is the right size, which makes it look like a drawing bug rather than a scaling
one.

## Cause

There are two kinds of pixel and only one of them was set.

A widget 100 units wide on a display that draws two device pixels per unit is
200 pixels of memory and 100 of arithmetic. The image has to be sized in the
first kind and told the ratio, so that the painter accepts the second.

```cpp
QImage image(size * ratio, QImage::Format_ARGB32);   // right size
// and nothing tells it the ratio, so the painter treats its coordinates as
// device pixels
```

Measured on a 100 by 60 chart at a ratio of 2:

| | image | ink | bounding box |
|---|---|---|---|
| ratio 1 | 100x60 | 396 | 0,0..99,59 |
| ratio 2, never told | 200x120 | 397 | 0,0..100,60 |
| ratio 2, told | 200x120 | 797 | 0,0..199,119 |

The middle row is the same image size as the last and a quarter of the drawing.

**At a ratio of 1 the two are identical.** That is the whole reason this ships:
the person who wrote it has a ratio of 1, the test machine has a ratio of 1, and
the fault appears only on the screens somebody paid more for.

## Fix

Size in device pixels and set the ratio, together, in one place.

```cpp
QImage canvas() const {
  QImage image(device(), QImage::Format_ARGB32);   // logical * ratio, rounded
  image.setDevicePixelRatio(ratio);
  return image;
}
```

Then paint in logical coordinates and never think about it again. That is the
point of the ratio: everything above this line is in the units the layout is in.

Three details.

**Round the device size.** A ratio is not always a whole number: 1.5 and 1.25
are ordinary settings, and 101 logical units at 1.5 is 151.5 device pixels,
which does not exist.

**Test at a ratio other than one.** A test that renders at 1 passes on every
version of this bug. Rendering the same drawing at 1 and at 2 and comparing the
bounding boxes takes four lines and catches all of them.

**Do not fix it by multiplying the coordinates.** Painting at `x * ratio` gets
the picture back on a screen and breaks every hit test, every layout calculation
and every stored geometry, because now half the program is in one unit and half
in the other. Set the ratio and leave the coordinates alone.

The related mistakes are `E-QT-0013`, a pen width that means something different
on each screen, and `E-QT-0014`, a coordinate read back from an image without
dividing by the ratio.
