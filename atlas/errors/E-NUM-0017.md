title: A number that does not say what it is
match: the conversion lives in one place instead of everywhere
match: a quantity is one double, and costs nothing to be one
platforms: linux, windows

## Symptom

A robot that moves a thousand times too far, or a thousandth as far, and stops
against something. An angle that comes out at 57 times what it should be. A
timeout that fires immediately or never. A gain that behaves differently after a
sensor is replaced with one that reports in different units.

Nothing produced a warning. Every value was a `double` and every operation was
valid arithmetic.

## Cause

Every value in a robot is a quantity of something, and nothing in a `double`
records which something.

Metres and millimetres are both doubles. So are radians and degrees, seconds and
milliseconds, a position and a velocity, and a value in the world frame and the
same value in the robot's. Adding two of them compiles perfectly whatever they
mean.

The usual repair makes it worse: a comment saying `// millimetres`, a naming
convention like `distance_mm`, a factor of a thousand written wherever somebody
noticed one was needed. Each of those is a promise nothing checks, and the
factors accumulate in different files until nobody can say how many there should
be.

## Fix

Give the number a type that carries the unit.

```cpp
template <class Tag>
class Quantity {
 public:
  explicit constexpr Quantity(double value) : value_(value) {}
  // arithmetic defined between two of the same Tag, and nowhere else
};

struct MetreTag {};
using Metres = Quantity<MetreTag>;
```

The tag has no members and is never instantiated. It exists so that
`Quantity<MetreTag>` and `Quantity<SecondTag>` are different types, and that is
the entire mechanism.

It costs nothing. `sizeof(Metres)` is `sizeof(double)`, it is trivially
copyable, and every operation is a function that disappears. There is no runtime
representation of a unit anywhere.

**Put the conversions in one place**, as named functions:

```cpp
constexpr Metres millimetres(double value) { return Metres(value / 1000.0); }
constexpr double as_millimetres(Metres length) { return length.value() * 1000.0; }
```

That is where a unit system earns its keep. Not in the arithmetic, which was
probably right anyway, but in a factor of a thousand existing in exactly two
lines of the program instead of wherever somebody remembered it.

**Make the constructor explicit**, so a bare number cannot become a quantity by
being passed to something that wanted one: see `E-NUM-0018`.

**And know what it does not check**: a unit is not a meaning, which is
`E-NUM-0019`.
