## Symptom

On exit the program prints "QThread: Destroyed while thread is still running" and aborts, or crashes in a thread after its owner has gone. It happens only when the program is closed while the sensor is running, which is the usual way to close it.

## Cause

Asking a thread to stop is not stopping it. `requestInterruption()` sets a flag, and the thread may be mid-iteration, using the object that is being destroyed. Only `wait()` says it is finished. A thread that is destroyed while running is a fatal error in Qt, and one that keeps running after what it writes to has gone is a use after free.

Measured: a bridge stopped after 50 ms produced the same count fifty milliseconds later, and 20 bridges destroyed while their threads were running all shut down cleanly because the destructor asks and waits. A bridge that was never started could be stopped, twice.

## Fix

Ask, then wait, in `stop()`, and call it from the destructor:

```cpp
loop_.requestInterruption();
loop_.wait();
```
