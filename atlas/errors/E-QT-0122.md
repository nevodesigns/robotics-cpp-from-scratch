id: E-QT-0122
title: An object that was to be deleted later and never was
match: an object told deleteLater is still there when no loop runs again, and flush_deferred_deletes deletes it
match: expected !alive_after_drain
platforms: linux, windows
teaches: 12-11-the-station-that-closed-badly
---

## Symptom

A leak checker reports objects that were deleted with deleteLater at the end of the program, or a destructor that saves a file never runs, because it was waiting for a loop.

## Cause

A deferred delete is an event that an event loop delivers. A program that has left its loop has nothing to deliver it. Measured: after `deleteLater()` and `processEvents()` the object was **still alive**; after `flush_deferred_deletes()` it was **gone** and the live count was 0.

## Fix

Send the deferred deletes as one of the last steps:

```cpp
QCoreApplication::sendPostedEvents(nullptr, QEvent::DeferredDelete);
```
