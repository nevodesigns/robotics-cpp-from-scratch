## Symptom

A log line says only "std::exception" where the program threw something with a long, specific message, or the message survives and the type does not. A handler for the specific type further up never runs.

## Cause

`catch (std::exception e)` makes a new `std::exception` by copying the base part of what was thrown. The derived type and its message are cut off. This is slicing, and it happens for exceptions for the same reason it happens for any
polymorphic type passed by value.

Measured: `invalid_argument("the specific message")` caught by value was no longer an `invalid_argument`, on every toolchain. On libstdc++ the message became **"std::exception"** as well; on MSVC the text survived and the type did not. Caught by reference it kept both.

## Fix

```cpp
catch (const std::exception& e) { ... e.what() ... }
```

Most specific handlers first, then the general one, and always by const reference.
