title: A mean that divides by the count it asked for, not the count it got

## Symptom

A moving average reads low for the first few seconds after start-up, then
corrects itself. A controller driven by it lurches at the start of every run and
is fine afterwards, so it is never caught in a long test.

## Cause

The function averages "the last n readings, or all of them if there are fewer".
The loop is right: it starts at zero when there are fewer than n. The divisor is
the problem.

```cpp
return sum / n;           // n, the count asked for
```

Measured. With two readings 2 and 4 and n of 4, the comment promises 3 and the
code returns **1.5**. With one reading of 5 and n of 3 it returns 1.67 where the
comment says 5. When there are n or more readings, the two agree, which is why
tests with plenty of data pass.

## Fix

Divide by the number of readings actually summed:

```cpp
const std::size_t used = count - start;
return used == 0 ? 0.0 : sum / static_cast<double>(used);
```

and decide what an empty input should return, because `0 / 0` is not a number.

A test that only ever supplies at least n readings will never see this. The case
to add is the one the comment mentions in passing: fewer than n.
