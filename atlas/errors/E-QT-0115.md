title: A robot that starts moving by itself when a reason to stop goes away
match: a link that comes back while the key is still held does not move the robot, and neither does a key held from before the link was good
match: expected after_return
platforms: linux, windows
teaches: 12-08-the-button-that-must-be-held

## Symptom

The link drops, the robot stops, the link comes back, and the robot drives off while the operator, who had not noticed, still has a finger on the key.

## Cause

An interlock that is a pure function of its inputs allows speed again the moment the inputs allow it. Permission to move has to be given by a deliberate act after the last reason to stop has gone. Measured: a link lost and back with the key held gave an allowed speed of **0**; a key held from before the link was good gave **0**; let go and pressed again gave the speed.

## Fix

Arm only on a press while it is safe, and disarm on every reason to stop:

```cpp
if (!alive) armed_ = false;                    // and set_link_alive(true) does not arm
else if (link_alive_ && !estop_ && !latched_) armed_ = true;   // in set_enable(true)
```
