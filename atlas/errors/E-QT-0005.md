title: No Q_OBJECT in the class with the signal
match: static assertion failed: No Q_OBJECT in the class with the signal
platforms: linux, windows

## Symptom

Compilation stops on a static assertion reading: No Q_OBJECT in the class with
the signal. It is usually followed by a long tail of template errors mentioning
QFunctorSlotObject, which are consequences rather than causes.

## Cause

You connected with the pointer to member syntax, connect(&sender,
&Sender::signalName, ...), and the sender's class has no Q_OBJECT macro. Qt 6
checks this at compile time on purpose, because the alternative is the older and
far less helpful undefined reference to vtable at link time.

## Fix

Add Q_OBJECT as the first line inside the class body, make sure the class
inherits QObject, and reconfigure so the build hands the header to moc. Ignore
the template errors that follow the assertion: fixing the assertion removes them
all. See E-QT-0001 for the link time form of the same problem.
