id: E-MEM-0028
title: Pushing a temporary when it could have been built in place
match: reserving removes the moves of growth, and building in place removes all of them
match: expected t_reserved.moves to equal
platforms: linux, windows
teaches: 02-15-how-many-copies
---

## Symptom

A loop that fills a vector with objects shows up as a hot spot, though each object is cheap to make. It is costlier for objects that own something.

## Cause

`push_back(Packet(i))` builds a temporary and then moves it into the vector: one move for every element, and with no `reserve` the moves of growth as well. `emplace_back(i)` builds the object where it will live.

Measured, 100 packets: no reserve **227 moves**, reserve and push_back **100 moves**, reserve and emplace_back **0 copies and 0 moves**. The growth part depends on the library, so the suite checks that reserving
removes it and not its size.

## Fix

```cpp
v.reserve(n);
for (int i = 0; i < n; ++i) v.emplace_back(i);
```
