## Symptom

Closing the window takes seconds, or never finishes: the program hangs on exit with the sensor thread still going. Or the sensor produces far more than its rate, because a loop with no sleep spins.

## Cause

A thread loop that does not look at `isInterruptionRequested()` cannot be stopped by one: `wait()` waits for a loop that never ends. And a loop that sleeps for the period after each reading is bounded by it, while one that forgets the sleep runs as fast as the CPU lets it and fills the latest value's skipped count with millions.

Measured with a 100 Hz sensor for about 200 ms: the bridge produced no more than 100 divided by the period plus 2 readings (the ceiling printed by the test), and stop returned in well under 500 ms.

## Fix

Check the request on every pass, and sleep for the period:

```cpp
while (!isInterruptionRequested()) {
  bridge_->produce_one();
  QThread::msleep(static_cast<unsigned long>(bridge_->period_ms_));
}
```
