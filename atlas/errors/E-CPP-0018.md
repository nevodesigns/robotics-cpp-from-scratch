id: E-CPP-0018
title: remove_if left the container the same length
match: expected .*size\(\) to equal
platforms: linux, windows
teaches: 03-04-algorithms-over-loops

## Symptom

Elements that should have been removed are still counted. The container's size
is unchanged, and the tail holds duplicated or unspecified values. No error is
reported anywhere.

## Cause

std::remove_if cannot resize a container. It is given iterators, and an iterator
has no way to reach the container it points into. What it does is move the
elements you are keeping to the front and return an iterator to the new logical
end, leaving the physical size alone.

## Fix

Erase from the returned iterator to the real end. The pair has a name, the
erase remove idiom:

```cpp
readings.erase(std::remove_if(readings.begin(), readings.end(), is_invalid),
               readings.end());
```

C++20 added std::erase_if, which does both in one call and is the better choice
the day a project moves to it:

```cpp
std::erase_if(readings, is_invalid);
```

The same trap applies to std::remove and std::unique, which also only shuffle.
