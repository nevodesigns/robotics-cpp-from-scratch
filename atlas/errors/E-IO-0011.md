id: E-IO-0011
title: A serial port left in the terminal's default mode
match: every byte the line discipline would have eaten arrives intact
match: a frame whose length byte is an ordinary number survives
platforms: linux, windows
teaches: 08-05-opening-a-real-port
---

## Symptom

The port opens. The device is transmitting. Some messages arrive perfectly,
some arrive truncated, and some never arrive at all, and which is which does not
seem to depend on anything.

Text sent down the same port is flawless, which is the detail that sends people
looking in the wrong place.

## Cause

The port was opened and not configured:

```cpp
const int fd = ::open("/dev/ttyUSB0", O_RDWR);   // the bug is what comes after
```

A serial port arrives in the state a terminal is in when a person is typing at
it, and every part of that state is hostile to binary data. Measured, sending
each of these through a port left at its defaults:

| sent | received |
|---|---|
| `68 69 0A` | `68 69 0A` |
| `68 69 0D` | `68 69 0A` |
| `68 11 69 0A` | `68 69 0A` |
| `68 13 69 0A` | `68 69 0A` |
| `68 03 69 0A` | `69 0A` |
| `68 1A 69 0A` | `69 0A` |
| `68 58 7F 69 0A` | `68 69 0A` |
| `68 69` | nothing |

0x11 and 0x13 are XON and XOFF and are taken as flow control. 0x03 and 0x1A are
interrupt and suspend and discard what came before them. 0x7F erases the
previous byte. 0x0D is rewritten to 0x0A. And with no newline at all, nothing is
delivered, because canonical mode exists to let a person finish a line before
the program sees it.

Now a frame:

```text
sent      AA 04 20 21 22 23 5C
received  AA
```

Nothing in that payload is unusual. What destroyed it was the **length field**,
because the payload was four bytes long and four is the end of file character.
Three is Ctrl-C. Seventeen is XON. Nineteen is XOFF. The message that fails is
chosen by how long it is, and no line of your code mentions its length, which is
why this looks like a device that works except sometimes.

## Fix

One line, immediately after `tcgetattr`:

```cpp
::cfmakeraw(&settings);
```

Raw means deliver bytes as they arrive, change nothing, interpret nothing. With
it, every row of that table arrives exactly as sent.

Then the rest of what a wire needs and a terminal does not:

```cpp
settings.c_cflag |= (CLOCAL | CREAD);          // no modem, receiver on
settings.c_cflag &= ~CSIZE; settings.c_cflag |= CS8;
settings.c_cflag &= ~PARENB;                   // no parity
settings.c_cflag &= ~CSTOPB;                   // one stop bit
settings.c_cflag &= ~CRTSCTS;                  // no hardware flow control
settings.c_cc[VMIN] = 0;
settings.c_cc[VTIME] = 0;
```

On Windows the same trap has different names. `fInX` and `fOutX` are XON and
XOFF and eat the same two bytes. `fBinary` must be `TRUE`, and `SetCommState`
fails if it is not, which is the tidiest way a platform has said that text mode
on a serial port was a mistake.

Then verify it, because `tcsetattr` reports success if it applied any of what it
was given. See `E-IO-0013`: a read back check turns this silent corruption into
an error code returned by `open`, which is the difference between a bug found in
the first minute and one found in the field.
