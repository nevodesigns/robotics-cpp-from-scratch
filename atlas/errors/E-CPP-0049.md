id: E-CPP-0049
title: A destructor that silently stopped the class from moving
match: what the destructor costs when the container grows
platforms: linux, windows
teaches: 03-09-declare-nothing-or-everything
---

## Symptom

A program got slower and nothing in the diff explains it. A profiler shows
time in allocation and in memcpy, in code that only grew a container. The
commit that did it added a destructor, or a logging copy constructor, to a
small struct that holds a buffer.

Nothing warns. Nothing fails. Every test passes.

## Cause

Declaring any one of the five special member functions changes what the
compiler writes for the others, and declaring a destructor suppresses the
implicit **move** constructor.

So the class still copies, because the copy operations are still generated, and
every move of it is quietly a copy.

Measured on three classes holding the same `std::vector<double>`:

| class | moves cheaply | buffer on move |
|---|---|---|
| nothing declared | yes | travelled |
| `~X() = default;` declared | **no** | **copied** |
| copy constructor declared | **no** | **copied** |

Note the second row. The destructor is written `= default`, it does nothing
whatever, it is as close to not being there as the language allows, and it
still does this.

And the cost in a program rather than in a trait. Pushing 64 rows, each
holding 64 doubles, into a `std::vector`:

| element type | allocations |
|---|---|
| nothing declared | 71 |
| `~X() = default;` declared | **198** |

**127 extra allocations from a line that does nothing.** Those are libstdc++
counts; on the Microsoft debug library the gap was 254. Assert the direction
rather than a ratio, because the ratio belongs to the standard library. Every reallocation of
the outer vector has to relocate the rows, and copying one allocates a new
buffer where moving one would have stolen the existing buffer.

## Fix

**Declare nothing.** If every member looks after itself, which is true of
`std::vector`, `std::string`, `std::unique_ptr` and anything built out of them,
the compiler writes all five correctly. This is the rule of zero and it is the
default to reach for.

**If you must declare one, declare all five.** Measured, a class with all five
written `= default` behaves exactly as the one that declared nothing: same
trait, same buffer travel, same 71 allocations. It costs six lines that then
have to stay correct.

**Do not add a destructor for logging.** That is the commonest way this
happens. Log in the owner, or accept the cost knowingly.

**Assert it where it matters.**

```cpp
static_assert(std::is_nothrow_move_constructible<Readings>::value,
              "Readings must be cheap to move. ...");
```

One line at the top of a header, and the next person to add a destructor finds
out immediately rather than in a profile six months later. Lesson 03-09 keeps
that assertion in `checks/`.

**Remember the asymmetry.** Declaring a move constructor suppresses the
implicit copy, and that is refused at the call site because the caller tries to
use what was taken away. Declaring a destructor takes away something the
compiler was going to do on your behalf, and nothing complains at all.
