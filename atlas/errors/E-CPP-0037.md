id: E-CPP-0037
title: A buffer copied at every call, because the parameter was taken by value
match: each call that takes its own copy allocates another buffer
platforms: linux, windows
teaches: 01-11-what-the-call-costs
---

## Symptom

A pipeline that processes sensor readings is slower than the arithmetic in it
can account for. A profiler shows time in allocation and in memcpy, inside
functions that only read their input. Raising the sample rate makes it worse
faster than linearly, because the work per sample did not change but the number
of calls did.

```cpp
double mean(std::vector<double> samples);        // takes a copy
double median(std::vector<double> samples);      // takes another
```

## Cause

A `std::vector` parameter taken by value is a new vector. Its buffer is
allocated and every element is copied into it, for the duration of that call,
and nothing in the source says so.

Measured by comparing the address of the data the callee received against the
caller's, for a vector of 1024 doubles:

| how it is passed | what arrives |
|---|---|
| by value | a new buffer |
| by const reference | the same buffer |
| as a span | the same buffer |

And it is per call, not once. Passing the same vector by value through two
functions:

| | buffers allocated |
|---|---|
| by value | **2** |
| by const reference | 0 |

A chain of five reading functions allocates and copies five times, and each one
looks innocent on its own line.

## Fix

**Take a span for anything you only read.**

```cpp
double mean(rc::span<const double> samples);
```

This is the signature almost every buffer reading function should have. It
copies nothing, and unlike a const reference to `std::vector` it does not demand
that the caller own a `std::vector`: it accepts a vector, a `std::array`, or a
pointer and a length straight from a device driver. Measured against all three,
no copies.

**Take a const reference when the parameter really is that container**, for
instance when you need `capacity()` or will pass it to something else that wants
a vector.

**Take by value deliberately, when you want your own copy**, and when you do,
say so in the name or a comment. `std::vector<double> sorted_copy(std::vector<double>)`
is a reasonable signature: it is going to modify what it was given, and taking a
copy is cheaper than making the caller write one.

**Do not reach for a pointer and a length separately.** It is two parameters
that can disagree, and a span is the same thing with the disagreement removed.
