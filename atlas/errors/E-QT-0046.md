## Symptom

A program that reads a serial port runs for hours and then its memory use climbs until it is killed. A cable came loose, or a device was powered on at the wrong baud rate, and what arrived was noise with no newline in it.

## Cause

A reader that keeps everything since the last newline keeps all of it when there is no newline. The buffer is as long as the noise.

Measured with a limit of 8 bytes: 100000 bytes with no newline left **0** bytes held and no lines returned, and the assembler was skipping. A buffer that kept everything would have held all 100000. When the newline came the long line was counted as dropped (**1**), and the next line, `next`, was read normally.

## Fix

Choose a longest line, stop keeping bytes once it is passed, and remember that the rest of that line is to be thrown away:

```cpp
if (line_.size() > max_) { skipping_ = true; line_.clear(); }
```
