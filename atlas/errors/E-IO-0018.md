## Symptom

After a crash, or after the program was stopped, the file you were saving is
empty, or ends in the middle of a line, and the previous version is gone too.
There is nothing to go back to.

A calibration that took twenty minutes to produce is zero bytes.

## Cause

Three separate causes, and they stack.

**Opening for writing empties the file at the open**, not at the first write.
Measured: a 27 byte calibration file was **0 bytes** the moment the stream
existed, before a single byte of the new contents had been produced. From then
until the last byte is written there is no old file and no new one.

**The rows may never have reached the disk.** Measured: a program wrote 1000
rows of seven bytes, 7000 bytes, through a stream and then called `abort()`.
The file was **0 bytes**. The same program writing `std::endl` after each row
left **7000 of 7000**. The rows were in the stream's buffer, which dies with the
process.

**A file that stops partway can be a valid file.** Measured, on a ten row log
of `0.5,1.5` cut after 77 bytes: the reader found ten rows, no bad lines, and a
last value of 1 where the logger meant 1.5. A row cut short is the same width
and a perfectly good number, so nothing is rejected and nothing is reported.

## Fix

Do not touch the file until the new one is complete.

1. Write to a temporary file beside the real one.
2. Close it, and check that the close worked.
3. Rename it over the real one.

A rename that replaces an existing file is one step on Linux and Windows, so
anything else reading the file sees the old one or the new one and never half
of either.

```cpp
#include <rc/core/save.hpp>

const auto saved = rc::core::save_text("calibration.txt", text);
if (!saved.ok) std::cerr << saved.error << "\n";   // and the old file is untouched
```

Flushing every row, with `std::endl`, is the right answer for a **log** that
you want to survive a crash row by row. It costs a write per row. It does not
help a file that must be replaced whole, which is the other case, and the one
`save_text` is for.

What none of this survives is the power going. The data may still be in the
operating system's cache, and C++17 has no portable way to force it to the
disk. That needs `fsync`, which is platform code.
