## Symptom

A Qt program that builds correctly refuses to start, reporting that it could not
load the xcb or wayland platform plugin.

## Cause

Qt loads a plugin at runtime to talk to the display system, and it is not finding
one. This happens most often over SSH with no display, inside a container, or in
continuous integration where no display exists at all.

## Fix

For a program with no interface, and for every test in this repository, run with
the offscreen platform: QT_QPA_PLATFORM=offscreen ./your_program
On a desktop, install the platform plugin package, which on Ubuntu is
libxcb-cursor0 together with qt6-base-dev. Under WSL2, a current Windows release
provides the display through WSLg with no extra setup.
