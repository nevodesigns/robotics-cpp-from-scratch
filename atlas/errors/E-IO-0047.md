id: E-IO-0047
title: A command that is retried for ever, or never
match: a command nobody answers is sent its number of times and then fails, and is not waiting any more
match: expected link.sender.failed
platforms: linux, windows
teaches: 12-03-the-command-that-arrived-twice
---

## Symptom

A command to a robot that is off is retried every fifty milliseconds for a week and the log is full of it, or a command is sent once and its loss means the robot never moves.

## Cause

A retry with no limit is a loop, and a retry with no retry is a lost command. A limit has to be counted, and the failure has to be kept so that it can be shown. Measured: a command on a link that lost everything was transmitted **5** times, the first and four retries, then failed and was no longer waiting.

## Fix

Count the attempts, and fail the command when they are used up:

```cpp
if (it->second.attempts >= max_attempts_) { failed_.push_back(it->first); it = pending_.erase(it); continue; }
```
