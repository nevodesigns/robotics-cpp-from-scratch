## Symptom

QML code pushes a reading onto a list that is a property of a C++ object, and the C++ side sees it on one machine and not on another. The same code works for one property and not for another that looks identical.

## Cause

A `QStringList` is a sequence type that QML writes back. A `QVariantList` was a JavaScript array on Qt 6.2, which is a copy, and is written back on 6.4 and 6.5. Measured after one push onto each: the `QStringList` had **3** (1 changed signal) on all of 6.2, 6.4.2 and 6.5.3; the `QVariantList` had **2** with **0** signals on 6.2 and **3** with **1** on 6.4.2 and 6.5.3.

## Fix

Do not push onto list properties: what it does is a matter of the Qt version. Give QML a function, or a model:

```cpp
Q_INVOKABLE void append(double value);
```
