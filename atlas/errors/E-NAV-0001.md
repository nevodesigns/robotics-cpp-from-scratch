## Symptom

A robot that works beautifully for the first few minutes and then behaves as
though the world has moved. It stops short of things, or drives into them, and
the error grows the longer it has been running.

Restarting it fixes the problem, which sends everybody looking for a leak or an
overflow. There is neither. It was told where it was at startup, and it has been
guessing ever since.

## Cause

Dead reckoning has no way to be right. Every step adds to the estimate and
nothing ever subtracts, so every error that enters stays in for ever and the
estimate is only as good as the last time somebody told it the truth.

That is not a defect to be fixed. It is what odometry **is**, and it remains the
only thing that keeps working when the lights go out, in a tunnel, under a
gantry, when the camera is blinded.

The defect is treating the estimate as though it were a measurement. A
measurement has an error that stays roughly constant; this has one that grows,
and code that does not distinguish them will trust a five minute old estimate
exactly as much as a fresh one.

## Fix

Carry how far it has driven since the last correction, and let callers see it:

```cpp
class Odometry {
 public:
  rc::sim::Pose update(double left, double right);
  const rc::sim::Pose& pose() const;
  double travelled() const;                    // since the last correction
  void correct(const rc::sim::Pose& truth);
};
```

`travelled()` is the honest confidence measure, and it is more useful than a
time, because the error grows with distance rather than with the clock. A robot
parked for an hour has drifted by nothing.

Then decide, out loud and in one place, what to do about it:

- **Correct it** from something absolute: a landmark, a wall, a charging dock, a
  satellite fix. Everything else in this phase is a way of doing that.
- **Bound the exposure.** Plan moves that end at something recognisable before
  the estimate has drifted further than the task can tolerate.
- **Report it.** A number on a screen saying "forty metres since the last fix"
  turns a mysterious failure into an obvious one.

One design detail worth getting right. A correction replaces the pose and does
**not** reset the odometer's total distance if that total is what you use to
decide whether to trust it. Choose which of the two `travelled()` means and say
so, because both are useful and they are not the same number.
