## Symptom

A sanitizer reports an allocation and deallocation mismatch, naming operator
new[] against operator delete. Without a sanitizer the program frequently
appears to work, which is worse, because the corruption surfaces later somewhere
unrelated.

## Cause

The bracket forms must match. Memory from new[] is released with delete[], and
memory from new is released with delete. An array allocation stores extra
information about how many destructors to run, and plain delete does not know it
is there.

Mixing the family entirely, such as releasing new with free, is the same class
of mistake and equally undefined.

## Fix

Match the forms exactly. Then remove the need to remember: std::vector holds an
array and releases it correctly, and std::unique_ptr has a separate array form,
written std::unique_ptr<T[]>, which calls delete[] for you.

Nearly every real occurrence of this error disappears the moment a raw array
allocation is replaced by a std::vector.
