## Symptom

A name that is three bytes in the data sheet is eight on the wire and the device sees garbage after the first byte. The text is right in a Qt debugger and wrong on a logic analyser.

## Cause

`stream << QString` writes a four byte length, counted in bytes, followed by the characters as UTF-16, big endian by default. That is Qt's own format, and it is nothing like one length byte and UTF-8.

Measured: the string "ab" went out as **8 bytes**, `00 00 00 04 00 61 00 62`. The format of the lesson writes the name's length as one byte and the name as UTF-8 with `writeRawData`: id 258, value 1.5 and the name micro-s came out as **14 bytes**, `02 01 00 00 00 00 00 00 f8 3f 03 c2 b5 73`. A name over 255 bytes is refused by the encoder, since the length byte could not say it.

## Fix

Write the text yourself:

```cpp
const QByteArray name = r.name.toUtf8();
stream << static_cast<quint8>(name.size());
stream.writeRawData(name.constData(), name.size());
```
