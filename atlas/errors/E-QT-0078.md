## Symptom

A test or an application crashes on a null pointer after loading a QML file, only when the interface is large or loaded in the background, and works with a small file on a fast disk.

## Cause

A component loaded asynchronously is Loading until the event loop has delivered the result, and `create()` on it returns null. Measured on Qt 6.2: a local file loaded by default was **Ready**; loaded with `Asynchronous` it was **Loading**, and `create()` gave null.

## Fix

Wait for the status to change, with the event loop running:

```cpp
QObject::connect(&component, &QQmlComponent::statusChanged, &loop, [&loop](QQmlComponent::Status s) { if (s != QQmlComponent::Loading) loop.quit(); });
loop.exec();
```
