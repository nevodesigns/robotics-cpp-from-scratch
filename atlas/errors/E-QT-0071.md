match: an object read from a property is not collected, and the pool is one owner for everything it was given

platforms: linux, windows

## Symptom

Objects handed to QML are sometimes deleted twice, sometimes never, depending on which factory function made them.

## Cause

A parent without the ownership marking leaves the choice to the engine at the moment of return, and the marking without a parent leaves no owner. Measured: with the pool, two pooled objects were alive after a collection (**3** with the held property), the pool owned **2**, and `pool.clear()` took alive to **1** and the pool to **0**.

## Fix

Do both in one function, in one place, and have every factory use it:

```cpp
QObject* add(QObject* object) { keep_alive(object, this); return object; }
```
