## Symptom

```
error: invalid conversion from 'const char*' to 'int'
error: '::main' must return 'int'
error: cannot convert 'std::basic_ostream<char>' to 'int' in return
```

A program tries to end by saying what went wrong, and the compiler refuses.

## Cause

There are exactly two ways out of a program, and they do two different jobs.

**Two streams of text**, for people to read.

**One number**, for whatever ran the program to act on.

The number has nowhere to put a sentence, and that is not an oversight. It is
read by shells, build systems and the supervisor that starts your robot, none
of which know what your program does or can display your text. The only thing
any of them can do with it is decide whether to carry on.

So each of these is refused for the same reason:

| what was written | why |
| --- | --- |
| `return "cannot open the file";` | a message is not a number |
| `void main()` | something is always waiting for the number |
| `return std::cerr << "failed";` | `<<` hands back the stream, not a result |

The third is the subtle one, and it is worth understanding rather than just
avoiding. Each `<<` returns the stream so the next one has something to attach
to, which is what makes a chain work. It does not report whether anything was
written.

That matters more than it looks: a stream that has failed, because the disk
filled or the pipe at the other end closed, does not say so and does not
throw. It sets a flag on itself and silently discards everything afterwards.
A program whose only report is its printing can print nothing at all and still
end with the number 0.

## Fix

Two lines, always. The message for the human, the number for the machine.

```cpp
#include <rc/core/exit_status.hpp>

if (!file) {
  std::cerr << "cannot open " << path << "\n";
  return rc::core::kFailed;
}
```

`rc/core/exit_status.hpp` names the three conventional codes, because `0` and
`1` and `2` scattered through the bottom of `main` are three magic numbers
nobody can grep for:

| | |
| --- | --- |
| `kSuccess` is 0 | it did what it was asked |
| `kFailed` is 1 | it tried and could not |
| `kMisused` is 2 | it was asked for something that makes no sense |

Keeping the last two apart is what lets a script tell a broken input from a
broken machine, which are two problems with two different people to tell
about them.

One mercy worth knowing, because it looks like an exception to the rule.
`main` is the only function in C++ that may reach the end of its body without
a `return`, and doing so is defined to return 0. So `int main() { work(); }`
is legal. Write the `return` anyway: a reader cannot otherwise tell a function
that succeeded from one where somebody forgot.

`E-NUM-0024` is what happens when the number you hand back is too large, which
is the next mistake after this one.
