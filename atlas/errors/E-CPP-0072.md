## Symptom

Two ways the same keyword goes wrong, both silent.

**A function whose answer depends on its history.** A test passes alone and fails
after another test, or passes today and fails when a new test is added above it.
The function was called with the same arguments and returned something else.

**A count of live objects that is wrong.** It reads 3 when there are 4, or goes
negative, or never returns to zero. It is wrong by exactly the number of copies
that were made.

## Cause

**A static local gives the function a memory.** It is built the first time control
reaches it and keeps its value from then on:

```cpp
inline int next_id() { static int next = 1; return next++; }
```

Measured, three calls gave 1, 2, 3, and the first number a test sees depends on
how many calls came before it in the same program. A test cannot start it from
zero. Lesson 05-06 measures what that does to a suite.

When it is built matters too. A static local is built when first reached and
destroyed after `main` returns, in the reverse order of construction. A sensor in
a static local was built 0 times before the first call and 1 after ten, where the
same function without `static` built one per call.

**A static counter has to see every way an object is made.** A copy is a new
object that the ordinary constructor never ran for, so a class that adds one
there and takes one away in the destructor drifts down by one per copy. The
compiler's own copy constructor does not touch the counter.

## Fix

For the memory: know that it is there, and give tests a way in when a function
needs one. Prefer passing the state as an argument, or keeping it in an object
whose lifetime the test controls.

For the counter, count in the copy constructor too:

```cpp
explicit Wheel(double radius) : radius_(radius) { ++live_; }
Wheel(const Wheel& other)     : radius_(other.radius_) { ++live_; }
~Wheel()                       { --live_; }
```

and, if the class is movable, the move constructor as well. Lesson 02-05 is the
list of ways an object can be made.
