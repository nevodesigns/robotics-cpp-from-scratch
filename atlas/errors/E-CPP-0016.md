## Symptom

A value read through a reference or iterator is wrong, or the program crashes,
after something was added to the container. Under the address sanitizer it
appears as a use after free whose free is inside the container's own code, which
is confusing until you know why.

## Cause

A vector holds one block of memory. Growing past its capacity allocates a larger
block, moves the elements across, and frees the old one, so every pointer,
reference and iterator into it now refers to memory that has been released.

```cpp
double& first = readings[0];
readings.push_back(1.0);   // may reallocate
first = 2.0;               // may write to freed memory
```

Nothing warns. It works until the push happens to be the one that reallocates,
which depends on the capacity, which depends on how many elements arrived
earlier. That is why it appears late and looks intermittent.

## Fix

Do not hold a reference into a container across anything that could change its
size. Take the value by copy, or re read it afterwards, or hold an index rather
than a reference, since an index survives reallocation.

```cpp
const std::size_t at = 0;
readings.push_back(1.0);
readings[at] = 2.0;        // fine
```

Where the elements genuinely must stay put, reserve the capacity up front so no
reallocation happens, or use a container with stable references such as
std::map, or a fixed capacity buffer that never grows.

std::unordered_map keeps references valid across inserts but invalidates
iterators when it rehashes, which is a distinction worth remembering.
