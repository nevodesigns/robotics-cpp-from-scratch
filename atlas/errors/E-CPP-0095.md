title: Events at the same time in no particular order

match: expected this to be true: in_order
platforms: linux, windows

## Symptom

Two commands scheduled for the same instant, "stop the motor" and "close the gripper", run in one order on one machine and the other order on another, or in a different order after an unrelated change. A test that passes on the laptop fails on the build server.

## Cause

A priority queue says which is first only when two elements differ under its comparison. For equal elements the standard does not say, and the order depends on the heap's layout.

Measured: eight events at the same time, scheduled 0 to 7. The event queue gave 0 1 2 3 4 5 6 7. A `priority_queue` comparing only the time gave **0 2 6 5 7 4 1 3** on libstdc++, and that is not promised to be the same anywhere else.

## Fix

Give each event a sequence number when it is scheduled and compare it after the time:

```cpp
if (a.time != b.time) return a.time > b.time;
return a.seq > b.seq;
```
