## Symptom

A function with overloads for `bool` and `std::string` is called with a message, and the log says it is OK. The failure text never appears. The same call with a `std::string` variable works.

## Cause

A string literal is an array of `const char`. It becomes a `const char*` at no cost, and a pointer converts to `bool` with one more built-in conversion. Becoming a `std::string` needs a constructor to run, and overload resolution ranks a built-in conversion above a user-defined one. A pointer to a literal is never null, so the `bool` is true.

Measured: `report("transmission failed")` with only the `bool` and `std::string` overloads wrote **"flag: ok;"**.

## Fix

Add the overload that the literal matches exactly:

```cpp
void report(const char* message) { report(std::string(message)); }
```

With it the same call wrote `message: transmission failed;`, and flags and strings still went to their own.
