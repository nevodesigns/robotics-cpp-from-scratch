id: E-BUS-0034
title: A setting changed to something that is not what it was
match: a setting is read back as it was declared, and one that was never declared is not there
match: a wrong type, a value out of range and a read only setting are refused, and nothing changes
platforms: linux, windows
teaches: 17-12-settings-that-change-while-running
---

## Symptom

A gain of 250 is accepted and the arm shakes itself apart, or a mistyped name is accepted and nothing happens, and the operator believes it worked.

## Cause

A setting has a declared type, an optional range and a read only flag, and a set is refused unless all of them are met. Five requests were refused, kp as an integer, kp = 250, kp = -1, the read only serial and channels as a real, and nothing changed. A name never declared was refused as not declared.

## Fix

Declare each setting and check every set against the declaration.

```cpp
if (c.second.type != found->second.type) return fail(c.first + ": wrong type");
```
