## Symptom

The application prints something like "failed to load main.qml" and exits. The
file is several hundred lines. Nothing says which line.

Or worse, `engine.rootObjects()` is empty, the code checks for that, and the
message it prints is one somebody wrote by hand, so it says the file is missing
when the file is present and has a typo on line 214.

## Cause

The error information was thrown away at the point it was available.

`QQmlComponent` knows exactly what is wrong. `errors()` returns a
`QList<QQmlError>`, each carrying a url, a description, a line and a column.
`QQmlApplicationEngine::load` does not hand that list back, and a caller that
checks `rootObjects().isEmpty()` has reduced all of it to one bit.

Every mistake in this tier arrives with a location. Measured:

| case | loaded | errors | first location |
|---|---|---|---|
| a syntax error | NO | 1 | 2:15 |
| a type that does not exist | NO | 1 | 2:1 |
| a property that does not exist | NO | 1 | 2:8 |
| a missing import | NO | 1 | 1:1 |
| a string where a number goes | NO | 1 | 2:15 |
| a colour that is not one | NO | 1 | 2:20 |

Six for six, refused before anything was created, each with a line and a column
that a caller discarded.

## Fix

**Use `QQmlComponent` and return its errors.** It is the primitive underneath
`QQmlApplicationEngine`, and it gives the list rather than a bool.

```cpp
QQmlComponent component(&engine, url);
QObject* root = component.isError() ? nullptr : component.create();
if (root == nullptr) return rc::unexpected(problems_from(component.errors()));
```

**Return the problems, not a boolean.** `rc::expected<QObject*,
std::vector<QmlProblem>>` costs nothing and means the caller can print the file,
the line and the column, which is the difference between a report and a
complaint.

**Never write your own message about why it failed.** QML's description is
accurate and yours is a guess. Print QML's.

**Handle an empty error list.** A component can fail to produce a root object
with nothing in `errors()`, and a caller handed an empty list of reasons has
been told nothing. Put one problem in it saying that much.

**Keep the component alive as long as its object.** Destroying a `QQmlComponent`
while the object it created is still in use takes the object's type information
with it, which is a separate and much stranger failure.
