title: An update rate the bus cannot give
match: the control loop on the servo arm cannot run faster than 100 Hz
match: the arm is sluggish at a low baud rate
match: the bus takes a few milliseconds a cycle and a slow bus cannot keep an arm up to date
platforms: linux, windows
teaches: 29-07-an-arm-made-of-smart-servos

## Symptom

The loop built on the servos will not run faster than a few hundred updates a second, or much less. Adding servos slows the loop; raising the loop rate makes it miss updates.

## Cause

The wire sets the rate. A cycle of goals and readings for six servos took 2.98 ms at 1 Mbit/s and 14.3 ms at 115200 bit/s; twelve took 5.68 ms.

Every servo on a shared bus takes its turn: a packet out, a packet back, at a baud rate. The time for a cycle is set by the bytes and the rate, not by the program.

## Fix

Use the highest baud rate the servos take, send one goal packet to all (a sync write), read only what is needed, and design the loop for the rate you actually get.

```cpp
const double t = rc::arm::bus_cycle_seconds(bus, 6);   // 2.98 ms at 1 Mbit/s
```
