## Symptom

A fourth command is added. The program builds, and when the new command arrives the robot does nothing, or the wrong thing, because the function that applies commands was never told. It is found on the robot.

## Cause

With a `kind` field and a `switch`, a new kind with no `case` falls through to nothing, and the compiler is not obliged to say so. `std::visit` needs a function for every alternative of the variant, and
for one with none there is nothing to call.

The lesson ships a snippet that adds a `Park` kind and visits it with the three-kind `Applier`. The build tries to compile it and is expected to fail, which it does with `no type named 'type' in 'struct std::invoke_result<Applier, Park&>'`, so the guarantee is checked and not remembered.

## Fix

Write the visitor as a struct with one `operator()` for each kind, and add the new one when the new kind is added. The compiler lists what is missing:

```cpp
struct Applier {
  RobotState& state;
  void operator()(const Stop&) const;
  void operator()(const Drive&) const;
  void operator()(const SetLimit&) const;
  void operator()(const Park&) const;      // the build fails until this exists
};
```
