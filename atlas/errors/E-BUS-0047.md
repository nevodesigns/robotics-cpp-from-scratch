id: E-BUS-0047
title: A damaged recording read as if it were whole
match: a file that is not a bag, or that stops in the middle, is refused at every point it could stop, and leaves nothing behind
platforms: linux, windows
teaches: 17-16-record-and-replay
---

## Symptom

A recording from a robot that lost power replays most of a run, and the last message is missing or wrong, and nothing says the file was damaged.

## Cause

A reader must check before every read, and must not leave half a result behind. All 92 prefixes of the test file were refused and none left entries in the bag, and a file with its first letter changed was bad_magic.

## Fix

Parse into a copy and replace the output only on success.

```cpp
Bag parsed;
// ... read every entry into parsed ...
out.entries_ = parsed.entries_;
```
