id: E-QT-0114
title: A held enable key seen as let go
match: holding a key sends releases that are repeats, and a handler that believes them sees the key let go
match: losing focus ends the hold, and the key must be pressed again
platforms: linux, windows
teaches: 12-08-the-button-that-must-be-held
---

## Symptom

The robot stutters while the operator holds the key: it moves, stops and moves again several times a second. Or it keeps moving after the operator has switched to another window.

## Cause

A held key is repeated by the system, and on some platforms each repeat is a release and a press marked as auto-repeat. A handler that does not look at the mark sees the key let go. And a key released in another window is never seen. Measured: a naive handler saw the key let go **5** times in one hold; this one **0**; focus lost ended the hold.

## Fix

Ignore auto-repeat, and end the hold on focus lost:

```cpp
if (event.isAutoRepeat()) return;
held_ = event.type() == QEvent::KeyPress;
```
