id: E-IO-0032
title: A reader that spins at full speed when the port fails
match: a port that fails is retried gently, and the reader recovers when it comes back
match: expected this to be true: loops < 2000
platforms: linux, windows
teaches: 08-10-a-reader-thread-of-its-own
---

## Symptom

One core is at 100 percent and the fan is loud, on a robot whose cable has come
out. The program is doing no work. The log is thousands of lines a second of the
same port error, or nothing, because the error counter is not logged and only the
CPU graph shows it.

## Cause

A reader thread that rests only when nothing was waiting has a gap. A port that is
failing does not say "nothing waiting", it says "error", and the code path for an
error returns at once. The loop then asks again immediately, and again, as fast as
the processor will go.

Nothing here is a bug in the usual sense. Every call is correct and the loop is
correct. The failure is that a loop with no rest in one of its branches is a spin.

Measured, 200 ms with every read failing: the reader made **355** attempts and
counted 355 errors, about one every 0.56 ms, which is its rest of 500 microseconds
and not the speed of the processor. A loop with no rest in that branch has nothing
else to wait for, so it runs at the speed of the processor.

## Fix

Rest after an error as well as after nothing:

```cpp
if (!any || link_.port_errors() != errors_before) {
  std::this_thread::sleep_for(options_.idle_sleep);
}
```

And make it recover. A cable that comes back should start delivering frames without
anybody restarting the reader. The test pulls the cable for 200 ms and puts it back,
and the next frame is delivered.

The better design retries with a growing wait so a dead port is not polled twice a
millisecond for an hour. Lesson 08-13 does that.
