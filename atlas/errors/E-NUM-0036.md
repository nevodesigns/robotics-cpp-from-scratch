## Symptom

A configuration value `1,5` or `1.5x` is accepted as 1 or 1.5. A value of `nan` or `inf` passes the parse and then breaks a division three functions later.

## Cause

`strtod` reads as much as looks like a number and stops, reporting where. A caller that ignores the end pointer accepts whatever came first. And `strtod` accepts the words `nan` and `inf` and numbers too big to hold (`1e999` is infinity), which are not numbers a configuration means.

Measured: of ten bad texts (empty, spaces only, `1.5x`, `1,5`, `two`, `1 2`, `nan`, `inf`, `-inf`, `1e999`) **10** were refused, and each refusal left the output as it was.

## Fix

Check the end pointer, allow only blanks after the number, and require a finite value:

```cpp
if (end == text) return false;
while (*end == ' ' || *end == '\t') ++end;
if (*end != '\0') return false;
if (!std::isfinite(value)) return false;
```
