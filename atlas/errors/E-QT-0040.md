title: A word that QVariant calls true
match: QVariant says the words no and off are true, and so are abc and 2, and 0.1 is false
match: expected this to be true: QVariant
platforms: linux, windows

## Symptom

A setting `enable_brakes = no` leaves the brakes on, or `safety = off` leaves the safety check on. The file says the opposite of what the program does.

## Cause

`QVariant::toBool` on a string is false only for an empty string, "0" and "false"; any other text is true. "no" and "off" are true. So is "abc". For numbers, a double is cut to a whole number first, so 0.1 is false, and not a number is true.

Measured on Qt 6.2: `"false"` and `"0"` and the empty string were false; **"no"**, **"off"**, **"abc"** and **"2"** were true; `QVariant(0.1).toBool()` was **false**.

## Fix

Say what the accepted words are, and refuse the rest:

```cpp
if (s == "true" || s == "yes" || s == "on" || s == "1") { *ok = true; return true; }
if (s == "false" || s == "no" || s == "off" || s == "0") { *ok = true; return false; }
return false;           // *ok stays false
```
