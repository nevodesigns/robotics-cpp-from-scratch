title: The cast that was not rounding, and the cell that was twice the size

platforms: linux, windows

## Symptom

A position near the origin lands in the wrong place. Values just below zero and
just above it are treated as the same, so a grid cell, a bucket or a tick count
at zero is twice as wide as every other. A rounded value is off by one for
negative inputs and right for positive ones, so it passes every test written
with positive numbers.

## Cause

A cast from `double` to `int` throws the fraction away **toward zero**. It is
not rounding, and it is not flooring, and for a negative number all three
differ.

| value | `static_cast<int>` | `+ 0.5` first | floor | round |
|---|---|---|---|---|
| 2.9 | 2 | 3 | 2 | 3 |
| -2.9 | **-2** | **-2** | -3 | -3 |
| -0.5 | **0** | **0** | -1 | -1 |

The usual repair, adding a half before the cast, is right for positives only.
Measured over 601 values from -3.00 to 3.00, it disagreed with the correct
rounding on **251**, all of them negative.

Truncation toward zero also gives zero two sides. On a map of one metre cells,
twenty positions from -1.0 to 0.9 landed **19 in cell 0 and 1 in cell -1** by
cast, and 10 and 10 by floor. The cell at the origin is twice the size of every
other.

## Fix

Say which you mean.

```cpp
#include <rc/core/narrow.hpp>

const auto cell = rc::core::floor_to_int(position / cell_size);   // a grid
const auto ticks = rc::core::round_to_int(angle * ticks_per_rad); // nearest
```

A map wants floor, because the cell of -0.5 is the one below zero. A command
wants round. A cast is right only when truncation is what you want, which is
rare enough that the cast should carry a comment saying so.

Do not write `static_cast<int>(value + 0.5)`.
