title: A loop that changed nothing, and a pointer to a copy

## Symptom

A loop that scales, clamps or resets every element leaves the container exactly
as it was. No error, and no crash. The numbers are simply unchanged.

Or a function that finds an element and returns a pointer to it returns a
pointer that is wrong, or valid for a moment and then not.

Or a loop over a large container is slow for no reason anyone can find, and a
profile shows time in the copy constructor.

## Cause

In a range based for the loop variable is **declared by you**, and what you
write decides whether it is the element or a copy of it.

Measured. Five readings summing to 15, doubled:

| loop | sum afterwards |
|---|---|
| `for (double v : values) v *= 2` | **15** |
| `for (double& v : values) v *= 2` | 30 |

A thousand readings, each loop run once, counting copies:

| loop | copies |
|---|---|
| `for (Reading r : readings)` | **1000** |
| `for (const Reading& r : readings)` | 0 |
| `for (auto r : readings)` | **1000** |
| `for (const auto& r : readings)` | 0 |

`auto` does not change this. It has the compiler write the type, and the type it
writes has no reference in it unless you add one.

And the address of a by value loop variable is not the address of the element:
asked from inside the loop, `different` for `double v` and `same` for
`const double& v`.

Whether the compiler says anything depends on which one you have. Measured:
gcc 11 reported nothing for the copy that is modified and thrown away; clang 14
reported `-Wunused-but-set-variable`, but only when the copy was never read
afterwards. Add `sum += v` after the multiplication and both were silent.

## Fix

Read with `const auto&`, change with `auto&`, and copy only something as cheap
as a number.

```cpp
for (Reading& reading : readings) reading.value *= factor;            // change
for (const Reading& reading : readings) sum += reading.value;         // read
for (double value : samples) sum += value;                            // cheap
```

A function that returns a pointer to what it found needs the reference, or it
hands back the address of a copy that is gone:

```cpp
for (const Reading& reading : readings)
  if (reading.value > limit) return &reading;
```
