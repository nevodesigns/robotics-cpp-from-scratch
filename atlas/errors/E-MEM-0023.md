title: Allocating in a loop that has to run on time
match: a steady loop of acquire and release allocates nothing, where new allocates every time
match: expected pool_allocations to equal
platforms: linux, windows
teaches: 02-14-a-loop-that-never-allocates

## Symptom

A control loop that is correct and leak free misses its deadline now and then, always at a different moment. Nothing in the loop is slow. Profiling the loop's own code shows nothing.

## Cause

Each pass makes a message with `new`. How long `new` takes depends on the state of the heap, which depends on everything that ran before: usually quick, sometimes it goes to the operating system. The loop
does not leak, because each message is freed, so a leak check passes (lesson 02-02). It allocates, and the loop's time is hostage to that.

Measured with a count of every allocation: 100000 cycles of taking and giving back a message made **0** heap allocations through the pool and **100000** with `new`.

## Fix

Make the messages once, before the loop, and lend them:

```cpp
Message* m = pool.acquire();     // an index off a stack: no heap
...
pool.release(m);
```
