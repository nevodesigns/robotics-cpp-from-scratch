id: E-BUS-0039
title: A timer that ignores a jump back
match: a clock that jumps back starts the timer again, where one that kept its old schedule is silent until the clock catches up
match: a time that goes forward in small steps, the same time twice and the first time ever are not jumps
platforms: linux, windows
teaches: 17-13-whose-clock-is-it
---

## Symptom

After a simulation restart a node looks frozen for exactly as long as the previous run lasted, with nothing in its log.

## Cause

A timer due at 100.5 s waits for the clock to get there again after a restart to 0. Counting the jump as a new epoch and re-arming gave 199 firings in the next 100 s, against 0 for a timer that kept its old schedule. Any step back counts, even 1.5 to 1.4999; the same time twice does not.

## Fix

Change an epoch on any step back and re-arm timers when it changes.

```cpp
if (t < now_) { ++jumps_back_; ++epoch_; }
```
