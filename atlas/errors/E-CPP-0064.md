## Symptom

A loop that works on every other container does not compile on a `vector<bool>`:

```
error: cannot bind non-const lvalue reference of type 'std::_Bit_reference&'
       to an rvalue of type 'std::_Bit_iterator::reference'
```

The error is about binding to a temporary, and the words `vector<bool>` appear
nowhere in it. Clang says the same thing with its own type name.

## Cause

A `std::vector<bool>` does not store bools. It packs eight flags to a byte, so
there is no `bool` to refer to, and indexing hands back a small stand-in object
that knows which bit it means.

Measured: `sizeof(bool)` is 1 and `sizeof(flags[0])` is **16** on gcc 11, a
pointer to the byte and a mask for the bit. The size is the library's choice,
which is why nothing should depend on it.

A loop variable of `auto&` wants a reference to something that exists, and the
stand-in is a temporary. Both gcc and clang refuse it, which
`checks/a_reference_to_a_flag.cpp` proves.

## Fix

Copy the stand-in, which is as cheap as a bool and still means the same bit:

```cpp
for (auto flag : flags) count += flag;
for (const bool flag : flags) count += flag;
```

To **write** to the flags, use an index:

```cpp
for (std::size_t i = 0; i < flags.size(); ++i) flags[i] = value;
```

If you need real references to flags, use `std::vector<char>` or a vector of a
small struct. The packing is a space saving most programs never needed.
