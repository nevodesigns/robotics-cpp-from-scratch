## Symptom

Statistics over readings that clearly vary report a variance of zero, or a small
negative number. A standard deviation computed from it is not a number.

## Cause

A running total lost the variation. Readings around a large constant, a
temperature near 1,000,000 counts or a timestamp in nanoseconds, spend all of a
double's fifteen significant digits representing the constant part, so the small
differences fall off the bottom. The naive formula, mean of squares minus square
of mean, then subtracts two nearly equal large numbers, which is where the sign
goes wrong.

A negative variance is mathematically impossible, so seeing one is a reliable
diagnosis rather than a puzzle.

## Fix

Use Welford's online method, which never holds the sum:

```cpp
++count_;
const double delta = value - mean_;
mean_ += delta / count_;
const double delta_after = value - mean_;
m2_ += delta * delta_after;
```

Every quantity stays the size of the variation rather than the size of the total.
If a large constant offset is known in advance, subtracting it from every reading
before accumulating achieves the same thing and is worth doing for timestamps.
