## Symptom

Two opposite complaints from the same keyword.

**It compiled and should not have.** A function taking a distance is called with
7 and runs. A speed is passed where an angle was wanted and nothing objects,
because every number in the program converts to every class that takes one.

**It does not compile and the message is oblique.**

```
error: conversion from 'double' to non-scalar type 'Meters' requested          (gcc)
error: no viable conversion from 'double' to 'Meters'                          (clang)
error C2440: cannot convert from 'double' to 'Meters'
             note: constructor is declared 'explicit'                          (MSVC)
```

## Cause

A constructor that can be called with one value is also an **implicit
conversion** from that value's type, unless it is marked `explicit`.

Measured, with a class whose constructor was not explicit: `whole_part(7)`
compiled and returned 7, the bare 7 having been turned into the class without
anyone asking. With `explicit`, the same call is refused by both compilers, and
so is the copy form, `Meters m = 5.0;`.

The standard library does this on purpose. `std::vector<int> v = 5;` does not
compile, because the vector constructor taking a size is `explicit`. A vector
equal to 5 is not a thing anybody means.

## Fix

Mark a one-value constructor `explicit` unless the conversion is the whole point
of the type.

```cpp
class Meters {
 public:
  explicit Meters(double value) : value_(value) {}
};

to_feet(Meters(1.0));       // says what it means
to_feet(1.0);               // refused: is 1.0 a distance?
```

When the compiler refuses, the message is right. Either write the constructor
call, so the reader sees the decision, or ask whether the function should have
been taking a distance at all.

The exceptions are types that really are wrappers for their contents, where
`std::string s = "text"` reading naturally is the point. A distance, an angle, a
duration and a count are not those.
