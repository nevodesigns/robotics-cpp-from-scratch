## Symptom

The interface is smooth with the sensor off and sluggish with it on, and keeps updating for seconds after the sensor stops. Memory climbs while the sensor runs. Nothing is wrong with any one update.

## Cause

A queued connection posts an event for every emit, and Qt does not merge them. If the slot is slower than the sensor, the event queue grows for as long as the sensor runs, and the interface is showing readings that are old by the length of the queue.

Measured: 10000 queued emits were **0** calls before the loop ran and **10000** calls after it. The last value was 9999, so the interface worked through 9999 values it did not need on the way to the one it did.

## Fix

Keep only the newest value, and post one event while one is not already waiting:

```cpp
post = !pending_;       // under the lock
pending_ = true;
if (post) QMetaObject::invokeMethod(this, &LatestValue::deliver, Qt::QueuedConnection);
```
