title: A mask on a narrow type that loses the top of the word
match: a narrow register promotes before it shifts, and the top bit goes nowhere
platforms: linux, windows
teaches: 01-10-the-fault-that-never-fired
---

## Symptom

A bit shifted off the end of a `std::uint8_t` or `std::uint16_t` and
disappeared, or a mask built by shifting came out as zero. Or clearing one flag
cleared several, or set bits in a part of a register the code never touched.

The expression looks right and gives the right answer in a print statement,
then the wrong one when assigned to a variable.

## Cause

Narrow integer types promote to `int` before anything happens to them, so the
expression is a different type and a different width from the variable it came
from.

Measured on a `std::uint8_t` holding `0x80`:

| | value | sizeof |
|---|---|---|
| `narrow` | 0x80 | 1 |
| `narrow << 1` as an expression | 256 | 4 |
| stored back into the `std::uint8_t` | 0 | 1 |

The shift did not lose the bit. The assignment did, and nothing said so.

The complement is the same problem with a worse failure. For a mask of `0x02`
held in a `std::uint8_t`:

| | value | sizeof |
|---|---|---|
| `~mask` | **-3** | 4 |

So `~mask` is a signed int with the whole top of the word set. `value & ~mask`
gives the right answer because the and throws the top away again, and storing
`~mask` anywhere, or comparing it, does not.

Neither of these produces a warning under `-Wall -Wextra` on gcc or clang.
`-Wconversion` reports the narrowing, and it also reports several hundred
conversions that are fine, which is why almost nobody has it on.

## Fix

**Pick one register width and stay at it.** `rc::core::Bits` is a fixed
`std::uint32_t`, so every expression is already the width it looks like. A
narrower device register widens into it losing nothing. This removes the
question rather than answering it at each use.

**Shift the wide value, not the narrow one.** `Bits{1u} << index`, never
`1 << index`, so the shift happens at the register width. `1 << 31` on a signed
int is undefined behaviour, which is a separate problem in the same line.

**Cast at the assignment, where the loss happens**, if you genuinely must store
back into a narrow type, and know that you are discarding something.

**Never store a complement.** `~mask` is for using immediately in an and. If
you want the inverse of a mask as a value, compute it at the register width.

**Build masks with a function.** `rc::core::bit(index)` checks the index and
shifts at the right width, which is two of these traps closed in one call.
