title: A choice that cannot say none
match: the tool picked a robot that could not lift the part
match: the selection always returned something
match: four different jobs go to four different robots, and a job nothing can do is refused
platforms: linux, windows

## Symptom

The selection always names a robot, even for a job that none of them can do. The selection tool is run for an odd job and confidently names a robot.

## Cause

It took the best of the list without checking that the best passes every requirement. A job of 500 kg must give -1: no robot.

Taking the maximum of a score over a list always gives an answer. Only checking each requirement as pass or fail before ranking can give none.

## Fix

Return a refusal when nothing passes, and give each family's verdict so the user can see which requirement stopped it.

```cpp
rc::arm::Verdict verdicts[5];
const int f = rc::arm::choose_family(robots, families, 5, task, verdicts);
if (f < 0) explain(verdicts);   // payload_ok false for every one
```

Saying no robot fits is a result, and the cheapest one: it is found before anything is bought.
