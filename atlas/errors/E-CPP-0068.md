title: A call that is ambiguous, because two namespaces both offer the name

## Symptom

A line that looks innocent stops compiling, and the message says that a name is
ambiguous without saying between what:

```
error: call of overloaded 'limit(double)' is ambiguous               (gcc)
error: call to 'limit' is ambiguous                                  (clang)
error: reference to 'count' is ambiguous                             (gcc, clang)
error C2668: 'limit': ambiguous call to overloaded function          (MSVC)
```

Often it appears after adding an `#include`, a `using` line, or a new library,
none of which touched the line that fails.

## Cause

A using-directive, `using namespace x;`, makes every name in `x` visible without
its prefix. Make two namespaces visible and both can offer the same name:

```cpp
using namespace drive;
using namespace arm;
limit(1.0);          // drive::limit or arm::limit?
```

Measured: both candidates fit equally well, so both compilers refuse, which
`checks/two_namespaces_both_used.cpp` proves.

The same happens with a name of your own and one in `std`. A global variable
called `count`, with `using namespace std;` and `<algorithm>` included, gave
`reference to 'count' is ambiguous` on gcc 11 and clang 14, because `std` has an
algorithm called `count`. Nothing you wrote changed. A header you included
started offering a name.

## Fix

Write the prefix.

```cpp
drive::limit(1.0);
arm::limit(1.0);
```

Or name the one function you mean, with a using-declaration in the smallest scope
that needs it:

```cpp
void tune_drive() {
  using drive::limit;
  limit(2.0);        // drive::limit, and nothing else came with it
}
```

Do not fix it by renaming one of the functions. The namespaces exist so that
neither has to be called `drive_limit`.

This is the loud case, and it is the good one. The quiet case is `E-CPP-0069`.
