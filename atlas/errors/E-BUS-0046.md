title: A recording that does not round trip
match: a bag written to bytes and read back is the same bag, stamps to the last bit and payloads with zero bytes in them
match: a node fed from a recording gives exactly the output it gave live, so a bad day can be replayed as often as it takes to understand it
platforms: linux, windows
teaches: 17-16-record-and-replay

## Symptom

A replayed day behaves differently from the live one: a payload is cut short, a stamp is a little different, and the bug does not reproduce.

## Cause

A payload is bytes and a double is eight bytes, and both must be written exactly. Four messages, one with a zero byte in its payload, were 92 bytes and came back with every stamp equal to the last bit and every payload the same size. A node that averaged the scans gave 2.000 3.000 2.333 3.250 3.000 live and the same when its messages came from the file.

## Fix

Write lengths with strings, and doubles as their bytes.

```cpp
w.put_string(e.topic);
w.put_f64(e.stamp);
w.put_string(e.payload);
```
