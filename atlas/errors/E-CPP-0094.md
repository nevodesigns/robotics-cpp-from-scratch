title: A schedule that runs the latest event first

## Symptom

A simulation processes events in the wrong order: the last thing scheduled happens first, or a timer set for ten seconds fires before one set for one second.

## Cause

`std::priority_queue` is a max-heap. Its `top()` is the greatest element by the comparison it is given, and the default comparison is `<`, so the greatest time comes out first. A schedule wants the smallest.

Measured: the numbers 5, 1, 9 and 3 in a plain `priority_queue<int>` gave **9** first. The event queue compares the other way round and gave 1, 3, 5, 9.

## Fix

Compare with "comes after", so the one that is not later than any other is on top:

```cpp
struct Later {
  bool operator()(const Event& a, const Event& b) const { return a.time > b.time; }
};
std::priority_queue<Event, std::vector<Event>, Later> queue_;
```
