title: A sensor thread that reaches into the interface
match: a sensor on its own thread reaches the interface on the interface's thread, and every reading is accounted for
match: expected shown_on == interface_thread
platforms: linux, windows
teaches: 09-14-the-sensor-that-never-touched-the-screen

## Symptom

The sensor thread calls a function on an interface object to show a reading: a label's setText, a model's setData, a slot called directly. The program works for minutes and then draws garbage or crashes in the paint code, and Qt may print that an object was used from another thread.

## Cause

An interface object belongs to the thread that runs its loop, and its state is not protected against another thread. A call from the sensor's thread is a data race with the loop that is painting it.

Measured with the bridge: a 1 kHz sensor produced readings on **another thread**, and every update was shown on **the interface's thread**. The producer called nothing but `publish`. Readings produced equalled readings published, and updates plus skipped equalled both.

## Fix

Make the producer's only call the one that is safe from any thread, and let the interface's loop do the rest:

```cpp
latest_.publish(value);     // the thread's whole contact with the interface
```
