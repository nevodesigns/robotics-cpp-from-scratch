id: E-IO-0028
title: A loop that reads one message a tick and acts on the past
match: acting on one message a tick: the data the robot acts on is seconds old
match: expected this to be true: one.mean_age
platforms: linux, windows
teaches: 08-09-the-newest-reading-or-all-of-them
---

## Symptom

The robot responds to things a few seconds after they happen. A sensor reading
that was true when the device sent it is acted on long after it stopped being
true. Nothing is reported as wrong: the link is healthy, the counters are clean
for the checksum, and a restart makes it good again for a while before it
degrades.

## Cause

```cpp
if (link.poll(now)) act(link.message());     // one message, once a tick
```

That is correct if the device sends no faster than the loop runs. If it sends
faster, every call leaves messages behind. The queue grows to the size of the
driver's buffer and stays there, and a full buffer keeps what it already holds and
**drops what arrives**, so the data at the head of the queue is the oldest there
is.

The age is the queue ahead of you divided by the rate you drain it. Measured, a
500 Hz device, a 100 Hz loop and a 4096 byte buffer, twenty seconds:

| policy | acted on | mean age | worst age | bytes lost |
|---|---|---|---|---|
| one message per tick | 2000 | 2472 ms | 3741 ms | 76058 |
| every message, 3 ms each, 3 a tick | 5999 | 962 ms | 1245 ms | 27692 |
| drain, act on the newest | 2000 | 1 ms | 1 ms | 0 |

The worst age is predictable: 4096 bytes is 372 frames, and 372 frames at 100 a
second is 3.72 seconds. At 300 a second it is 1.24 seconds.

## Fix

Drain what is waiting and act on the newest:

```cpp
const Drained d = drain_latest(link, now, newest, 1000);
if (d.got) act(newest, d.size);
```

Acting on every message is not the cure when acting takes time. The loop handled
300 a second against 500 sent, so it fell behind more slowly and still fell behind.
