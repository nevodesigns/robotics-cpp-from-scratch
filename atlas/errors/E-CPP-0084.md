## Symptom

The tool prints "invalid input" and stops. The person types the numbers again, in case, and gets the same message. They cannot tell which of three numbers is wrong or why.

## Cause

The code knew which value was wrong and what was wrong with it, and discarded both. Each of four situations needs different advice: a word instead of a number, a number with something stuck to it, a number outside the range and nothing at all.

The messages from the suite: `right speed: not a number (allowed 0 to 2)`, `right speed: out of range (allowed 0 to 2)`, `duration: no input (allowed 0.1 to 60)`.

## Fix

Name the value, give the problem the checker found, and say what would have been accepted:

```cpp
err << names[i] << ": " << asked.entry.problem << " (allowed " << low[i] << " to " << high[i] << ")\n";
```
