title: A handle closed twice, or never, after it was handed on
match: moving a handle moves the duty to close it, and it is closed exactly once

platforms: linux, windows

## Symptom

A handle is passed to another part of the program, and it is closed by both. The library reports a bad handle, or the second close frees memory that something else has since been given.

## Cause

A copied raw pointer has two owners and each thinks it must close. A `unique_ptr` cannot be copied, only moved, so there is always exactly one.

Measured with two devices, one handed over with `std::move` and one replaced by an assignment: opened **2**, closed **2**, bad closes **0**. The assignment closed the device that was being overwritten, and the one moved from was empty afterwards.

## Fix

Pass ownership with `std::move` and leave the old name empty; pass a plain pointer, `d.get()`, to code that only uses the device:

```cpp
DevicePtr b = std::move(a);          // a is now empty
double v = device_read(b.get());     // the function borrows it
```
