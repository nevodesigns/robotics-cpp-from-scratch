id: E-MEM-0015
title: New memory that looked zeroed
match: it was zero when I tested it
platforms: linux, windows
teaches: 02-09-the-value-that-was-never-written
---

## Symptom

A buffer from `new` is read before anything writes it, and it is full of
zeros. The code is written as though that is a guarantee, because it was true
every time it was tried.

Later, the same code reads something else out of the same allocation. Usually
after the program has been running for a while, or after an unrelated feature
started allocating, or on a second run inside the same process where the first
run has already used the heap.

## Cause

A fresh page from the operating system is zero, because the kernel must not
hand one process another process's data. That is a property of the page, not of
`new`, and it holds only while the page is genuinely new.

Once your own process has used and released memory, the allocator reuses it,
and what you get back is your own old data plus whatever bookkeeping the
allocator keeps inside free blocks.

Measured in lesson 02-09, asking for 32 bytes, writing `0x7e` into all of
them, freeing, and asking for 32 bytes again:

| | |
| --- | --- |
| bytes still `0x7e` in the second block | **16 of 32** |
| what replaced the other 16 | the allocator's own free list bookkeeping, different every run |

The first 16 bytes differed between runs because the allocator stores a
mangled pointer there. The other 16 came back exactly as they had been left.

The more instructive number is the first one. In a program whose very first
act is that allocation, all 32 bytes read as zero. Inside the lesson's test
suite, which has already allocated, only **27 of 32** did. Nothing is the first
allocation for long, which is why a zeroed buffer during testing says nothing
at all about the next one.

## Fix

Ask for the zeros, or do not depend on them.

```cpp
int* a = new int[4];        // four indeterminate ints
int* b = new int[4]();      // four zeros, guaranteed
std::vector<int> c(4);      // four zeros, guaranteed, and it frees itself
```

The parentheses are the whole difference, and `std::vector` is the right answer
in this curriculum for the reason lesson 02-02 gave: it also cannot leak.

For a struct, `= {}` value initialises every member, and default member
initialisers in the type itself are better still, because then there is no form
of the declaration that leaves it unwritten.

If a buffer is genuinely filled by something else later, such as a device read
or a frame decode, poison it first and then check (`E-MEM-0016`). Do not test
it by reading it once and seeing zeros.
