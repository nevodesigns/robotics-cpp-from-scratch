## Symptom

A header-only library builds perfectly in the file that was used to test it, and
the link fails the moment a second file includes it. The message names a symbol
you wrote and says it is defined more than once.

Adding the header to one more file breaks a build that was fine.

## Cause

A header is text, copied into every file that includes it. A function or a
variable **defined** there is defined once per file, and the linker's rule is
that one entity may have one definition in the program.

```cpp
// in a header
int wheel_speed() { return 1; }     // a definition
double wheel_base = 0.35;           // a definition
```

With one includer this links. With two it does not, and the second file did
nothing wrong.

The compiler never sees the problem, because each file on its own is correct.
Only the linker, which sees them all, can object.

## Fix

Say which of the three you meant.

**`inline`** for something there should be one of, shared:

```cpp
inline int wheel_speed() { return 1; }
inline double wheel_base = 0.35;      // C++17
```

**A declaration in the header and a definition in one `.cpp`**, for anything
large or anything whose definition you do not want every includer to depend on:

```cpp
// header
int wheel_speed();
// one .cpp
int wheel_speed() { return 1; }
```

**`static`** only where each file genuinely should have its own, which is almost
never and is `E-LNK-0003`.

Three notes.

**A class member function defined inside the class is already inline**, which is
why header-only classes work without anybody writing the keyword.

**`constexpr` variables at namespace scope are implicitly inline** in C++17, so
they are safe in a header. `const` at namespace scope has internal linkage,
which makes it the `static` case with all of that case's problems.

**Templates are exempt** from the one-definition rule in the way that matters:
the linker discards the duplicates. That is why template-heavy header libraries
do not hit this, and why the first non-template function added to one does.

The build gate that catches this before anybody else meets it is to compile each
header twice, in two translation units, and link them. That is what librc's
`rc_headers_standalone` target does, and it exists because a header in this
repository once needed it.
