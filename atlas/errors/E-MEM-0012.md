id: E-MEM-0012
title: A live pointer to the wrong element, after an erase
match: erase leaves the buffer alone and changes what each address holds
platforms: linux, windows
teaches: 02-07-the-pointer-that-was-right-yesterday
---

## Symptom

A reading is wrong. Not missing, not garbage, not a crash: a plausible value
from the same sensor, one position out. A fault is attributed to the wrong
motor, a waypoint to the wrong leg of a route.

No sanitizer reports anything. The address sanitizer is clean. Valgrind is
clean. The pointer is valid and the memory is live.

## Cause

`erase` does not reallocate. It shifts every element after the erased one down
by one and shortens the vector, in the same buffer.

So a pointer saved into that buffer is still pointing at live memory inside the
container, and it is pointing at a different element than it was.

Measured on five readings, with room reserved so nothing could reallocate:

| | index 2 holds | buffer |
|---|---|---|
| before erasing index 1 | 30 | the original |
| after erasing index 1 | **40** | the same, unchanged |

Nothing was freed. There is no use after free, because there was no free. Every
tool that finds `E-MEM-0011` finds nothing here, and the program continues with
a number that looks entirely reasonable.

This is the worst of the three invalidation failures and the only one with no
diagnostic at all.

An index is no protection either. An index into a vector is exactly as
invalidated by an erase as a pointer is, and for the same reason.

## Fix

**Do not keep a reference to an element across a modification of the
container.** Not a pointer, not an iterator, not an index. Take it, use it,
drop it.

**Find it again by identity, not by position.** If a fault belongs to motor
seven, store the motor number and look it up, rather than storing where motor
seven happened to be in the list this cycle.

**Remove by moving to the end instead of shifting**, when order does not
matter. `std::swap` with the last element and `pop_back` touches two positions
instead of shifting everything, so the damage is bounded and local, and it is
much cheaper.

**Collect the removals and apply them once.** A loop that erases while
iterating is this bug with extra steps. `std::remove_if` followed by a single
`erase` does the whole pass with one shift.

**Rebuild rather than patch, for small containers.** Constructing a new vector
of the elements you want to keep is clearer than any in place removal and the
cost is a copy of something small. Reach for it first and measure before
replacing it.
