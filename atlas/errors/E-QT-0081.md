## Symptom

Part of an interface shows the value that was set and part shows the default it started with, and the parts are not the ones you would guess.

## Cause

`create()` evaluates bindings and runs `Component.onCompleted` before it returns. A property set after that is a change to a running object. Measured: with a limit of 5 set afterwards, `onCompleted` saw **1** and a binding on it gave **10**; as an initial property `onCompleted` saw **5**.

## Fix

Create in two steps with the values set between them:

```cpp
QObject* object = component.beginCreate(context);
component.setInitialProperties(object, initial);
component.completeCreate();
```
