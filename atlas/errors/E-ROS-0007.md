platforms: linux, windows

## Symptom

A robot comes up on one machine and not on another, or one time in ten, depending on which node happened to start first.

## Cause

The start order is computed from what each node needs, with ties broken by the listing so that it depends on nothing else: driver filter planner controller logger viewer from a list in no useful order. A repeated name, a need that is not listed and a circle of needs were each refused with their reason and no order.

## Fix

Compute the order, and refuse a list that has none.

```cpp
std::string error;
const auto order = start_order(specs, error);
```
