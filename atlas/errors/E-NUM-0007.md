## Symptom

The program stops dead. On Linux the shell reports a floating point exception,
which is confusing because the values involved were whole numbers. Inside this
curriculum's test runner you instead get a line saying the test crashed with an
arithmetic fault, and the remaining tests still run.

## Cause

Dividing a whole number by zero is undefined behaviour, not an error you can
catch. On x86 the processor raises a hardware fault, which the operating system
turns into a signal, and by default that ends the process.

Note that fractional division behaves differently: 1.0 divided by 0.0 produces
infinity rather than crashing, which is its own quiet problem because the
infinity then spreads through every later calculation.

## Fix

Check the divisor before dividing, and decide deliberately what a zero divisor
should mean for the caller. Returning zero, returning an error through
rc::expected, or refusing the input are all defensible. Crashing is not.

```cpp
if (whole == 0) return 0;
return (part * 100) / whole;
```

Any divisor that comes from a sensor, a configuration file, or a caller counts
as untrusted and needs the guard.
