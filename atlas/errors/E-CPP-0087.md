id: E-CPP-0087
title: Cleanup written after the call that throws
match: on the way out of a throw, destructors run in reverse order, before the handler
match: expected log()
platforms: linux, windows
teaches: 03-12-what-a-throw-does-on-the-way-out
---

## Symptom

A function acquires something, calls a function that can throw, and releases it on the next line. When the call throws, the release never runs, and the program leaks, or leaves a motor enabled, or a lock held.

## Cause

A throw leaves the function at once. Lines after the throwing call do not run. What does run, on the way out, is the destructor of every object that was alive in each scope being left.

Measured: three guards A, B and C made in order and a throw after them gave the log make A, make B, make C, **drop C, drop B, drop A**, handler. The destructors ran in reverse order and before the handler began.

## Fix

Put the cleanup in a destructor (lesson 02-03), so the unwinding does it:

```cpp
Guard a("A");     // released on every way out, a throw included
parse_positive(text);
```
