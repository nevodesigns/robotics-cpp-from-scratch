title: Dereferencing a pointer that is null

## Symptom

The program dies the moment a search finds nothing, or the moment an optional
piece of hardware is absent. On Linux the shell reports a segmentation fault. A
sanitizer reports SEGV on address zero.

## Cause

A function answered nullptr, meaning there is no such thing, and the caller used
the answer without asking whether there was one. Address zero is deliberately
never valid, so the hardware faults rather than silently reading nonsense.

Address zero specifically is good news. It means the pointer was honestly null
rather than pointing at recycled memory, which is the far harder bug in
E-MEM-0001.

## Fix

Check before dereferencing:

```cpp
const Reading* found = find_first_above(readings, count, limit);
if (found == nullptr) return;
use(found->celsius);
```

If a value is genuinely optional rather than a location, prefer std::optional,
which cannot be dereferenced without the compiler reminding you it might be
empty. If the thing should never be absent, take a reference instead of a
pointer, so absence cannot be expressed at all.
