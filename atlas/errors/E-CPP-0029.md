id: E-CPP-0029
title: A negative sentinel that stops being negative in a comparison
match: a negative number compared against a size is not negative any more
platforms: linux, windows
teaches: 01-07-the-loop-that-never-ends
---

## Symptom

A function returns -1 to mean "not found", and the check for it never fires.

```cpp
int found = index_of(readings, target);   // -1 when absent
if (found < readings.size()) { use(readings[found]); }
```

The branch is taken when nothing was found, and the index used is -1.

## Cause

The comparison has an `int` on one side and a `std::size_t` on the other, so one
of them is converted, and it is not the one you would guess. The signed value
goes to unsigned, and -1 becomes the largest number a `std::size_t` can hold.

| | value |
|---|---|
| `(std::size_t)(-1)` | 18446744073709551615 |
| `(std::size_t)(-1) < 3` | false |
| `-1 < ssize(3)` | true |

So the answer flips. Read as numbers, -1 is smaller than any size. Read the way
the language evaluates it, it is larger than all of them.

Every compiler this curriculum claims warns about this one, through
`-Wsign-compare` on gcc and clang and C4018 on MSVC. It reaches production
anyway, because it is one warning among the hundreds a codebase without
`-Werror` prints.

And the warning is less reliable than it looks. Write the sentinel as
`const int missing = -1` rather than `int missing = -1` and clang folds it to a
known value and says nothing at all, while gcc still refuses. Adding `const` to
a variable removed the diagnostic on one of the two compilers.

## Fix

**Make both sides signed.**

```cpp
if (found >= 0 && found < rc::core::ssize(readings.size()))
```

Or use `rc::core::is_valid_index(found, readings.size())`, which checks both
ends in one call and is harder to get half right.

**Check the sentinel first, on its own.** `if (found < 0) return;` is one
comparison between two signed values and cannot be misread by anyone, including
the compiler.

**Prefer a type that cannot hold a sentinel.** An index that might not exist is
an optional, and `std::optional<std::size_t>` says so in the signature rather
than in a comment. The caller then cannot forget, because there is nothing to
compare until they have unwrapped it.

**Do not silence the warning with a cast.** `(std::size_t)found < size()` makes
the message go away and keeps the bug exactly as it was.
