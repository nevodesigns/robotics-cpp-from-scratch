title: An emergency stop that is cleared by letting go of it, or a reset that is a start
match: an emergency stop latches, letting go of it does not clear it, and a reset is refused while the key is held
match: expected reset_while_held
platforms: linux, windows
teaches: 12-08-the-button-that-must-be-held

## Symptom

The stop is pressed, the operator takes a hand off it, and the robot is free to move. Or the reset button restarts the robot as well as clearing the fault.

## Cause

A stop that is the same as the button is a stop that lasts as long as the button. A fault has to latch until a person clears it, and clearing it must not start anything. Measured: stop pressed and let go with the key held left it **latched**; a reset was **refused** while the key was held; after the key was let go the reset worked and the speed was still 0.

## Fix

Latch, and make the reset a separate act that arms nothing:

```cpp
if (pressed) { latched_ = true; armed_ = false; }
bool reset() { if (estop_ || enable_) return false; latched_ = false; return true; }
```
