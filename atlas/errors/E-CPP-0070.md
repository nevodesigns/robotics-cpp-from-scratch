## Symptom

A line compiles for a `std::vector` and fails for an array, or the other way
round, with no `std::` anywhere in it:

```
error: 'distance' was not declared in this scope; did you mean 'std::distance'?   (gcc)
error: use of undeclared identifier 'distance'; did you mean 'std::distance'?     (clang)
```

The compiler is suggesting the fix, and it is right. The mystery is why the same
line worked a minute ago.

## Cause

When the compiler meets a call it also looks in the namespaces of the call's
**arguments**. This is called argument dependent lookup, and it is why
`operator<<` for a `std::string` is found without anyone writing `std::`.

Measured: `distance(v.begin(), v.end())` for a `std::vector<int>` compiled with
no prefix and returned 3, because the iterators belong to `std`. The same line
for an `int` array was refused. The arguments were `int` pointers, which belong to
no namespace, so there was nowhere else to look.

So the unqualified name was never found by name. It was found through the type of
its arguments, which is an accident of which container was in use.

## Fix

Write `std::distance`. It works for both, and for the next container.

```cpp
const auto count = std::distance(readings.begin(), readings.end());
```

Argument dependent lookup is not a bug, and a few names, `swap` above all, are
meant to be called unqualified for it. Until you know which, write the prefix.
It cannot be found by accident and it cannot be lost by changing a type.
