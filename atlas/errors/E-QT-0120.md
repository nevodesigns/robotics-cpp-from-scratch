id: E-QT-0120
title: Things closed in the order that started them
match: things are closed in the reverse of the order they were added, so that each is closed before what it used
match: only what was started is closed: steps added after a failure to start are not in the sequence
platforms: linux, windows
teaches: 12-11-the-station-that-closed-badly
---

## Symptom

On exit the station crashes or logs an error from a thread that outlived the thing it used: a message sent to a closed log, a read on a link that was closed under it.

## Cause

Things started later use things started earlier, and closing the earlier first closes what is in use. Measured: added settings, log, link and monitor, they were closed as **monitor, link, log, settings**, and what had not been started was not closed.

## Fix

Add each closing step as the thing starts, and run them from the last to the first:

```cpp
for (std::size_t i = steps_.size(); i > 0; --i) steps_[i - 1].second();
```
