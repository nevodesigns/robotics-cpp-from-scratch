id: E-CPP-0067
title: A member set twice, or set in an order the list does not say
match: (will be initialized after|Wreorder|member initialization order)
platforms: linux, windows
teaches: 02-11-how-an-object-starts
---

## Symptom

A warning that reads as pedantry:

```
warning: 'Window::first_' will be initialized after 'Window::second_' [-Wreorder]
warning: field 'first_' will be initialized after field 'second_' [-Wreorder-ctor]
```

Or no warning at all, and a constructor that does the work of every member twice:
a `std::string` allocated blank and then allocated again, a vector built empty
and then filled.

## Cause

**Members are built in the order they are declared, not the order they are
listed.** Measured: a class whose list read `second_("second"), first_("first")`
built `first_` before `second_`, in that order, regardless. gcc 11 and clang 14
both warned, and the warning is not pedantry. The list is lying about what
happens, and when one member's initialiser uses another it reads it before it
exists.

**By the time the body runs, every member already exists.** A member left out of
the list is built blank, and an assignment in the body overwrites it. Measured,
two members of a type that counts its own construction:

| | built blank | built as a copy | overwritten |
|---|---|---|---|
| in the list | 0 | 2 | 0 |
| in the body | **2** | 0 | **2** |

Same result, twice the work. For an `int` it costs nothing. For a `std::string`
or `std::vector` it is an allocation made and thrown away, and for a type with no
blank form it does not compile at all.

## Fix

Initialise in the list, and write the list in the order the members are
declared.

```cpp
class Calibration {
 public:
  Calibration(const Tracked& offset, const Tracked& scale)
      : offset_(offset), scale_(scale) {}      // declaration order, no body work
 private:
  Tracked offset_;
  Tracked scale_;
};
```

Treat the warning as the finding it is and reorder the list, or the declaration,
until they agree. Do not switch `-Wreorder` off.
