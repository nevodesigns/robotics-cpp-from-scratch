title: A component that names its middleware
match: a component given a node publishes and subscribes under the names the node resolves, in the node's namespace
match: two nodes of the same component in two namespaces do not hear each other, and in one namespace they do
platforms: linux, windows
teaches: 17-17-the-seam-where-ros-plugs-in

## Symptom

A planner can only be tested on a robot, or in a container with ROS 2, and every change needs the whole stack to be running.

## Cause

A component that is written against an interface, Node, with publishers, subscriptions, timers, a clock and name resolution, runs against any class that implements it. The test component of twelve lines published on /robot1/out and /robot1/doubler/status, was heard in /robot1 as 42 and 8 and not at all in /robot2, and two robots running it did not hear each other.

## Fix

Give components a Node& and put the middleware in one class behind it.

```cpp
class Doubler { public: explicit Doubler(Node& node); };
```
