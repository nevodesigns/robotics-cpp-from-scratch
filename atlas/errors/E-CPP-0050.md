id: E-CPP-0050
title: is_move_constructible trusted to mean there is a move constructor
match: the trait everybody checks says yes to all of them
platforms: linux, windows
teaches: 03-09-declare-nothing-or-everything
---

## Symptom

A static assertion confirms the type is move constructible, and it is copied
anyway. A test checks the trait, passes, and proves nothing. Somebody concludes
the move is happening and looks elsewhere for the cost.

```cpp
static_assert(std::is_move_constructible<Readings>::value);   // always true
```

## Cause

`std::is_move_constructible<T>` asks whether a `T` can be constructed from an
rvalue `T`. A **copy** constructor can do that: binding a `const T&` to an
rvalue is perfectly legal.

So the trait is satisfied by copying, and answers yes for a class with no move
constructor at all.

Measured across three classes, two of which have no move constructor:

| class | `is_move_constructible` | `is_nothrow_move_constructible` |
|---|---|---|
| nothing declared | yes | yes |
| `~X() = default;` declared | **yes** | **no** |
| copy constructor declared | **yes** | **no** |

The left column is useless here. The right one matched the observed behaviour
on every row.

The nothrow trait is the right question for a reason rather than by
coincidence: **it is the condition the standard library itself uses.** A
`std::vector` reallocating has already allocated the new buffer and is part way
through relocating its elements. If a move could throw, it could not put them
back, so it copies instead and keeps the strong exception guarantee.

Which means a class that is move constructible and not *nothrow* move
constructible is copied by every container it is put into, while the trait most
people check reports no problem.

## Fix

**Check `std::is_nothrow_move_constructible`.** It is the one that predicts
behaviour, and it is the one the library branches on.

**Say it in a static_assert, not a test.** A test can only check the types it
happens to name. An assertion at the top of the header fires for whoever adds a
destructor next.

**Write the message as an instruction.** The first line of a failed
static_assert is what gets read, which lesson 03-07 measured, so spend it on
what to do.

**Do not add `noexcept` to make the trait pass.** Marking a move that can throw
as `noexcept` does not make it safe, it makes a throw terminate the program.
Fix the reason it can throw, which for a class holding a `std::vector` is
usually that somebody declared something they did not need to.

**Measure the consequence when you want to be sure.** Counting the allocations
a container growth performs is four lines with `rc::test::AllocationCount` and
turns a trait into a number: measured, 71 against 198 for the same work.
