## Symptom

Compilation fails with a use of deleted function error, naming a copy
constructor or copy assignment, often on a std::unique_ptr or on your own handle
type.

## Cause

This is not a fault. It is the type refusing to do something dangerous. Copying
an owning type would produce two owners of one resource, and both would release
it. The compiler is reporting the mistake at the line that attempts the copy,
which is where the mistake actually is.

## Fix

Decide what you meant.

Transferring ownership, so use std::move:

```cpp
registry.add(std::move(device));
```

Handing ownership back to a caller, so return by value, which moves:

```cpp
return taken;
```

Only looking at it, so take a reference or a non owning raw pointer instead:

```cpp
void inspect(const Device& device);
Device* find(int id);
```

Reaching for std::shared_ptr to make the error go away is almost always the wrong
answer. It replaces a compile time question about ownership with a run time cost
and a possible leak. See lesson 02-06 for when sharing is genuinely correct.
