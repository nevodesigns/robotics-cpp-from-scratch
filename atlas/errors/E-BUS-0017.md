id: E-BUS-0017
title: A topic memory with no bound, or one that repeats
match: what is remembered is bounded by keep however much is published, and a subscriber that was there all along hears nothing twice
platforms: linux, windows
teaches: 17-06-the-subscriber-that-arrived-late
---

## Symptom

A publisher that runs for a week uses more and more memory, or an early subscriber hears everything again each time a new node starts.

## Cause

A memory has to be a fixed size queue, and a replay must go only to the new subscriber. 1000 messages published to a topic that keeps 1 left 1 remembered; the late subscriber heard 1 (the 999th) and the early one heard 1000 once each.

## Fix

Drop the oldest beyond keep and replay to the new handler only.

```cpp
while (t.kept.size() > t.keep) t.kept.pop_front();
```
