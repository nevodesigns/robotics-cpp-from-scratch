id: E-CPP-0099
title: A literal zero where a null pointer was meant
match: a literal zero is an int, and only nullptr is a pointer
match: expected std::string
platforms: linux, windows
teaches: 03-17-which-function-got-called
---

## Symptom

A function overloaded for an integer and a pointer is called with `0` to mean "no pointer", and the integer one runs. Or the call is ambiguous and the build fails somewhere unrelated to the mistake.

## Cause

`0` is an `int` literal that also happens to convert to a null pointer. With both overloads present, an exact match to `int` wins. `NULL` is usually written as an integer too, and is the same trap.

Measured: `which(0)` chose **int** and `which(nullptr)` chose **pointer**.

## Fix

Write `nullptr` when a null pointer is meant. It has its own type, which converts to any pointer and to no integer.
