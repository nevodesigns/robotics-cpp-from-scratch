## Symptom

Comparing a state against a number, or passing one where an int is expected,
fails to compile with a message about no matching operator or an invalid
conversion.

## Cause

This is the type doing its job rather than a fault. An enum class does not
convert to a number implicitly, which is the whole reason to prefer it over a
plain enum: it stops a state being compared against a magic number, added to a
count, or passed to a function that wanted something else entirely.

## Fix

Compare against a named value:

```cpp
if (state == DriveState::Faulted) { ... }
```

Where a number genuinely is needed, at a wire protocol or a hardware register,
convert deliberately and say so:

```cpp
const auto code = static_cast<int>(state);
```

Having to write the cast is the point. The conversion becomes a decision
somebody made rather than something that happened, and it appears at the one
boundary where it belongs rather than throughout the program.
