title: A number that was not a number, and became a plausible one

## Symptom

A sensor drops out and its reading becomes nan. A little later a motor command
or an array index or a count is -2147483648, or a huge negative number, with no
error anywhere. Nothing crashed. The value is simply not the one that was
computed.

## Cause

Casting a `double` to an `int` when the value does not fit is **undefined
behaviour**, and it gives an answer anyway.

Measured, once, outside any test, on gcc 11 and clang 14 at `-O0` and `-O2`,
the raw cast of each of these gave the same result:

| value | `static_cast<int>` gave |
|---|---|
| 1e10 | -2147483648 |
| -1e10 | -2147483648 |
| nan | **-2147483648** |
| inf | -2147483648 |
| 2147483648.0 | -2147483648 |

So not a number, infinity, and a number one too large are all the **most
negative int**, which is also a real reading a real sensor could produce. There
is nothing to compare it with afterwards.

The sanitizers disagree about it. Measured: gcc's `-fsanitize=undefined`
reported nothing, and clang's reported it as `is outside the range of
representable values of type 'int'`. The separate `-fsanitize=float-cast-overflow`
reported it on both. A sanitizer lane that is gcc alone will not see this
unless it is asked for by name.

Neither compiler says anything about `double` to `int` under `-Wall -Wextra`.
`-Wconversion` does, and is noisy; lesson 04-08 is about deciding whether to
believe it.

## Fix

Ask whether it fits before converting, and make the answer something the
caller has to look at.

```cpp
#include <rc/core/narrow.hpp>

const auto steps = rc::core::round_to_int(requested);
if (!steps.ok) { /* nan, infinite, or too large: say so and stop */ }
use(steps.value);
```

`ok` is separate from `value` because no `int` can stand for "it did not fit":
every one of them is a reading some sensor could legitimately produce.

NaN needs no special case in the check. It fails both comparisons against the
limits, so it is refused for the same reason as everything else that is not a
number an `int` can hold.
