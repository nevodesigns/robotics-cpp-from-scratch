title: Mistaking a unit for a meaning

## Symptom

A unit system is in place, everything compiles, and the robot still does
something absurd. A value from one frame is used in another. A quantity that
should have been wrapped is not. Two lengths that have nothing to do with each
other are added together and the compiler is perfectly happy.

The conclusion drawn is often that the unit types were not worth the trouble.

## Cause

A unit type checks that two quantities are of the same **kind**. It does not
check that they are of the same **thing**.

```cpp
const Metres height = metres(1.8);
const Metres wavelength = metres(0.0000005);
const Metres meaningless = height + wavelength;   // compiles, and it should
```

Both are lengths in metres. There is nothing wrong with the arithmetic and
nothing a unit system could reasonably object to.

The same applies to everything that is not a unit:

- **Frames.** A position in the world frame and one in the robot's are both
  metres, and adding them is the mistake `E-KIN-0003` is about.
- **Ranges.** `degrees(370.0)` is a perfectly good `Radians`. Nothing here wraps
  it, and nothing should: wrapping is a decision about the quantity's meaning.
- **Sign conventions.** Clockwise positive and anticlockwise positive are the
  same type.
- **Sensibleness.** A distance of a light year is a `Metres`.

## Fix

Be precise about what the type bought, so that the rest is still looked for.

**It removes one class of mistake completely.** Metres and millimetres, radians
and degrees, seconds and milliseconds: those can no longer be confused, at zero
runtime cost, and they were a large share of the numeric faults in this
curriculum's atlas.

**Everything else still needs the ordinary tools.** A frame belongs in the name
or in a separate tag, a range belongs in a wrapping function called at the
boundary, a sign convention belongs written down beside the axis definition, and
sensibleness belongs in a range check.

**More tags are cheap.** If a frame confusion is a real risk in a particular
program, `Quantity<WorldMetreTag>` and `Quantity<BodyMetreTag>` are two more
empty structs and one conversion function that has to be called, which is
exactly the shape of the fix that worked for units.

The general form is worth keeping: **a type can only enforce a distinction you
actually made in the type**. Deciding which distinctions are worth making is
design, and it is the part the compiler cannot do.
