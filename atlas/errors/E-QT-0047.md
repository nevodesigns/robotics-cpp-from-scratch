id: E-QT-0047
title: A carriage return left on the end of every line
match: a carriage return before the newline is removed, an empty line is a line, and a carriage return inside a line stays
match: expected lines.size() to equal 5
platforms: linux, windows
teaches: 09-12-the-line-that-arrived-in-two
---

## Symptom

A command from one machine is not recognised on another: `"stop"` is compared with `"stop\r"` and does not match. A number parses on the bench and not from a file written on Windows, and the log shows nothing wrong because the carriage return does not print.

## Cause

A line written as `\r\n` that is split at `\n` alone ends in `\r`. The first line of `a\r\nb` is **2** bytes, not 1. And not every `\r` is a line ending: one inside a line is data.

Measured: `a\r\nb\n\r\nc\rd\n\n` gave **5** lines: `a`, `b`, an empty line, `c\rd` and an empty line.

## Fix

Remove one `\r` immediately before the `\n`, and nowhere else:

```cpp
if (line_.endsWith('\r')) line_.chop(1);
```
