## Symptom

A test that injects faults passes, then fails, then passes, with nothing changed.
Or it passes on one compiler and fails on another with the same seed. The
failure cannot be reproduced on request, so nobody can fix it, and the test is
eventually disabled.

## Cause

The random source was not reproducible. Two common routes to this.

**The seed came from the clock or `std::random_device`.** The faults are then
different every run by design, which is exactly wrong for a test: a failure
cannot be replayed.

**The seed was fixed and the sequence still differs across toolchains.** The
standard fixes the *engines* in `<random>`, `mt19937` gives the same numbers
everywhere, but it does **not** fix the *distributions*. `uniform_real_distribution`
and `uniform_int_distribution` are allowed to turn those numbers into values in
different ways, so the same seed gives different faults on gcc, clang and MSVC.

A third trap is smaller. A xorshift generator started at zero stays at zero for
ever, so a seed of zero drops or flips nothing and the test passes for the wrong
reason.

## Fix

Fix the seed, own the generator, and compare integers.

```cpp
std::uint32_t next() {
  state_ ^= state_ << 13;
  state_ ^= state_ >> 17;
  state_ ^= state_ << 5;
  return state_;
}

bool chance(std::uint32_t per_million) {
  return next() % 1000000u < per_million;
}
```

Express the rate in parts per million, so the decision is an integer comparison
and not a floating point one. Replace a seed of zero with any other value. Then
a number measured on one machine holds on the others, and a failing test can be
run again.
