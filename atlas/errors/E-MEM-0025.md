id: E-MEM-0025
title: A message given back twice, or one that was never lent
match: a release that was never an acquire is refused, and a double release does not lend a slot twice
match: expected distinct_count to equal
platforms: linux, windows
teaches: 02-14-a-loop-that-never-allocates
---

## Symptom

After a fault the pool lends the same message to two users, and the two corrupt each other. The fault was a second `release` of a message that had already been returned.

## Cause

A release that trusts its argument pushes the slot onto the stack of free ones every time. Released twice, the slot is on the stack twice and is lent twice. The same happens with an address that was never lent: one outside the pool, or one
that points into the middle of a slot.

Measured: `nullptr`, a stranger on the stack and an address one byte into a slot were all refused; a second release of a returned message was refused; and after that, 64 lends still gave **64 different** messages and the 65th was refused.

## Fix

Check four things before taking a message back: it is not null, it is inside the pool, it points at the start of a slot, and the slot is out.

```cpp
if (!taken_[index]) return false;
taken_[index] = false;
free_[free_count_++] = index;
```
