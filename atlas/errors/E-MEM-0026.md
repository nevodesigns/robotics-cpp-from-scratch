id: E-MEM-0026
title: A vector that copies every element when it grows
match: growing a vector moves its packets when the move is noexcept, and copies them when it is not
match: expected with_promise.copies to equal
platforms: linux, windows
teaches: 02-15-how-many-copies
---

## Symptom

A program that stores a few thousand objects is much slower than the arithmetic says it should be, and every object that owns something allocates and frees far more often than the code does. Nothing is wrong
with the output.

## Cause

A vector that runs out of room allocates a bigger block and carries its elements across. It moves them only if the move constructor is declared `noexcept`: a move that might throw half way would leave elements in two places, and
the vector cannot undo that, so it copies instead. A type with a move constructor that lacks the word silently loses it for this purpose.

Measured on libstdc++, a hundred push_backs with no reserve: **0** copies and 227 moves when the move was `noexcept`, and **127** copies and 100 moves when it was not.

## Fix

```cpp
Packet(Packet&& other) noexcept : id_(other.id_) { ... }
Packet& operator=(Packet&& other) noexcept { ... }
```

A test with `std::is_nothrow_move_constructible<T>::value` catches it for any type.
