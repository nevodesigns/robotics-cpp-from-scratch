title: A wait with no limit
match: waiting for a component that is ready already, or has no source, returns at once
match: the wait is bounded by its timeout, and a component that is still loading when it ends is a timeout
platforms: linux, windows
teaches: 11-07-the-component-not-ready-yet

## Symptom

A test run hangs on a machine where a file is slow to arrive, and the CI job is killed by its own time limit without saying which test.

## Cause

A wait with no timer has no end if the status never changes. And a wait that starts the loop without looking at the status first waits for a change that already happened. Measured: Ready and Null components returned in **0** ms, a wait of 0 on a Loading component was a **Timeout** after 0 ms, and a wait of 5 seconds then got it to Ready.

## Fix

Look first, then wait with a timer:

```cpp
if (component.status() != QQmlComponent::Loading) return result_now();
timer.start(timeout_ms);
loop.exec();
```
