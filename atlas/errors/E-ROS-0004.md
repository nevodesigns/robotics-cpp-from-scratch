id: E-ROS-0004
title: A start up step run from the wrong state
match: a node goes from unconfigured to inactive to active, and back down again, one step at a time
match: a transition asked for from the wrong state is refused and its callback is not run
platforms: linux, windows
teaches: 17-18-a-node-with-a-life-cycle
---

## Symptom

A driver tries to start a device that was never opened, or releases one twice, because something activated or cleaned it up out of order.

## Cause

Each transition can only start from certain states. The way up and down was inactive, active, inactive, unconfigured, finalized. Six requests out of order were all refused with no callback run, and only the two legal ones, configure and activate, ran.

## Fix

Check the state before running the callback.

```cpp
if (!allowed(t, target)) { r.legal = false; return r; }
```
