title: A generator seeded with zero
match: a seed of zero does not leave the generator stuck at zero
match: expected this to be true: first != 0u
platforms: linux, windows

## Symptom

A simulated sensor reports exactly the same value every time, or a random test that is supposed to explore inputs tries one input a million times. It happens only for a seed of zero, which is
what a program that did not set one often has.

## Cause

xorshift is shifts and xors of its own state. Zero shifted and xored with itself is zero, for ever. The generator is not broken for any other seed.

## Fix

Replace a zero seed with a fixed non-zero one when the generator is made:

```cpp
explicit Rng(unsigned int seed) : state_(seed != 0 ? seed : 0x9E3779B9u) {}
```

With that, seed 0 gave 1359758873 and then 3761132862, as any other seed would.
