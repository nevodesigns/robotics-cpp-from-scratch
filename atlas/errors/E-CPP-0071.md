## Symptom

A function marked `static` inside a class stops compiling when it touches one of
the class's own members:

```
error: invalid use of member 'Wheel::radius_' in static member function    (gcc)
error: invalid use of member 'radius_' in static member function           (clang)
error C2597: illegal reference to non-static member 'Wheel::radius_'       (MSVC)
```

The member is plainly there, in the same class, one screen up.

## Cause

A `static` member function belongs to the class and not to any object of it. It
can be called with no object at all, `Wheel::count()`, and that is its whole
use. So it has no `this`, and a member such as `radius_` is part of an object:
which object's radius?

Measured: the refusal is the same on every compiler, which
`checks/a_static_function_with_no_object.cpp` proves.

The reverse works. An ordinary member function may use a static member, because
the class-wide counter exists whichever object is asking.

## Fix

Decide which kind of thing the function is.

If it needs one object's data, it is not static. Remove the word and call it on an
object:

```cpp
double diameter() const { return radius_ * 2.0; }
```

If it is about the class as a whole, such as how many exist, keep `static` and
read only static members:

```cpp
static int count() { return live_; }
```

If it needs both, pass the object in:

```cpp
static double larger_radius(const Wheel& a, const Wheel& b);
```
