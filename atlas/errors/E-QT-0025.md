title: A range-for that copies its container
match: a loop that only reads copies the bytes for every frame it is given, unless it looks through const
match: expected copied_by_nonconst
platforms: linux, windows
teaches: 09-05-a-copy-that-was-not-a-copy

## Symptom

A handler that loops over the bytes of each incoming frame is much slower than its work says, and its time grows with the size of the frames. Making the parameter `const QByteArray&` fixes it, but a copy of the array local to the function does not.

## Cause

A range-for calls `begin()` and `end()`. On an array that is not const those are the versions that can write, so the first call detaches: a whole copy of the bytes, made once for each frame, to read them.

Measured: 1000 frames of 4096 bytes, each a copy of one shared array, read by a range-for. **1000** of them were copied through a non-const array, and **0** through `std::as_const`, which gives the loop a const view.

## Fix

```cpp
for (char c : std::as_const(frame)) total += static_cast<unsigned char>(c);
```
