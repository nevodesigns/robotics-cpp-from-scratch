id: E-IO-0041
title: A mistake retried for ever, as if it were patience
match: a mistake in the program is reported once and not retried for ever
match: a device that is refused permission is tried a few times and then called a setting
match: expected port.attempts.* to equal
platforms: linux, windows
teaches: 08-13-the-cable-comes-out
---

## Symptom

The robot never connects, and nothing says why. The program is running, the loop is
running, the log says it is trying. It has been trying since the build, and a person
watching sees only a program that is slow to start.

## Cause

A reconnect loop that treats every failure as "the device is not there yet". Some
failures are not about the cable:

| status | what it usually is | retry? |
|---|---|---|
| not found | the cable is out | yes, with a backoff |
| busy | something else holds the port | yes, it may let go |
| permission denied | the user is not in the group that owns the port | a few times, then no |
| fatal | a baud rate that does not exist, a path that is not a terminal | never |

A baud rate with no constant will fail every time for ever. Retrying hides a
mistake in the program behind a loop that looks like patience, and the log fills with
the same line.

Permission is the awkward one, because it has two causes that look the same. For a
moment after a device appears, the system has not yet set its permissions, and a retry
a moment later works. A user who is not in the group fails every time. A device
refused five times in a row is the second kind.

## Fix

Say which failures are worth retrying, and stop for the rest:

```cpp
if (status == OpenStatus::Fatal) { state_ = LinkState::Failed; return; }
if (status == OpenStatus::PermissionDenied &&
    ++permission_failures_ >= options_.permission_attempts) {
  state_ = LinkState::Failed;
  return;
}
```

A `Failed` state is information. `last_status()` says why, and the caller can print
the one sentence a person needs: add yourself to the group, or fix the baud rate.
