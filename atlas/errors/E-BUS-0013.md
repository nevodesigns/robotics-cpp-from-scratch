id: E-BUS-0013
title: A receiver that trusts the order things arrive in
match: a receiver hands messages up in order, once each, however they arrive, and acknowledges the next one it needs
platforms: linux, windows
teaches: 17-05-reliable-or-fast
---

## Symptom

A command is carried out twice, or a later command is carried out before an earlier one, after the link had a bad second.

## Cause

Retransmission makes duplicates, and a lossy link reorders. A receiver that delivers on arrival acts on a repeat twice and on number 2 before number 1. Arrivals 2, 0, 1, 1, 0 were delivered a b c, once each and in order, with 2 duplicates counted and the acknowledgements 0 1 3 3 3.

## Fix

Deliver only the number expected, keep early ones, and acknowledge repeats.

```cpp
if (packet.seq < expected_) { ++duplicates_; return expected_; }
```
