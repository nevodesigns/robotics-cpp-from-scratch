id: E-BUS-0032
title: An absolute name inside a node
match: a relative name is put in the node's namespace, an absolute one is not, and a private one goes inside the node's own
match: two robots running the same node with relative names do not collide, and with absolute names they do
match: a namespace means the same however it was written
platforms: linux, windows
teaches: 17-11-what-a-name-means
---

## Symptom

Two robots on one network each plan from both robots' scans, or one robot's command moves the other.

## Cause

An absolute name is itself whatever namespace the node is in. A node that publishes to /scan on two robots puts both on one topic, where one that publishes scan gets /robot1/scan and /robot2/scan. A namespace written robot1/, /robot1 or /robot1/ is the same one, and the root adds nothing, so scan in it is /scan.

## Fix

Write relative names in a node and run each robot in its namespace.

```cpp
resolve_name("scan", "/robot1", "lidar_driver");   // /robot1/scan
```
