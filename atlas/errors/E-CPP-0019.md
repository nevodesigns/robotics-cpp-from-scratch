## Symptom

std::sort crashes with a heap buffer overflow, and every frame in the report is
inside the standard library. It happens only with certain data, usually data
containing duplicates, which makes it look intermittent.

## Cause

std::sort requires a comparator that answers strictly less than, and in
particular reports false when handed the same element twice. A comparator
written with <= reports an element as coming before itself.

The partition step relies on that being impossible: it walks forward until it
finds an element that is not before the pivot, and with a broken comparator no
such element exists, so it walks past the end of the range.

## Fix

Use < rather than <=, and never write a comparator that can return true for two
equal elements:

```cpp
bool earlier(const Reading& a, const Reading& b) { return a.at_ms < b.at_ms; }
```

For a comparator over several fields, compare the first, and only fall through to
the next when the first is equal. std::tie expresses that correctly in one line:

```cpp
return std::tie(a.at_ms, a.celsius) < std::tie(b.at_ms, b.celsius);
```

A quick check that catches almost every broken comparator: it must be false when
both arguments are the same object.
