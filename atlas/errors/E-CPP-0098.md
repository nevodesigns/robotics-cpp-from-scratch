title: A default argument on a virtual function
match: a default argument on a virtual function comes from the reference's type, not the object's
match: expected as_base.send
platforms: linux, windows
teaches: 03-17-which-function-got-called

## Symptom

A derived class gives a different default than its base, and the derived function runs, but with the base's default. Called on the derived object itself it behaves as written; called through a base reference it does not.

## Cause

Which function runs is decided when the program runs, from the type of the object. Which default argument is filled in is decided when it is compiled, from the type of the reference or pointer in the call. The two can disagree, and the function that runs gets the other class's number.

Measured: a quiet sink with a default of 0 retries gave **0** when called on itself and **3** through a reference to the base.

## Fix

Do not put a default argument on a virtual function. Make the default a virtual function of its own and let a non-virtual function fill it in:

```cpp
std::string send(const std::string& text) const { return send_with(text, default_retries()); }
virtual int default_retries() const { return 3; }       // Quiet overrides it to return 0
```
