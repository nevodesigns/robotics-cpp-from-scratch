id: E-CAP-0026
title: A gate of the safety tests only
match: a candidate that is safe and never gives up on a ghost in the doorway fails on a scenario that is for no hazard, and the gate is still red
match: a configuration is written as text one setting to a line, and a different configuration is a different release
platforms: linux, windows
teaches: 21-09-a-gate-before-the-robot
---

## Symptom

A release that is safe and useless, a robot that waits for ever at a door, goes out because no hazard was behind the scenario that caught it.

## Cause

A candidate that never forgets failed S3 only, with no failing hazard, and the gate refused it. A different configuration was a different manifest, since the policy is a file of the release.

## Fix

Gate on the whole suite, not on the hazards alone.

```cpp
g.passed = suite_green(rows, coverage);
```
