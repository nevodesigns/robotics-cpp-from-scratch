id: E-CPP-0038
title: An out parameter used to avoid a copy that never happened
match: returning a container hands the buffer over rather than rebuilding it
platforms: linux, windows
teaches: 01-11-what-the-call-costs
---

## Symptom

Functions throughout a codebase return nothing and write their results through
a reference parameter.

```cpp
void compute_path(const Map& map, std::vector<Pose>& out);
```

The result cannot be `const`, has to be declared on a line of its own before
the call, is empty for as long as it takes to get there, and might be partially
filled if the function gives up halfway. Everyone agrees it is ugly and
believes it is necessary.

## Cause

The belief that returning a container copies it. It does not.

Measured by recording where a local vector's buffer lives inside the function
and comparing it against what the caller receives, for 1024 doubles: **the same
buffer arrives.** Whether the compiler elided the local entirely or moved it,
the buffer was handed over rather than rebuilt. This holds at `-O0` as well as
`-O2`, so it is not an optimisation to hope for.

The out parameter version computes exactly the same thing. What it costs is not
performance:

- the result cannot be `const`
- it needs a declaration on a separate line, before you know whether the call
  will succeed
- a function whose answer is not its return value cannot be used in an
  expression
- a half filled output after an early return is a state the caller has to think
  about

## Fix

**Return the thing.**

```cpp
std::vector<Pose> compute_path(const Map& map);
```

The buffer travels out. The caller can write `const auto path = compute_path(map);`
and have a result that is complete or not there at all.

**Return a named local, plainly.** `return local;` is the form that lets the
compiler elide it. Do not write `return std::move(local);`, which is
unnecessary and can prevent the elision it was meant to help.

**Never return a reference to a local.** That is the other thing people reach
for, and the local is destroyed as the function returns, so the reference refers
to freed memory. Both compilers refuse it once warnings are errors, and this
lesson keeps one in `checks/` so you meet the error on purpose.

**Keep an out parameter when it genuinely earns its place**: filling a buffer
the caller already owns and reuses every cycle, so that no allocation happens in
a control loop at all. That is a real reason, it is about allocation rather than
copying, and it belongs with a comment saying which.
