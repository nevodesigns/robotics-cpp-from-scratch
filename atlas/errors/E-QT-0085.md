id: E-QT-0085
title: A number accepted as a mode
match: QML can assign any number to a property that is meant to hold a mode, and is_valid_mode is what says no
match: expected this to be true: !is_valid_mode
platforms: linux, windows
teaches: 11-09-the-enum-that-was-undefined
---

## Symptom

The robot enters a mode that is not on the list: a state machine falls through every case, or a lookup returns the wrong text, or a switch has no default.

## Cause

An enum in QML is an integer, and a property of an integer type takes any. Measured: assigned `RobotMode.Manual` and then `99`, the property stored **99**, whose name is `unknown`.

## Fix

Ask the meta object in the setter, and refuse what is not a mode:

```cpp
if (!QMetaEnum::fromType<Mode>().valueToKey(value)) return;
```
