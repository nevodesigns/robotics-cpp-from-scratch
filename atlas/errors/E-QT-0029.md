title: A number written with the machine's own locale

platforms: linux, windows

## Symptom

A configuration file written on one laptop is read on another and every setting is wrong by a factor of a thousand, or refused. It works on every machine in the lab except the one set to German.

## Cause

`QLocale()` is the locale of the application, which starts as the machine's. It writes and reads numbers the way a person there does: a comma for the decimal point and a dot for the thousands. A protocol, a file and a configuration must not depend on that.

Measured, with German as the application's locale: `QLocale().toString(1.5)` was **"1,5"**, `QLocale().toDouble("1.500")` was **1500**, and `"1.5"` was refused. With `QLocale::c()`, the plain locale, `format_number(1.5, 1)` was "1.5", `parse_number("1.500")` was 1.5, and nothing changed when the default locale was German.

## Fix

Name the locale in every call that reads or writes a number for a machine:

```cpp
inline double parse_number(const QString& text, bool* ok) { return QLocale::c().toDouble(text, ok); }
inline QString format_number(double value, int decimals) { return QLocale::c().toString(value, 'f', decimals); }
```

Use the application's locale only to show a number to a person.
