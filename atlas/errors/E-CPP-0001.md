## Symptom

```text
solution.hpp:32:26: error: expected ';' before 'if'
   32 |   if (value < 0) return 0
      |                          ^
      |                          ;
```

## Cause

A statement did not end. The compiler kept reading the next line as a
continuation of the unfinished one and stopped at the first token that could not
possibly follow, which is why the message names a token you were not thinking
about.

Where it points is worth knowing precisely, because the usual advice is out of
date. Measured on GCC 11 and Clang 14:

| the mistake | GCC points at | Clang points at |
|---|---|---|
| `return 0` with no semicolon, before `}` | the right line | the right line |
| a struct member with no semicolon | the right line | the right line |
| a struct's closing brace with no semicolon | the right line | the right line |
| `int a = 1` with no semicolon, next line another declaration | **the next line** | the right line |

So three times in four, modern compilers name the line you want and print the
missing character under a caret. The old rule that a semicolon error is always
reported one line late is now true of one case, and only on GCC: when the next
line starts a new declaration, there is nothing wrong until that declaration
begins, and that is where GCC notices.

## Fix

Add the semicolon at the caret. When the caret is at the start of a line that
looks fine, the statement above it did not end.

Two places people forget, both worth checking before reading anything else:

```cpp
struct Pose {
  double x;
  double y;
};          // this one, after the closing brace of a struct or class

int battery_percent(int millivolts);   // and this one, on a declaration
```

If the message names a token from a line further down than seems reasonable,
the unfinished statement is above it, not at it.
