title: A percentage that tops out at 99

## Symptom

A battery, a throttle or a joystick that is fully on reads 99 percent. Nothing
ever reports 100, so a check for "full" is never true and a progress bar never
quite fills.

## Cause

A 10 bit reading takes **1024 values**, 0 to 1023, and the **full scale is
1023**. Dividing by the number of values instead of the size of the range makes
the top land one step short:

```cpp
int percent(int raw) { return raw * 100 / 1024; }      // percent(1023) is 99
```

Measured: `percent(1023)` was **99**, and 767 gave 74 where the exact figure is
74.97. Integer division truncates as well, so the error is always downward.

The comment above it said "0 to 1023 to 0 to 100". The comment was the intent,
and the code was an off-by-one in the divisor.

## Fix

Divide by the span, which is the highest value:

```cpp
inline int percent_exact(int raw) {
  if (raw <= 0) return 0;
  if (raw >= 1023) return 100;
  return raw * 100 / 1023;
}
```

Measured against the old function across the whole range: it differs on **49 of
1024** values, never by more than 1, never decreases, and gives 100 at the top.

Rounding to the nearest percent as well moves 560 of 1024 answers. That is a
second change, and it should be made on its own, deliberately.
