## Symptom

A policy learned for a task behaves well in a state some of the time and badly at other times, with nothing in the state to tell the two apart.

## Cause

The state left out something the outcome depends on: the speed, the load, which way the robot was facing. The decision process then treats different situations as one, and the value and the best action for that state are averages over situations that each need a different action.

In the grid every outcome depends only on the cell and the move, which is what makes a table of values by cell meaningful.

## Fix

List what decides the outcome of an action and put each in the state; if it cannot be measured, estimate it (phase 16) and put the estimate in.

```cpp
// state = (cell) is enough here; on a robot: (position, velocity, heading, load, ...)
```

Too much in the state makes learning slow; too little makes it impossible. The first is the cheaper mistake.
