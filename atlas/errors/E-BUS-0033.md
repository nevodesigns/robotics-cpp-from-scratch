id: E-BUS-0033
title: A remap that applies to the wrong name
match: a remapping redirects a name without changing the node, and applies to the name as it resolves
platforms: linux, windows
teaches: 17-11-what-a-name-means
---

## Symptom

A remap was added and nothing changed, because it was written for the name as typed and the node's namespace made it a different name.

## Cause

A rule is read the same way as any name and applies to the resolved name. Rules scan -> /filtered/scan and ~/status -> /diagnostics/lidar turned /robot1/scan into /filtered/scan and /robot1/lidar/status into /diagnostics/lidar, and left /robot1/pose and the other robot's /robot2/scan alone.

## Fix

Resolve the rule's name the way the node's own would be resolved.

```cpp
if (resolve_name(r.from, ns, node_name) == resolved) return resolve_name(r.to, ns, node_name);
```
