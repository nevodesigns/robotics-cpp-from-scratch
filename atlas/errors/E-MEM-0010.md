## Symptom

A test that should report a clear failure instead produces a segmentation fault,
taking the remaining tests down with it. The learner sees a signal number and no
information about what went wrong.

## Cause

A check whose failure invalidates the following lines was written as a check
rather than a require. The classic shape is a size check followed by an index:

```cpp
RC_CHECK_EQ(events.size(), 1u);   // records a failure and carries on
RC_CHECK_EQ(events[0], 14);       // reads element zero of an empty vector
```

The first line records the problem, execution continues, and the second reads
memory that does not exist.

## Fix

Use the require form whenever a failure makes the next line meaningless or
dangerous:

```cpp
RC_REQUIRE_EQ(events.size(), 1u);
RC_CHECK_EQ(events[0], 14);
```

The require records the same failure and stops that test, so the learner gets a
sentence rather than a stack trace. Sizes before indexing, and pointers before
dereferencing, are the two cases that account for nearly all of these.
