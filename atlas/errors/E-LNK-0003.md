id: E-LNK-0003
title: A header-only global that is one per file
match: a static function in a header is one per file, silently
platforms: linux, windows
teaches: 04-04-one-definition-and-two-copies
---

## Symptom

A counter that undercounts. A registry that is missing entries somebody is
certain were added. A cache that misses things that were definitely put in it.
A "singleton" that is initialised more than once, or that reports different
state depending on which file you ask from.

Nothing fails to build. Nothing warns. Every file is perfectly consistent with
itself, which is what makes it so hard to see.

## Cause

A header is copied into every file that includes it, so anything it defines is
defined that many times. `static` at namespace scope, or on a free function,
says "give this file its own", and the linker is then satisfied because there
is no shared entity to conflict about.

Measured, with a counter behind a `static` function in a header, bumped twice
from one translation unit and once from another:

| | |
|---|---|
| bumps from the first file | 2 |
| bumps from the second file | 1 |
| count the first file can see | **2** |
| count the second file can see | **1** |

Three bumps happened and **no counter says three**.

The addresses of the two functions may or may not differ, because a linker is
allowed to fold two functions whose generated code is identical. The counts are
the thing to look at.

This is the middle row of three, and it is the dangerous one:

| written as | what the program gets |
|---|---|
| nothing | two definitions, and the link fails |
| **static** | **one per file, silently** |
| inline | one, shared |

The first row is loud and gets fixed in minutes. The second ships.

## Fix

Say "one of these" in the way that means it.

```cpp
static Registry& instance() {
  static Registry only;
  return only;
}
```

A function-local static inside an **inline** function. The `inline` makes the
function one entity across the whole binary, and the standard then guarantees
its local static is one object, constructed once, however many translation units
call it. A member function defined inside a class is inline already.

`inline` variables, from C++17, do the same for data:

```cpp
inline double wheel_base = 0.35;
```

Two things to watch for.

**`static` in a header is almost never what you meant.** It is right for a
constant that genuinely is per-file, and wrong for everything else. When it
appears in a header, ask what it is for.

**Test with two translation units.** The whole class of fault is invisible from
one. Lesson 04-04's suite has a second `.cpp` file whose only job is to include
the same header and report what it sees, which is four lines and finds all of
this.

The same reasoning is why `rc/test/leak_check.hpp` keeps its counters behind
inline functions, and why it may appear in only one translation unit per binary:
two copies of those counters would report leaks that are not there.
