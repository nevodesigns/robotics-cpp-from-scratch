## Symptom

The body controller balances perfectly in its own tests and is poor on the robot: it rocks after a push, or reacts too little.

## Cause

The predictive controller's model is a rigid inverted pendulum of constant height, and in the lesson's tests the simulated body is exactly that model, so the predictions are exact. A real body has springy legs, a delay between command and torque, a height that changes, and a push that is only estimated. The test passing says the arithmetic is right; it says nothing about how wrong the model is.

## Fix

Test the controller against a plant that differs from its model: add a delay, a lag and an error in height, and see how much of the advantage survives. Then measure those things on the robot (36-07).

```cpp
// the model the controller believes
const double u = rc::legged::mpc_zmp(x, v, h_model, 0.05, 15, bound, 1.0, 1.0, 0.01, 300, nullptr);
// the plant it is tested on: not the same height, and the command a tick late
plant.step(delayed(u), h_model * 1.1);
```

A controller that is only ever tested on its own model will look better than any real body lets it be.
