title: The local that cost its space on a path it was not on

## Symptom

A function crashes on a branch that does not touch the large array declared
further down. Commenting out that array, which the failing branch never
reaches, fixes it.

Or a runtime sized array compiles on gcc, fails on clang, and nobody can
agree whether the code is legal:

```
error: variable-sized object may not be initialized
error: ISO C++ forbids variable length array 'samples'
```

## Cause

Two separate facts about how locals are allocated.

### The frame is allocated on entry, not at the declaration

Measured. A `double local[2000000]`, which is 15625 KiB against an 8192 KiB
stack limit, was declared in `main` alongside a branch that used a
`std::vector` instead:

| where the array was declared | the vector branch |
| --- | --- |
| in `main`, beside the branch | **crashed, status 139** |
| in its own function | survived, status 0 |

The array was never written on that path and never read. The space for it is
reserved when the function is entered, so a local you do not use costs you
exactly as much as one you do.

That is why a function with several large locals in mutually exclusive
branches can fail when none of the branches individually would.

### A variable length array is not C++

```cpp
double samples[n];      // n is a runtime value
```

C++ has no variable length arrays. C99 does, and both gcc and clang offer it
as an extension, which is why this is so often believed to be portable.

Measured, on a VLA with no initializer:

| flags | gcc 11 | clang 14 |
| --- | --- | --- |
| `-Wall -Wextra` | **silent** | **silent** |
| `-Wall -Wextra -Wvla` | error | error |
| `-pedantic-errors` | error | error |

Silent on both by default. The reason it matters is not portability, it is
that the size comes from the input: a function that allocates `n` doubles on
the stack is one input away from `E-MEM-0018`.

Clang's error in the symptom above appears only with an initializer, which is
why the same code can look rejected on one compiler and accepted on the other
when the only difference is `= {}`.

## Fix

**For a runtime size, use the heap.** `std::vector<double> samples(n);` is one
line, cannot overflow the stack, frees itself, and the size can be checked
before the allocation.

**Switch `-Wvla` on** so the compiler tells you rather than the operating
system. Lesson 04-08 is about which warnings to turn on and which to believe.

**For a large fixed local, put it in its own function**, so it is on the stack
only while that function runs rather than for the whole of the caller. Or put
it on the heap and stop thinking about it.

**For a bounded fixed size, `rc/core/ring.hpp` and friends** take their
capacity as a template parameter, so the size is known at compile time, no
allocation happens at all, and the space is accounted for where you can see
it.
