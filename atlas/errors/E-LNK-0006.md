id: E-LNK-0006
title: A static data member that was declared and never defined
match: (undefined reference to .[A-Za-z_]+::[A-Za-z_]+|unresolved external symbol "(public|private|protected): static)
platforms: linux, windows
teaches: 02-12-the-word-that-means-three-things
---

## Symptom

The code compiles without a complaint and the link step fails on a variable:

```
undefined reference to `Wheel::live_'                                  (gcc, clang)
unresolved external symbol "private: static int Wheel::live_"          (MSVC)
```

It is the error from lesson 00-02, `E-LNK-0001`, arriving for something that is
not a function.

## Cause

Inside a class, `static int live_;` is a **declaration**. It says there is one
such variable for the whole class. It does not make one. A declaration is a
promise, and the linker is the one who finds out it was not kept.

Measured on a class with a static member function reading `count_` and nothing
else: it compiled on gcc 11 and clang 14 and failed to link with the line above.
The error is reported against the line that uses the variable, which is not the
line that is missing.

Before C++17 the fix was a definition in exactly one `.cpp` file:

```cpp
int Wheel::live_ = 0;
```

Put it in a header and every file including it defines it, which is the duplicate
symbol of `E-LNK-0002`.

## Fix

In C++17, define it where it is declared:

```cpp
class Wheel {
  inline static int live_ = 0;     // declared and defined, once for the whole program
};
```

`inline` here is the same idea as lesson 00-02's, applied to a variable: one
definition, however many files include the header. This curriculum is on C++17, so
it is the form to use.
