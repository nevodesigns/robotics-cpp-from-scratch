id: E-IO-0023
title: A rescanning parser that holds bytes without bound
match: endless noise never overruns the window and never produces a frame
match: expected this to be true: .*malformed
platforms: linux, windows
teaches: 08-07-rescan-instead-of-giving-up

## Symptom

Memory use grows on a link whose device has gone wrong, or the process crashes
after the cable has carried noise for a while. In a debugger the parser's buffer
is enormous, or an address sanitizer reports a write past the end of the window.

## Cause

A parser that keeps bytes so that it can look at them again needs a rule for when
it may stop keeping them, and the rule is easy to leave out. Two cases matter.

**A length that promises more than the window holds.** The length byte comes off
the wire. A claim of 200 in a window built for 62 can never be satisfied, so the
parser would wait for bytes it has no room to store. Check the claim against the
space that exists before using it, and count it as malformed.

**A length too small to hold the checksum.** A length of zero, or of one for a
check that needs two, describes a frame with no room for its own proof. Trusting
it is how an empty frame gets accepted.

Noise made entirely of start bytes is the worst input, because every position
looks like the beginning of a frame and each failure sends the parser back to try
the next one.

## Fix

Reject a claim before acting on it, and give up the start byte so the search
moves on:

```cpp
if (length < check_bytes_ || length > longest_) {
  ++malformed_;
  discard_front(1);
  continue;
}
```

Then the window never holds more than one candidate's worth of bytes, because a
candidate that fits is completed or rescanned and one that does not is never
begun.
