## Symptom

Clicking a chart selects the wrong sample, and by more the further right you
click. A tooltip appears in the wrong place. A test that finds a drawn feature
in a rendered image and checks where it is reports a position off the end of the
chart.

On the developer's machine everything is exact.

## Cause

A position taken from an image is in device pixels, and everything else in the
program is in logical units. They are the same number only when the ratio is 1.

A line drawn at logical `x = 75` on a surface at a ratio of 2:

| | value |
|---|---|
| found in the image at column | **150** |
| read back with the ratio | 75 |
| read back without it | 150 |

The chart is 100 units wide, so 150 is not merely wrong, it is off the end of
it. Anything that then looks up "which sample is at 150" either clamps to the
last one or indexes past the array.

The error is exactly the ratio, which means it is exactly zero on any machine
where the ratio is 1, which is where it gets written and reviewed.

## Fix

Convert at the boundary, in one function, and keep everything above it logical.

```cpp
QPointF from_device(QPointF pixel) const {
  if (ratio == 0.0) return pixel;
  return QPointF(pixel.x() / ratio, pixel.y() / ratio);
}
```

Then the rule is simple to state and to review: **a coordinate that came out of
an image is device, everything else is logical, and there is one place where
they meet.**

Qt already delivers mouse and touch positions in logical units, so a hit test
against an event needs no conversion. What needs it is anything that reads
pixels: a test asserting where a line landed, a screenshot compared against an
expectation, a colour picked out of a rendered frame, an image loaded from disk
and probed.

Two habits that make it stick.

**Name the units in the variable.** `device_column` and `logical_x` cost
nothing and make a wrong assignment visible at the point it is written.

**Assert the round trip.** `from_device(to_device(p)) == p` is one line and it
fails immediately if either conversion is missing or doubled.

And guard the division. A ratio of zero comes from a default-constructed
surface or a screen that has not been queried yet, and dividing by it produces
an infinity that spreads into the layout, which is `E-NUM-0011` wearing a
different hat.
