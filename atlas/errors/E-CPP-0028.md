id: E-CPP-0028
title: A countdown loop over a container that never reaches the end
match: counting down with an unsigned index does not stop
platforms: linux, windows
teaches: 01-07-the-loop-that-never-ends
---

## Symptom

A loop that walks a container backwards hangs, or runs for a very long time and
then crashes reading memory that is not yours. It works on the test data and
fails on real data, or the other way round, and moving one line changes whether
it happens.

```cpp
for (std::size_t i = readings.size() - 1; i >= 0; --i) { ... }
```

## Cause

`i >= 0` cannot become false. `i` is unsigned, and nothing unsigned is ever less
than zero, so the condition is true on every pass forever.

What happens at the bottom is the part worth seeing. When `i` is 0 and `--i`
runs, it does not become -1. Unsigned arithmetic wraps, so it becomes
18446744073709551615 on a 64 bit machine, and the loop carries on indexing far
outside the container.

Measured over a three element vector, with the loop capped so it could be
reported at all, it was still running after ten passes.

There is a second failure in the same line. On an empty container,
`readings.size() - 1` is not -1, it is 18446744073709551615, so the loop starts
by indexing there.

| | value |
|---|---|
| `size()` on an empty vector | 0 |
| `size() - 1` | 18446744073709551615 |
| `last_index(size())` | -1 |

Compilers help unevenly. Under `-Wall -Wextra`, gcc reports `i >= 0` through
`-Wtype-limits` and clang says nothing about it. Neither says anything at all
about `size() - 1`.

## Fix

**Count with a signed index.**

```cpp
for (std::ptrdiff_t i = rc::core::last_index(readings.size()); i >= 0; --i)
```

`last_index` is -1 for an empty container, so the loop runs zero times, which is
the right number. Measured: three passes over three readings, none over an empty
one.

**Or do not count at all.** A reverse iterator, or a range based for over
`std::views::reverse` in C++20, removes the index and with it the whole
category:

```cpp
for (auto it = readings.rbegin(); it != readings.rend(); ++it)
```

**Never write `size() - 1`.** It is correct only when you already know the
container is not empty, which is exactly when you did not need to check. If you
want the last element, `readings.back()` says so and does not do arithmetic.

**Turn on the warnings and read them.** gcc catches this one and clang does not,
so a project that builds on only one of them is relying on a net with a known
hole in it.
