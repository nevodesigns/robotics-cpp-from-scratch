## Symptom

A configuration with a typo in a key name, or a number written as text in quotes, is accepted, and the robot runs with a speed of zero or a limit of -1 and nothing in any log says a field was wrong.

## Cause

`toDouble(default)` returns the default for every problem. A missing key, a string where a number was meant, a null, a boolean and a real value that happens to equal the default are all the same answer, so none can be told from another.

Measured: `toDouble(-1)` of a missing key, of the string "1.5", of null, of true and of a real -1 all gave **-1**. A number with a fraction read with `toInt(-1)` gave -1 too.

## Fix

Look at the value before converting it:

```cpp
const QJsonValue v = object.value(key);
if (v.isUndefined()) return missing;
if (!v.isDouble()) return wrong_type;
```

and give the caller the reason, so a typo is a message.
