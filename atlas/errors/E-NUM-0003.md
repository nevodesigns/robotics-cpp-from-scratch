id: E-NUM-0003
title: Comparing fractional numbers for exact equality
match: expected .* to equal .*\n.*got
platforms: linux, windows
teaches: 00-03-numbers-that-lie
---

## Symptom

A test fails by an impossibly small amount, reporting something like expected 1.0
but got 0.9999999999999999. A loop that should end after ten steps takes eleven.

## Cause

Fractional numbers are stored in binary and most decimal values have no exact
binary form. Adding 0.1 ten times does not produce exactly 1.0, so an exact
comparison is asking a question the representation cannot answer.

## Fix

Ask whether the values are close enough, and state how close. Use RC_CHECK_NEAR
in tests, and in code compare the absolute difference against a tolerance chosen
for the quantity being measured.
