title: A retried command that is not the command that was sent
match: a command whose answer is lost is sent again and applied once
match: expected robot.applied
platforms: linux, windows
teaches: 12-12-a-station-you-can-ship
---

## Symptom

The robot is told to stop and then, after a lost answer, is told to go at the speed that is being asked for now, or a command is applied twice.

## Cause

A retry has to be a repeat of the first send and not a new one: the same number and the same speed. The speed has to be kept with the number until the answer comes. Measured: with the first answer lost the robot received **2** copies, applied **1**, and the station had **0** waiting.

## Fix

Keep the speed by the number, send it again from there, and forget it when it is answered:

```cpp
speeds_.insert(seq, speed);
// in retry():  command_line(seq, speeds_.value(seq, 0.0))
// on ACK:      speeds_.remove(seq);
```
