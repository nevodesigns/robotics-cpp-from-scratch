## Symptom

A filter that keeps the last thousand readings is fine in a test and slow on the robot. The time it takes grows with the size of the window, not with the number of readings.

## Cause

A vector is contiguous. Removing the first element moves every element behind it forward by one. A window that drops its oldest reading for each new one pays that for every reading.

Measured, a window of 1000 kept over 5000 readings: erasing from the front of a vector moved **4000000** elements. `pop_front` on a deque moved **0**.

## Fix

Use a `std::deque` where elements leave from the front and arrive at the back, and keep a running sum so the mean does not need a pass over the window:

```cpp
values_.push_back(value);
sum_ += value;
if (values_.size() > capacity_) { sum_ -= values_.front(); values_.pop_front(); }
```
