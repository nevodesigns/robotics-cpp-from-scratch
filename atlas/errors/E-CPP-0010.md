title: Using an object after moving from it

## Symptom

A pointer is unexpectedly null, a string is unexpectedly empty, or a container
has unexpectedly lost its contents, immediately after being passed somewhere.

## Cause

The object was moved from. A move transfers what the object holds and leaves the
source valid but empty, so the next read finds nothing. This is not undefined
behaviour, which is why it produces a wrong answer rather than a crash and can go
unnoticed.

## Fix

After moving from an object, treat it as spent. The only reasonable things to do
with it are assigning a new value or letting it be destroyed.

```cpp
registry.add(std::move(device));
// device is empty from here on
```

If you still need the value, do not move: pass a reference for reading, or copy
deliberately when a copy is genuinely what you want. Clang tidy reports this as
bugprone-use-after-move and is worth switching on for any codebase that passes
ownership around.
