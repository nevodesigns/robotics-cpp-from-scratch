## Symptom

Text handling produces nonsense, or throws std::out_of_range from substr, or
crashes reading memory far past the end of a string. It happens only for input
that does not contain what was being looked for.

## Cause

Every search on a string or string view answers std::string::npos when it finds
nothing. npos is not minus one and it is not zero: it is the largest value the
size type can hold. Used as a position or a length it describes a range that
runs to the end of memory.

```cpp
const std::size_t at = line.find('=');
const std::string key = line.substr(0, at);   // fine by luck, at is huge
const std::string value = line.substr(at + 1);  // at + 1 wraps to zero
```

## Fix

Check before using it, every time:

```cpp
const std::size_t at = line.find('=');
if (at == std::string::npos) return rc::unexpected(ConfigError::MissingEquals);
```

Note also that the two argument substr takes a position and a **count**, not two
positions. Passing an end position where a length belongs is the neighbouring
mistake, and it produces a piece that is too long rather than an obvious crash.

Where the search result feeds straight into a decision, an interface answering
std::optional expresses the possibility of nothing better than a sentinel that
has to be remembered.
