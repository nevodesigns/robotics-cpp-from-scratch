id: E-MEM-0001
title: A view that outlived the data it points at
match: (AddressSanitizer|ERROR).*(heap-use-after-free|stack-use-after-return)
platforms: linux, windows
teaches: 01-04-arrays-and-spans
---

## Symptom

A std::span, string_view, reference or pointer returns correct data at first and
nonsense later. Under the address sanitizer it reports a use after free or a
stack use after return.

## Cause

None of these types own their data. When the container or local variable they
point at is destroyed, they are left pointing at memory that has been reused.

## Fix

Never return a view of a local. Return the container by value, or take the
container as a parameter so the caller owns it for the whole call. When storing a
view as a member, be explicit in the documentation about who must keep the data
alive and for how long.
