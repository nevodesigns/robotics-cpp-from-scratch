## Symptom

The arm reaches for an object the camera found in the world and goes to a place that is wrong by about the base's distance from the map's origin, and the error changes as the base moves. It can look like a calibration error, because the miss is steady while the base stands still.

## Cause

A point in world coordinates was given to the arm's inverse kinematics, which wants its target in the arm's own base frame. The two frames differ by the base's pose and the mount, so the hand goes to the right numbers in the wrong frame.

Every point has a frame, and a bare array of three numbers does not say which. The camera's detections come in the world frame (through the map and the base's localisation); the arm's solver works in its own base frame, which moves with the base. Between them are two transforms, the base's pose in the world and the mount, and both must be inverted in the right order.

## Fix

Put the world point through the inverse of the arm base's pose in the world first. The round trip world, arm, world gave the point back to 0.000000000 m.

```cpp
double in_arm[3];
rc::mobile::world_to_arm(m, base, target_world, in_arm);   // then solve the arm's inverse kinematics for in_arm
```

Name the frame in every variable that holds a point (target_world, target_arm), so a missing conversion is visible in the code.
