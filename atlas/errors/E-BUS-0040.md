id: E-BUS-0040
title: A long callback on the control loop's thread
match: on one thread callbacks run one after another, in the order they became ready
match: a long callback holds up a short one on a single thread, by almost the length of the long one
match: two threads and separate groups let the control callback run on time while the planner runs
platforms: linux, windows
teaches: 17-14-one-thread-or-many
---

## Symptom

The control loop misses cycles whenever the planner runs, the arm jerks, and the cause is in a different node.

## Cause

One thread runs one callback at a time. A planner of 5, 20, 50 and 200 ticks, ready at tick 5, made a 1 tick control callback every 10 ticks wait 0, 15, 45 and 195 ticks. Two threads with the two in separate groups made the wait 0.

## Fix

Put the control callback and the slow ones in separate groups and give the executor a thread for each.

```cpp
simulate(tasks, {true, true}, 2, 5000);
```
