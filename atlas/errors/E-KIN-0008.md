title: Joint angles clamped into range, and the move reported as done
match: the other elbow is the answer, far more often than clamping is
platforms: linux, windows
teaches: 13-05-the-angle-it-cannot-hold
---

## Symptom

The arm has joint limits, so the solver's output is clamped into them before it
goes to the joints. Nothing trips, nothing reports an error, and every move
reports success.

The tool goes to the wrong place. Not slightly wrong: half a metre wrong, on an
arm whose whole reach is 0.9 m. The targets it fails on look unremarkable and
sit well inside the workspace, and the ones on either side of them work.

## Cause

Clamping a solution is not a way of satisfying a limit. It is a way of
returning a different pose and calling it the one you asked for.

The joint angles that put the tool on a target are not independent. Change the
shoulder by 0.6 rad and the tool moves along an arc, it does not stay put while
the elbow compensates, because nothing recomputed the elbow. So a clamped
solution answers a question nobody asked: where does the tool end up if the
shoulder stops here and the elbow does what the old solution said.

Measured on a 0.5 m and 0.4 m arm, shoulder held to [-0.6, 2.2] and elbow to
[-2.4, 2.4], on four targets the first branch could not hold:

| target | clamped error | other branch |
|---|---|---|
| 0.574, -0.483 | 0.4540 | 0.0000 |
| 0.466, -0.587 | 0.5949 | 0.0000 |
| 0.340, -0.668 | 0.7294 | 0.0000 |
| 0.201, -0.723 | 0.1384 | no branch left |

Three of those four were reachable the whole time. The solver returned the
elbow the arm could not hold, the clamp turned that into a pose up to 0.73 m
away, and the other elbow was exact.

The fourth is the one the arm genuinely cannot reach, and it is the only one
where the question "how close can we get" was worth asking. The clamp gave the
same kind of answer to all four and distinguished none of them.

## Fix

**Treat a limit violation as a result, not a value to be repaired.** A pose that
violates a limit is information: this branch is unavailable. Clamping throws
that information away and substitutes a number.

**Try the other branch first.** A planar two link arm has two answers and one of
them is frequently legal when the other is not. On the arm above that is 33
percent of the legal workspace, which is a third of the machine's useful area
recovered by checking a second solution you already computed.

```cpp
const auto solved = rc::kin::legal_solutions(x, y, l1, l2, limits);
if (!solved) return solved.error();           // beyond the links, still
const rc::kin::LegalSolutions& both = solved.value();
if (!both.any()) return unreachable_here();   // and say so
```

**When no branch is legal, ask for the nearest legal pose and report the
distance.** `rc::kin::nearest_reachable` returns a pose the arm can hold along
with how far it lands from the target, and that distance is the number a caller
needs in order to decide whether to accept it, pick a different approach, or
stop. It is the number a clamp never produces.

**Never clamp and stay silent.** If a clamp is genuinely the policy, the caller
still has to be told the tool is not where it was sent, because everything
downstream, a gripper closing, a part being placed, a path continuing from the
current pose, is about to assume it is.
