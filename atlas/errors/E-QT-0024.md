title: A read that copied the whole buffer
match: reading through something that is not const copies the bytes, and at() does not
match: expected this to be true: by_at
platforms: linux, windows
teaches: 09-05-a-copy-that-was-not-a-copy

## Symptom

A function that only reads a QByteArray is slow, and a profile shows time in `memcpy` and `malloc` inside Qt. The function never writes anything.

## Cause

Qt's containers share their data between copies and copy it only when one is written to. Which calls count as writing is decided by whether the object is const, not by what the code does: on an array that is not const, `operator[]` and `data()` are the versions that can write, so they detach first. Qt cannot know you will only look.

Measured on a copy of a 1000 byte array: `b[0]` copied the bytes, `b.data()` copied them, and `b.at(0)`, `b.constData()` and `b.size()` did not.

## Fix

Read through the calls that cannot write:

```cpp
total += static_cast<unsigned char>(frame.at(i));    // on a const array, or with at()
```
