## Symptom

A name that every reference page describes as standard C++ does not exist:

```text
error: 'span' is not a member of 'std'
   34 |   void drive(std::span<const double> readings);
      |                   ^~~~
```

The same happens with `std::format` and `std::expected`. The header is included,
the spelling is right, and the compiler still says no.

## Cause

Those three arrived after C++17. `std::span` and `std::format` are C++20,
`std::expected` is C++23, and this curriculum compiles at C++17 because that is
the standard the toolchains it claims all support: GCC 11 on Ubuntu 22.04 has no
`std::format` at all, and reaching for it would quietly cut the curriculum down
to one platform.

This is not a compiler that is out of date. It is a compiler doing what the
standard the project selected says.

## Fix

Use the versions in `rc/core/compat.hpp`, which the lessons already include:

```cpp
#include <rc/core/compat.hpp>

void drive(rc::span<const double> readings);
const std::string line = rc::format("{} readings", readings.size());
rc::expected<Pose, Error> pose = solve();
```

Each is the standard type where the toolchain has it and a small
implementation where it does not, chosen by a feature test macro rather than by
a compiler version:

```cpp
#if defined(__cpp_lib_span) && __cpp_lib_span >= 202002L && __cplusplus >= 202002L
#  define RC_HAS_STD_SPAN 1
#  include <span>
#else
#  define RC_HAS_STD_SPAN 0
#endif
```

The point is not to avoid modern C++. It is that `rc::span` has deliberately the
same shape as `std::span`, so the day the project moves to C++20 the change is
deleting the shim, and the day you read `std::span` in somebody else's code you
already know what it does. Lesson 01-04 builds it, and lesson 01-05 makes the
same argument for `std::string_view`.

If you are compiling something of your own outside the lessons and genuinely
want the standard versions, ask for the standard that has them:

```cmake
target_compile_features(my_target PRIVATE cxx_std_20)
```

That target then no longer builds on every toolchain the README claims, which is
the trade being made and the reason the lessons do not make it.
