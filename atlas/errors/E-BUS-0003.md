id: E-BUS-0003
title: A publish from inside a handler delivered at once
match: a message published from inside a handler waits its turn: every subscriber of the first message is called before the second starts
match: two topics that publish to each other make a loop that the queue turns into a long run and not a stack overflow
platforms: linux, windows
teaches: 17-01-topics-by-hand
---

## Symptom

Messages arrive in an order nobody wrote down, or a pair of nodes that answer each other overflow the stack in a few thousand messages.

## Cause

A delivery inside a delivery nests, so the second subscriber of the first message hears it after everything the first one caused, and a ping that publishes a pong that publishes a ping deepens the stack for every hop. Queued instead, the publish inside returned 0, the order was first, second, out, and a ping and pong answering each other ran 5000 times each with no nesting.

## Fix

Queue a publish made during a delivery and drain the queue in a loop.

```cpp
pending_.push_back(Message{topic, payload});
if (delivering_) return 0;
```
