title: A function that is meant to write and copies more than once
match: putting a marker in a frame copies it once and leaves the caller's frame alone
match: expected int
platforms: linux, windows

## Symptom

A function takes a frame, changes a byte and returns it, and the caller's frame is changed as well, or the function copies the frame twice, once on the way in and once on the way out.

## Cause

Sharing makes a copy look free, and a function that writes through a reference writes into the caller's own bytes. A function that takes its argument by value gets a shared copy, which detaches on the first write: exactly one copy, and the caller's frame is untouched.

Measured: `with_marker` on a 1000 byte frame returned a frame whose first byte was **77**, left the caller's first byte at **0**, and the result had its own bytes while the caller's pointer was unchanged.

## Fix

Take it by value, write once and return it:

```cpp
inline QByteArray with_marker(QByteArray frame, char marker) {
  if (!frame.isEmpty()) frame[0] = marker;
  return frame;
}
```
