title: Comparing names by pointer instead of by content
match: the registry refuses what it cannot store
match: two translation units, one registry
platforms: linux, windows

## Symptom

A lookup by name works in one file and returns nothing in another. A registry
that has an entry cannot find it. It works in a debug build and fails with
optimisation, or the other way round, or it works until a string is moved to a
different file.

## Cause

Two identical string literals are not required to be the same object.

```cpp
if (entry.name == name) return entry.value;   // comparing addresses
```

Whether `"wheel_base"` written in two places produces one address or two is up
to the compiler and the linker. Most will pool them within a translation unit
and many will pool them across a binary, so this appears to work, and then a
build setting changes and it does not.

The same applies to any name that was built rather than written: a string
assembled at runtime, one read from a file, or one that came through a `const
char*` parameter from another library.

## Fix

Compare the characters.

```cpp
for (const Entry& entry : entries_)
  if (std::strcmp(entry.name, name) == 0) return entry.value;
```

And test it with a name that cannot possibly share an address:

```cpp
char spelled_out[] = {'s', 'o', 'm', 'e', 't', 'h', 'i', 'n', 'g', '\\0'};
RC_CHECK(registry.find(spelled_out) == &value);
```

That one line is the difference between a test that passes because the compiler
pooled the literals and a test that checks the lookup.

Two related habits.

**Prefer a `std::string` or a `std::string_view` for a name** that is stored,
and let its comparison do the work. A `const char*` in a container is a promise
that whatever it points at outlives the container, which is a second thing to
get right.

**Never compare a `const char*` with `==` unless you mean the address.** When
you do mean the address, say so in a comment, because every reader will assume
otherwise.

The general shape is the same as comparing floating point numbers with `==`,
which is `E-NUM-0003`: an operator that is defined, does something, and does not
do what the code is asking.
