## Symptom

The address sanitizer reports leaked blocks at exit, with the stack that
allocated them. Without a sanitizer there is no symptom at all until a long
running process slowly grows and is killed days later.

## Cause

A path out of the function skipped the release. Almost always an early return
added after the fact, or an exception thrown between the acquisition and the
release, by somebody who never looked at the bottom of the function.

The cleanup was attached to a place in the text rather than to the lifetime of
the object, so every new way out has to remember it.

## Fix

The narrow fix is to make sure every path releases, usually by turning an early
return into a break so the function keeps exactly one way out.

The real fix is to stop writing the release at all. Use std::vector when the size
varies and std::unique_ptr when one object must outlive its creator. Both release
on every path, including paths that do not exist yet, which is the subject of
lesson 02-03.

Run the leak check locally with the preset this repository ships:

```
cmake --preset asan && cmake --build build/asan && ctest --test-dir build/asan
```
