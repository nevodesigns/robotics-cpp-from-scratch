id: E-CPP-0017
title: Deleting through a base pointer with no virtual destructor
match: delete called on .* that has virtual functions but non-virtual destructor
match: -Wdelete-non-virtual-dtor
platforms: linux, windows
teaches: 05-02-fakes-and-replay
---

## Symptom

A leak that a sanitizer reports as allocated inside a derived class, with no
obvious missing release. Or a warning saying delete was called on a type with
virtual functions and a non virtual destructor.

## Cause

Deleting a derived object through a pointer to its base runs only the base
destructor, so everything the derived part owned is never released. It is
undefined behaviour rather than merely a leak, and in practice the leak is what
you notice.

## Fix

Give any class that is used as an interface a virtual destructor:

```cpp
class SensorSource {
 public:
  virtual ~SensorSource() = default;
  virtual rc::expected<double, ReadError> read(long at_ms) = 0;
};
```

The rule: if a class has any virtual function, it needs a virtual destructor.
The compiler will tell you with -Wnon-virtual-dtor, which is worth switching on
for any codebase that uses interfaces.

Where a base is never deleted polymorphically, a protected non virtual
destructor expresses that and costs nothing at runtime.
