title: A meta object check trusted further than it can see
match: the meta object catches one of the three, and it is honest about which
platforms: linux, windows

## Symptom

Every type exposed to QML passes the property audit. The test suite is green.
A gauge on the panel is still frozen.

## Cause

The check reads the declaration. The bug is in a function body.

`QMetaProperty::hasNotifySignal` answers a question about the `Q_PROPERTY`
line. It is exactly right about that question, and that question does not cover
whether the setter ever emits the signal it nominated.

Measured across four classes, one correct and three broken:

| class | notifiable | constant | check says |
|---|---|---|---|
| Telemetry | yes | no | can follow |
| NoNotify | NO | no | cannot follow |
| ForgotToEmit | yes | no | can follow |
| ConstantLie | NO | yes | can follow |

The check clears three of the four, and two of those three are broken.
`ForgotToEmit` declares `NOTIFY speedChanged` and its setter does not emit it.
`ConstantLie` declares `CONSTANT` and its setter changes the value. Both
declarations are well formed. Nothing static can see the difference.

This is not a defect in the check. It is the boundary of what a declaration can
prove, and a check whose boundary you do not know is worse than no check,
because it is where the confidence comes from.

## Fix

**Keep the static check, and know what it buys.** It catches the whole class of
"I forgot NOTIFY exists", which is the most common version of this bug and the
cheapest to catch. Assert it for every registered type.

**Add the check that runs.** Change the value in C++, read it back through a
loaded QML binding, and compare. That is the only thing that proves the path,
and it catches all three.

```cpp
source.setSpeed(7.5);
RC_CHECK_NEAR(root->property("shown").toDouble(), 7.5, 1e-12);
```

**Count the binding evaluations while you are there.** A property that reaches
QML correctly is evaluated twice, once at construction and once when it moves.
One evaluation means nothing told the binding anything, and the count says so
more precisely than the value does.

**Prefer a setter written once.** Most of these bugs are a hand written setter
that drifted from its declaration. A small macro or a template that generates
the compare, assign and emit removes the opportunity, and what it generates is
the same three lines every time.
