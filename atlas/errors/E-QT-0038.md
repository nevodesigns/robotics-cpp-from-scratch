## Symptom

A flag `busy` was added to a handler that refuses to run when entered again. Now readings that arrive while it works are dropped, or the handler works through them in the wrong order.

## Cause

Refusing the second call loses it. Handling it at once is the problem being solved. What is wanted is that a call made while one is in progress waits its turn: it is put in a line and the call already in progress works through the line.

With the guard: the log was **begin 1, end 1, begin 2, end 2, begin 3, end 3**, a nesting depth of **1** and **0** readings overwritten. A single reading was handled exactly as before. 200 queued readings were all handled, once each and in order, the first as `begin 1` and the last as `end 200`, with a log of 400 entries.

## Fix

```cpp
pending_.push_back(value);
if (running_) return;
running_ = true;
while (!pending_.empty()) { const int next = pending_.front(); pending_.pop_front(); process(next); }
running_ = false;
```
