## Symptom

A log line says only "std::exception" where the program threw something with a long, specific message. A handler for the specific type further up never runs.

## Cause

`catch (std::exception e)` makes a new `std::exception` by copying the base part of what was thrown. The derived type and its message are cut off. This is slicing, and it happens for exceptions for the same reason it happens for any
polymorphic type passed by value.

Measured: `invalid_argument("the specific message")` caught by value gave **"std::exception"**, and by reference gave **"the specific message"**.

## Fix

```cpp
catch (const std::exception& e) { ... e.what() ... }
```

Most specific handlers first, then the general one, and always by const reference.
