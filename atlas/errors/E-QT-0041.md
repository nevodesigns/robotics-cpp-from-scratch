## Symptom

A setting written as `3.7` or `1e3` is read as zero by `toInt()` while the same value as a double is read fine, and the two ways of writing the same number give different results.

## Cause

`QVariant` converts a string to an integer directly, as digits only. `"3.7"` and `"1e3"` are not digits only, and the conversion fails with a zero. As a double, `"1e3"` is 1000. The rules differ by the type asked for.

Measured: of **13** inputs that would change the value or are not whole numbers (3.7, -0.5, 3e9, -3e9, two integers too big for an int, the strings "3.7", "1e3", "12abc", "", true, an empty variant and not a number), `setting_int` refused all **13**. A real 42, -7, a whole double 5.0, the string "12", the largest int and a `qlonglong` of 1000 were read exactly.

## Fix

Decide what a whole number is and test for it:

```cpp
const int n = QLocale::c().toInt(v.toString(), &parsed);
```
