id: E-QT-0032
title: A frame accepted because the stream gave zero instead of failing
match: a frame that is short, long or cut in the name is refused, at every length
match: reading past the end of a QDataStream gives zero and a status, and the bytes that were read before it are not lost
platforms: linux, windows
teaches: 09-07-what-the-stream-wrote
---

## Symptom

A truncated frame from a noisy link is accepted as a reading with an id of 0 and a value of 0.0, and the controller acts on it. No error was raised anywhere.

## Cause

A `QDataStream` that runs out of bytes does not throw. It sets a status, and the values read after that are set to zero, overwriting what was in the variable. Code that never asks for the status sees a reading of zeros.

Measured: two bytes read as two 16 bit numbers gave **0x0102** with status Ok and then **0** with status `ReadPastEnd`; the second was zero, not the 88 it held before. A decoder that asks gave: every one of the **14** prefixes of the 14 byte frame refused, one byte too many refused, a length byte of 200 refused, and the whole frame accepted.

## Fix

Check the status after the fixed part, count the name bytes that were really read, and require that the stream is at its end:

```cpp
if (stream.status() != QDataStream::Ok) return d;
if (stream.readRawData(name.data(), length) != length) return d;
if (!stream.atEnd()) return d;
```
