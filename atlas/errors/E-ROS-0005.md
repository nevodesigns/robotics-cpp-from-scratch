title: A failure and an error taken for the same thing
match: a failed step leaves the node where it was, so it can be tried again, and a failed shutdown does not finalize
match: an error sends the node to error processing, and its own recovery decides between starting over and being finished
platforms: linux, windows

## Symptom

A node that could simply have been retried is abandoned, or one whose state is corrupt is retried as if nothing happened.

## Cause

A failure leaves the node where it was: a failed configure stayed unconfigured and succeeded on retry, a failed deactivate stayed active and a failed shutdown stayed active. An error is an untrusted state: the node goes to error processing and its recovery chose unconfigured, from which it was brought up again, or finalized, after which every request was refused.

## Fix

Return failure for what can be retried and error for what cannot be trusted.

```cpp
return device_busy ? CallbackResult::failure : CallbackResult::error;
```
