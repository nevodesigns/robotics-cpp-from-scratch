title: Static initialisation order, a global used before it exists

## Symptom

A registry is empty when it should hold entries, or the program crashes before
main is reached. The behaviour frequently differs between compilers, between
debug and release, or after an unrelated file is added to the build, which is
the strongest hint that this is the cause.

## Cause

Objects at file scope in different translation units are constructed in an order
that nobody defines. If one of them appends to a global container that has not
been constructed yet, it writes to an object that does not exist.

This is the static initialisation order problem, and it is a real design gap in
the language rather than a mistake you made.

## Fix

Put the shared object inside a function as a static local. It is constructed the
first time control reaches the declaration, which cannot be before its first use:

```cpp
std::vector<Case>& registry() {
  static std::vector<Case> cases;
  return cases;
}
```

Every access goes through the function, so the ordering question disappears. The
same pattern is the standard answer for any global that other globals depend on.
