## Symptom

A position, heading or command becomes NaN, and from then on every value derived
from it is NaN too. Comparisons against NaN are all false, so guards written as
range checks quietly stop protecting anything.

## Cause

A vector of zero length was normalised. Dividing each component by a length of
zero gives NaN, and NaN propagates through every arithmetic operation it touches.

A zero length vector is not unusual in robot code. It is what you get when two
positions are the same, when a path segment has no length, when a velocity is
zero, or when a sensor has not reported yet.

## Fix

Decide what no direction means, and answer it deliberately:

```cpp
Vec2 normalized(const Vec2& v) {
  const double len = length(v);
  if (len == 0.0) return Vec2{0.0, 0.0};
  return scale(v, 1.0 / len);
}
```

Returning the zero vector, returning an optional, or refusing with an error are
all defensible. Dividing and hoping is not.

Where NaN has already appeared and the source is unclear, assert on it at the
boundaries of each stage. std::isnan finds it at the point it enters rather than
where it is finally noticed, which is usually much later and somewhere else.
