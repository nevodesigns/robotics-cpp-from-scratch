title: A number followed by something else, read as the number
match: a number followed by something else is refused, not read as the number
match: expected this to be true: !e.ok
platforms: linux, windows
teaches: 00-10-a-program-that-asks

## Symptom

A person types 12abc, or 3,5 meaning three and a half, and the program carries on as if they had typed what it expected. A speed of 3.5 becomes 3, and
nothing complained. Or the next question gets an answer nobody gave, because the rest of the line is still waiting to be read.

## Cause

`in >> value` takes as much as looks like a number and stops. The rest stays in the stream, and success is reported.

The suite prints what `>>` alone took against what `read_number` said:

| typed | taken by `>>` | read_number |
|---|---|---|
| 12abc | 12 | not a number |
| 3,5 | 3 | not a number |
| 7 8 | 7 | not a number |
| 9.5.1 | 9.5 | not a number |

## Fix

After the number, look at what is left on the line. Spaces are fine, and anything else is a refusal.

```cpp
while (in.peek() == ' ' || in.peek() == '\t') in.get();
const int next = in.peek();
if (next != '\n' && next != std::istream::traits_type::eof()) { /* refuse, and discard the line */ }
```
