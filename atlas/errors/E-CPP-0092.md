## Symptom

A base class constructor registers an object under the name returned by a virtual function, and every derived object is registered as the base. Or it calls a virtual `init()` that a derived class overrides, and the override never runs.

## Cause

While the base constructor runs, the object is a base object: the derived part does not exist yet, so the virtual call cannot go there. It runs the base's version. Afterwards the object is the derived type and calls go to the derived function.

Measured: making a `Special`, the base constructor asked `who()` and was told **"base"**; asked afterwards it said **"special"**.

## Fix

Do not call virtual functions from a constructor or destructor. Pass what the base needs as an argument (`Named(std::string name)`), or have the caller call an `init()` once the object is built.
