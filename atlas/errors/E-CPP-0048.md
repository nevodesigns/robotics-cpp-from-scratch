title: An iterator category promised and not kept
match: declaring random access buys constant time distance and arithmetic
platforms: linux, windows
teaches: 03-08-making-it-iterable

## Symptom

An iterator that works with range-for, works with `std::accumulate`, works with
`std::find`, and then produces a page of errors from
`/usr/include/c++/11/bits/stl_iterator_base_funcs.h` the moment something calls
`std::advance`, `std::distance` or `std::lower_bound` on it.

```
error: no match for 'operator+=' (operand types are 'IndexIterator<Samples>'
and 'long int')
```

in a file you did not write, about an operator you did not know you had agreed
to provide.

## Cause

`iterator_category` is a promise, and the library holds you to all of it.

Declaring `std::random_access_iterator_tag` says that stepping n places costs
what stepping one costs. The algorithms then take you at your word and use the
arithmetic: `std::distance` subtracts instead of counting, `std::advance` uses
`+=`, and `std::lower_bound` jumps to the middle instead of walking.

So the tag is not a label describing what you wrote. It selects which
operations the library will require and which implementations it will choose.
Claim random access and you owe the whole set: `+`, `-`, `+=`, `-=`,
`operator[]`, `<`, and the iterator difference.

The errors arrive from inside the library because that is where the missing
operation is used, which is the same effect lesson 03-07 measured when it found
an unconstrained template reporting its failure 21 instantiation frames deep.

## Fix

**Claim the weakest category that is true.** `forward_iterator_tag` owes far
less and is enough for `find`, `count_if`, `accumulate` and range-for. A linked
structure should say forward and mean it, and the algorithms will then walk
rather than attempt arithmetic that would be wrong.

**If you claim random access, provide the whole set.** For an index based
iterator they are all one line each, because the work is an index addition,
which is also what makes the claim honest.

**Cast before subtracting two indices.** The difference is a
`std::ptrdiff_t` and the indices are unsigned, so subtracting them first and
converting afterwards wraps, which is lesson 01-07.

**Test the operations the category promised, not just the loop.**
`std::distance`, `it + n`, `it[n]`, `it < other` and `std::lower_bound` are
five lines in a test and they are the only thing that distinguishes a kept
promise from a declared one.

**Read the first error and find your own file in the "required from" chain.**
The deepest frame is the library's; the shallowest one in your code is the line
to change.
